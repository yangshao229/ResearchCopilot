# M6.5.6 验收：完整中英文界面切换

日期：2026-09-28。开源调研与边界决策见 [界面语言拆解](research/2026-09-28-interface-language.md)。

## 交付范围

- 顶栏可在“简体中文”和 English 间切换；显式选择保存在本浏览器，刷新后保持。首次访问跟随浏览器语言，无法识别时使用英文；不支持或损坏的存储值安全回退。
- 两套消息目录覆盖资料库、PDF 控件、目录、提问、证据、笔记、总结、信息、术语表、空状态、加载状态、常见错误与无障碍标签。页码和数量使用命名占位符。
- 界面语言不进入论文、会话、`LanguagePolicy`、模型任务、翻译缓存或导出文件。PDF 原文、用户问题、AI 回答、阅读记录和会话标题不被自动翻译。
- 后端返回的中文范围说明、选区上下文说明、目录/阅读建议警告，在英文界面按结构化状态显示英文操作说明；中文界面保留具体中文诊断。阅读建议新增结构化 `section_title`，操作标签按角色随 UI 语言切换，不再从中文展示标签中解析章节名；建议问题本身仍属于任务内容。

## 自动检查

- `.venv/bin/pytest -q`：`100 passed`，另有 2 条既有第三方弃用警告。
- `npm run build`（`web/`）：TypeScript 检查与 Vite 构建通过；构建报告现有的大 bundle 提醒，不是失败。
- 消息目录测试检查中英文键、非空值和占位符一致，并检查主要 React 组件没有绕过消息表的中文 UI 字符串。

## 真实页面检查

本地 `sample.pdf`，在 `http://127.0.0.1:8000/`：

1. 中文显示“本地资料库”“论文目录”“提问”等；选择 English 后立即显示 Local library、Paper outline、Ask、Previous/Next、15 pages 等。
2. 刷新后 English 仍被选中；切换时 PDF 原文仍为英文，既有中文会话标题“默认阅读”“方法精读”保留原内容。
3. 提问区的检索、语言偏好、翻译目标、术语策略等控件显示英文；阅读建议的操作标签已本地化，但建议问题内容未被界面语言改写。
4. 只检查了本地页面状态，未调用真实 DeepSeek，也未改写用户阅读记录或论文。
5. 临时设为 800×700 窄屏时，英文页面根元素的可视宽度与滚动宽度均为 800px，没有出现整页横向溢出；随后恢复默认视口。

## 后续边界

本阶段不是整篇论文翻译。M7 先做解析质量和布局块/坐标，再讨论稳定的双语阅读视图。若未来后端支持多客户端，应把人类可读的状态文字升级为稳定状态码，而不是继续扩大前端对中文诊断的处理。
