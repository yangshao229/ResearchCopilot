# M8.4k：同页相邻片段影子诊断

日期：2026-10-08。状态：**只做离线实验，未改变网页、检索排序或 DeepSeek 输入**。

设计先见[开源产品与技术拆解](research/2026-10-08-local-context-window-shadow.md)。这轮把“搜到正确 PDF 页”与“送给回答模型的片段含有答案”分开检查。固定 M8.4i 的独立 RAG 论文、PDF SHA-256、10 道问题和现有混合检索 Top-5；人工在[证据短语账本](evaluations/m8_4j_support_spans.json)标出 8 道有答案题的必要原文短语，另 2 道为无答案题。

## 三种视图的结果

| Top-5 视图 | 必要短语完整的有答案题 | 每题五条证据平均字符数（含负例） |
| --- | ---: | ---: |
| 原始片段 | 7/8 | 4,870 |
| 原片段 + 同页下一个片段 | 8/8 | 8,520 |
| 原片段 + 同页前后各一个片段 | 8/8 | 11,130 |

唯一补回的是中文“RAG-Sequence 的快速解码如何近似彻底解码”：Top-5 已有 PDF 第 4 页的前半片段，但回答所需的近似方法在同页下一个片段。英文同义问题在原始 Top-5 已有必要短语，所以不能把两种语言都算作改进。向后扩一个片段使本组短语覆盖增加 1 题，但平均上下文从 4,870 增至 8,520 字符，约为原来的 1.75 倍；双向扩充并未多救回题目，却增至约 2.29 倍。

另一道“参数化／非参数化记忆”题在 PDF 第 1 页摘要也有完整答案，而原页码账本只列了第 2 页。这说明原账本的单页锚点不完整，不能单靠页命中判断检索好坏；本轮短语覆盖是更窄的补充诊断，不取代人工判断。

## 安全边界与判断

- `window_text` 只读同一 PDF 页的连续片段；检索结果文本必须与当前切分数据完全一致，否则拒绝扩展。100 字符重叠只在完全相同时去除。不会把别的论文、别的页或 Obsidian 笔记拼到引用里。
- “短语完整”仅表示几处人工标出的字串出现在 Top-5 文本中，**不表示事实关系理解正确、生成答案正确，或引用正确**。它也不是通用语义检索分数。
- 诊断现已要求必要短语在同一 PDF 页共同出现，避免从不同页拼凑“完整证据”；M8.4k 数值未改变。三篇既有论文的扩展复核见 [M8.4l](M8_4L_THREE_PAPER_CONTEXT_VALIDATION.md)。
- 两道无答案题的覆盖结果是 `null`，不是“能够拒答”。扩大上下文还可能给模型带来更多似是而非的材料；本轮没有调用模型，不能评估拒答率。
- 当前只测一篇 RAG 论文的 8 道正例，其中中英问法成对，实际独立概念只有 4 组。收益集中于 1 道题，成本几乎加倍。因此**不将上下文窗口接入生产**，也不替换现有重排器或自动回答。
- 如要上线，须先在至少另一篇不同版式论文上冻结片段级答案真值，测算真实 token／延迟与无答案题的生成结果，并保证用户看到的证据集合与模型使用的证据集合完全一致。

复现：`.venv/bin/python scripts/evaluate_context_window.py`。实验只读本地 PDF 和本机缓存模型，不调用 DeepSeek，不写用户 Vault、翻译缓存或阅读记录。三个纯函数回归见 `tests/test_context_window_evaluation.py`。本轮 Python 全量测试 `206 passed`（另有 2 条依赖弃用警告），前端生产构建通过（只有既有的大分块提示）。
