# M6.4 架构基线验收

日期：2026-09-25

## 目的

在加入章节感知检索和双语阅读前，先消除已经出现的重复模型、重复业务流程和过大的入口文件，确保后续功能都接入同一条阅读链。

本轮不是新增一个用户按钮，而是落实既有的整体架构蓝图。设计依据沿用 [整体阅读架构与双语工作流拆解](research/2026-09-23-coherent-reading-architecture-and-bilingual-workflow.md)。

## 完成内容

1. 用 `ReadingContext` 统一描述论文、会话、问题、任务、检索方式、原文锚点、检索范围和语言策略。
2. 搜索结果、证据、回答、引用和阅读记录只保留一套领域模型，同时保留旧模块导入名称以兼容已有代码和测试。
3. 从网页入口中拆出 `PaperLibrary`、`PaperDocumentService` 和 `ReadingService`：网页路由不再直接完成文件管理、结构解析、问题路由、模型调用和历史保存的全部工作。
4. 论文结构按文件路径、修改时间和大小缓存；文件变化后自动重新解析。
5. 会话与阅读历史复用同一套安全 JSON 存储；临时文件名唯一，并用原子替换提交。
6. 阅读历史增加进程内可重入锁，避免同一服务中的并发请求互相覆盖记录。
7. 前端把目录、证据、记录卡、论文总结和论文信息拆为独立展示组件，主面板继续负责当前阅读状态和动作编排。
8. 命令行不再为了读取默认目录而提前导入并创建整个 Web 应用。

## 兼容性

- HTTP 路径、请求字段和响应字段保持不变。
- 旧 JSON 阅读记录缺少 `session_id` 时仍进入默认会话。
- `paper_answer_service` 与 `reading_history` 继续导出原有类型名称，避免一次性破坏调用方。
- 本轮没有修改用户正在编辑的旧版 `paper_card.py`。

## 验证

- Python 完整测试：`70 passed`。
- 新增统一上下文默认值和严格字段测试。
- 新增结构缓存命中与 PDF 改变后失效测试。
- 新增 12 个并发阅读记录写入不丢失测试。
- 前端执行 TypeScript 类型检查和生产构建成功。
- `git diff --check` 通过。

前端构建仍提示主 JavaScript 包超过 500 kB。主要来源包括 PDF.js；这是性能优化事项，不影响本轮正确性，后续在独立性能阶段采用懒加载和代码分块处理。

## 下一步

在现有 `ReadingContext.scope` 和 `ReadingAnchor` 上实现章节名称解析、章节页码范围计算与限定检索；识别失败时明确回退到全文检索。完成后再进入统一语言策略的实际 API 与界面接入。
