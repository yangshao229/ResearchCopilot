# ResearchCopilot 产品蓝图

状态：当前开发的统一架构基线
版本：0.2
日期：2026-09-23

成品化的阶段顺序、单一权威数据边界及减法约束见 [成品化路线](PRODUCT_COMPLETION_PLAN.md)。

## 1. 产品定义

所有新增功能必须先执行 [开源论文阅读产品拆解协议](OPEN_SOURCE_RESEARCH_PROTOCOL.md)。产品设计以成熟项目的一手实现与研究证据为参考，但仍以“帮助用户读懂论文”、本地优先、证据优先和人工确认作为最终取舍标准。

ResearchCopilot 是一个本地优先、面向 AI 科研论文的深度阅读工作台。

它不以“替用户快速生成摘要”为核心，而是让用户始终阅读原始论文，并在遇到语言、数学、背景知识、方法和实验理解障碍时，获得有原文证据、可回到准确页码核对的帮助。阅读过程中产生的高亮、问题、回答和个人理解，最终由用户确认并沉淀为长期可用的 Markdown 研究笔记。

一句话目标：

> 人读论文，AI 在旁解释；答案可回原文核对，理解由人确认后进入知识库。

## 2. 产品边界

### 当前主线

1. 在项目页面直接阅读英语 AI 论文。
2. 选择原文后进行翻译、解释、公式拆解和背景补充。
3. 针对当前论文进行连续问答，并提供可点击的原文页码引用。
4. 保存阅读进度、高亮、问题、回答和个人笔记。
5. 将有价值的阅读记录整理为人工确认的论文总结与论文卡片。
6. 建立多篇论文资源库，支持搜索、比较和主题研究。
7. 对切分、检索、重排序和生成策略进行可复现评测。

### 暂不作为主线

- 自动替用户读完论文并直接给出“最终理解”。
- 团队协作、账户、权限和云端部署。
- 自动播客、演示文稿和社交分享。
- 一开始就建设复杂知识图谱。
- Windows/CUDA 论文复现；只有阅读后确认需要复现实验时再启动。
- 用大型数据库或框架替代对 RAG 原理的学习。

## 3. 设计原则

1. **原文优先**：PDF 永远是第一视图，AI 不能把原文藏起来。
2. **证据优先**：重要回答必须附引用；点击引用能返回对应论文和页码。
3. **区分信息来源**：论文明确写出的内容、基于论文的推断、模型补充的背景知识必须分开标记。
4. **人工确认**：AI 生成的总结和论文卡片默认为草稿，不能自动覆盖人工笔记。
5. **本地优先**：PDF、解析文本、Embedding、索引、聊天记录和笔记默认保存在本机。
6. **最少上传**：云端模型默认只收到问题和检索出的必要证据，不上传整篇论文。
7. **过程透明**：用户可以查看命中的文本块、页码、分数和重排序结果。
8. **算法可替换**：PDF 解析器、Embedding、检索器、重排序器和大模型保持独立接口。
9. **先读懂再扩展**：任何新功能都要回答“它是否让用户更容易读懂论文”。
10. **跨平台可重建**：代码、配置和评测进入 Git；模型、密钥、论文和索引不进入 Git。

## 3.1 整体架构约束

ResearchCopilot 不按按钮堆叠功能。所有能力必须接入一条统一阅读链：

```text
论文与原文块
    ↓
阅读上下文（论文 + 会话 + 选区/章节 + 任务 + 语言 + 范围）
    ↓
证据构建（确定性读取 / 选区上下文 / 检索）
    ↓
任务执行（查词 / 翻译 / 解释 / 公式 / 问答 / 总结）
    ↓
带原文锚点的阅读记录
    ↓ 用户确认
论文卡片、章节笔记、术语卡等知识产物
```

系统只有八类核心对象：

| 对象 | 唯一职责 |
| --- | --- |
| `Paper` | 一篇论文的身份、元数据和状态 |
| `SourceDocument` | 原始 PDF 及其解析版本 |
| `DocumentBlock` | 可定位的标题、段落、公式、图表或选区，保留页码/坐标/语言 |
| `ReadingSession` | 同一论文下相互隔离的阅读主题 |
| `ReadingContext` | 当前论文、会话、锚点、任务、范围和语言策略 |
| `EvidenceSet` | 本次任务使用的原始证据及其检索过程 |
| `ReadingRecord` | 翻译、解释、回答和个人理解的统一记录 |
| `KnowledgeArtifact` | 用户确认后形成的论文卡片、章节笔记、术语卡和主题笔记 |

解析器、检索器、重排序器、翻译/回答模型和存储方式都是可替换实现，不成为新的业务中心。任何新功能必须先说明它复用哪些核心对象；如果要增加第九种核心对象，必须先更新蓝图并解释必要性。

当前落地状态（2026-09-25）：`ReadingContext`、`ReadingAnchor`、`ReadingScope`、`LanguagePolicy`、`SearchHit`、`Evidence`、`PaperAnswer` 和 `ReadingRecord` 已集中到统一领域模型；网页路由只负责 HTTP 输入输出，论文资料管理、结构解析缓存和一次阅读任务的编排分别由独立服务承担。章节意图已复用 `ReadingContext.scope`，解析失败会明确回退全文。实现与兼容取舍见 [M6.4 章节检索拆解](research/2026-09-25-section-aware-retrieval.md)。

### 横切基础能力

以下能力不属于某一个按钮，而是所有阶段共同使用：

- **语言策略**：界面、原文、解释、翻译目标和术语策略相互独立。
- **原文锚点**：所有输出最终引用同一套论文、页码、章节和页面坐标。
- **范围控制**：选区、当前章节、全文、指定论文集合必须明确可见。
- **来源与确认状态**：原文事实、模型解释、外部背景和用户理解分别标记。
- **隐私与费用**：每次外部调用都由同一个策略层决定允许发送的内容。
- **可观测性**：任务保存解析器、检索方式、模型、提示版本、延迟和失败原因。

## 4. 信息架构与页面

### 4.1 资料库首页

用于找到下一篇要读的论文，而不是展示复杂统计仪表盘。

核心区域：

- 最近阅读：显示上次阅读页和最后打开时间。
- 待读论文：按阅读状态、主题、标签和优先级筛选。
- 全部论文：按标题、作者、年份、关键词和全文搜索。
- 主题集合：例如 Transformer、RAG、Multimodal、Agent。
- 导入入口：本地 PDF；后期支持 arXiv、DOI 和论文 URL。

每篇论文的状态：

```text
未处理 → 已导入 → 待读 → 阅读中 → 已初读 → 已精读 → 已归档
```

### 4.2 论文阅读工作台

默认采用三块区域，其中左右侧栏都能收起：

```text
┌──────────────┬────────────────────────────┬──────────────────────┐
│ 目录/缩略图   │                            │ 提问 / 证据 / 笔记    │
│ 论文内搜索    │          原始 PDF          │ 总结 / 论文信息       │
│ 高亮列表      │                            │                      │
└──────────────┴────────────────────────────┴──────────────────────┘
```

顶部保留：返回资料库、论文标题、阅读状态、当前页、缩放、全文搜索和设置。

右侧工作区分为五个标签页：

1. **提问**：论文级连续对话。
2. **证据**：本次问题检索到的原文片段、页码和排序分数。
3. **笔记**：个人输入、高亮备注和固定的优质回答。
4. **总结**：本次阅读总结与整篇论文卡片草稿。
5. **信息**：标题、作者、年份、会议、链接、标签和阅读状态。

### 4.3 跨论文研究页

在单篇阅读闭环稳定后增加：

- 选择多篇论文作为当前研究集合。
- 针对集合提问，并让每个结论标明来自哪篇论文、哪一页。
- 比较任务、假设、方法、数据集、指标、结果、局限和计算成本。
- 把比较结果保存为主题笔记，而不是写回某一篇论文卡片。

### 4.4 检索与评测实验页

这是学习 AI 和改进系统的页面，不干扰普通阅读：

- 查看不同切分策略产生的文本块。
- 输入测试问题并比较关键词、向量、混合检索和重排序结果。
- 查看 Recall@k、MRR、nDCG、引用准确率、回答忠实度、延迟和费用。
- 保存实验配置、结果和人工结论。

## 5. 完整功能集合

优先级说明：

- P0：构成第一版可用阅读闭环。
- P1：让个人论文资料库成熟可靠。
- P2：跨论文研究和效率增强。
- P3：长期学习与研究扩展。

| 优先级 | 功能 | 说明 |

| P1 | 星标、评分与优先级 | 支持待读筛选和研究价值判断 |
| P1 | 全文搜索 | 标题、元数据、原文、笔记和问答统一搜索 |
| P2 | URL 导入 | arXiv、OpenReview、ACL Anthology、PMLR、DOI、直接 PDF |

### 5.3 阅读时的 AI 帮助

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P0 | 划词翻译 | 保留术语、变量、公式和上下文，不做脱离论文的意译 |
| P0 | 划词解释 | 用中文解释当前段落，并指出依赖的前置知识 |
| P0 | 自由提问 | 对当前论文进行连续追问 |
| P0 | 页码引用 | 回答的重要结论带可点击的证据引用 |
| P0 | 证据不足拒答 | 找不到依据时说明缺什么，不伪造页码 |
| P1 | 公式拆解 | 解释变量、维度、每一步含义、假设和直觉 |
| P1 | 图表解释 | 先说明图表在测什么，再解释趋势和论文结论 |
| P1 | 方法流程解释 | 输入、模块、训练目标、推理流程和输出 |
| P1 | 实验解读 | 数据集、基线、指标、消融、显著性和结论边界 |
| P1 | 术语卡片 | 将反复出现的概念保存为可复用的概念笔记 |
| P1 | 回答深度切换 | 快速解释、深入解释、导师式追问三种模式 |
| P2 | 外部背景搜索 | 明确与论文证据分区，不把网络资料冒充论文结论 |
| P2 | 自动建议追问 | 根据当前内容建议少量有价值的问题，不打断阅读 |
| P2 | 多论文比较问答 | 在用户选定的论文集合内检索和回答 |

### 5.3.1 双语阅读基础层

双语能力贯穿 PDF 阅读、检索、回答、记录和导出，不是独立附加页面。系统必须区分以下状态：

| 状态 | 含义 | 默认行为 |
| --- | --- | --- |
| 界面语言 `ui_locale` | 菜单、按钮和系统提示 | 中文，可切换 English |
| 原文语言 `source_language` | 每个原文块实际使用的语言 | 自动检测，但原文永不被覆盖 |
| 解释语言 `explanation_language` | 问答、概念和公式解释的语言 | 跟随提问，也可固定中文/英文 |
| 翻译目标 `translation_target` | 翻译动作输出的语言 | 使用论文偏好，可单次覆盖 |
| 术语策略 `terminology_policy` | 专业术语、缩写和变量的保留方式 | 首次出现显示中文、英文和缩写 |

交互只提供三个清晰层级：

1. 设置中选择界面语言。
2. 论文阅读区选择原文、中英对照或译文显示；在整篇翻译尚未完成时，只对已有译文块生效并明确提示。
3. 提问区选择回答语言：跟随提问、中文或 English。

选中原文后的“查词、翻译、解释、公式”共享同一个 `ReadingContext`。翻译记录必须保存原文、译文、目标语言、术语版本、上下文范围和原文锚点。中文问题直接检索英文原文，不先把论文整体翻译成中文。

实现顺序：

```text
语言策略与统一记录
  ↓
选区/段落上下文翻译 + 缓存 + 术语表
  ↓
章节级中英对照
  ↓ M7 布局解析稳定后
可恢复的整篇双语阅读视图
```

完整设计依据见 [整体阅读架构与双语工作流拆解](research/2026-09-23-coherent-reading-architecture-and-bilingual-workflow.md)。

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P0 | 每篇论文独立会话 | 不让不同论文的上下文相互污染 |
| P0 | 保存完整问答历史 | 记录问题、回答、时间、引用和使用的模型配置 |
| P0 | 新建对话线程 | 将不同阅读主题分开，例如方法、公式、实验 |
| P1 | 固定有价值回答 | 用户主动选择哪些内容进入笔记候选区 |
| P1 | 问题状态 | 未解决、部分解决、已解决、需要外部资料 |
| P1 | 本次阅读总结 | 汇总本次问题、高亮、理解、疑问和下一步 |
| P1 | 回答纠错与反馈 | 标记错误回答、错误引用或有帮助的回答 |
| P2 | 学习回顾 | 重新查看未解决问题、关键概念和已读论文 |
| P3 | 自测问题 | 根据用户确认的内容生成练习题，而非直接使用 AI 草稿 |

### 5.5 笔记、总结与论文卡片

所有 AI 生成内容具有状态：

```text
AI 草稿 → 用户编辑中 → 用户已确认 → 已归档
```

论文卡片建议结构：

1. 基本信息：标题、作者、年份、会议、链接。
2. 一句话结论：用户最终确认的核心认识。
3. 研究问题：论文试图解决什么、为什么重要。
4. 前置知识：理解论文所需概念。
5. 方法：输入、架构、目标函数、训练与推理流程。
6. 关键公式：变量、维度、直觉与原文位置。
7. 实验：数据集、基线、指标、主要结果和消融。
8. 贡献：论文真正新增了什么。
9. 局限：论文自述局限和用户判断的局限分开记录。
10. 与其他论文的关系：继承、区别、冲突和可组合点。
11. 未解决问题：后续需要查证或复现的内容。
12. 复现线索：代码、数据、环境、计算资源和潜在困难。
13. 阅读记录：重要问答、高亮和引用。

功能：

- P0：生成论文卡片草稿，并拒绝覆盖已有正式笔记。
- P1：从选中的高亮和问答生成本次阅读总结。
- P1：所有引用保留论文 ID、PDF 页码和原文片段。
- P1：预览差异后再将草稿合并到正式 Markdown。
- P1：人工确认后的正式研究知识保存为普通 Markdown；Obsidian Vault 是用户选定的长期知识库，可用内置 Bases 查看状态与标签，但阅读器本身不依赖 Obsidian 安装。具体权威边界、schema、双向回读和冲突保护见 [Obsidian 长期知识库蓝图](OBSIDIAN_KNOWLEDGE_VAULT_BLUEPRINT.md)。
- P2：用模板生成方法卡、数据集卡、概念卡和主题综述。
- P2：维护笔记修订历史并允许恢复旧版本。

### 5.6 PDF 解析与文本质量

采用逐级回退，而不是对所有论文一开始就运行重模型：

```text
快速文本层抽取
    ↓ 质量合格
分页文本 + 页码

    ↓ 质量不合格
布局感知解析（双栏、标题、表格、图片说明）

    ↓ 扫描或严重乱码
OCR / 视觉模型解析
```

每篇论文显示解析状态：成功、部分异常、需要 OCR、人工检查。

长期保存的结构信息包括：

- 页码、章节、文本块和阅读顺序。
- 文本在页面中的坐标，用于将引用定位到原文区域。
- 标题、正文、公式、表格、图片说明、脚注和参考文献类型。
- 解析器名称、版本、参数和质量警告。

### 5.7 检索、重排序与回答生成

标准管线：

```text
问题理解与范围确定
      ↓
关键词检索 + 多语种向量检索
      ↓
结果融合与去重
      ↓
重排序并保持章节/页码多样性
      ↓
证据充分性检查
      ↓
只基于证据生成回答
      ↓
逐条验证引用并输出
```

关键要求：

- 当前论文页面默认只检索当前论文。
- 跨论文检索必须由用户明确进入研究集合模式。
- 文本块保留论文、页码、章节、坐标和相邻块关系。
- 默认采用关键词与向量混合检索，降低专有名词、公式编号和缩写漏检。
- 重排序用于去掉参考文献等表面相关结果。
- 证据片段可以在“证据”标签页查看，用户可报告错误切分或错误排序。
- 无证据是合法结果；系统不能为了完成回答而编造引用。
- 补充常识或网络资料必须放在“补充背景”区域，并单独注明来源。

### 5.8 回答展示契约

普通论文问答默认采用以下结构：

```text
直接回答
用简洁中文先回答用户的问题。

理解与推导
分步骤解释概念、过程或公式。

论文依据
[第 4 页] 原文证据和它支持的结论。
[第 6 页] 第二条证据和它支持的结论。

边界与不确定性
说明论文没有回答什么、当前解释包含哪些推断。

补充背景（仅在需要时）
明确说明这部分不是论文原文结论。
```

翻译、术语解释等简单任务可以使用精简格式，但仍保留当前选区和页码。

### 5.9 评测与可观测性

每篇用于评测的论文维护一小组真实阅读问题：

- 问题。
- 期望找到的页码或章节。
- 人工参考答案或关键要点。
- 是否允许使用论文外背景知识。
- 问题类型：事实、概念、公式、图表、比较、批判。

评测分三层：

1. **解析层**：页数、字符覆盖、乱码、标题/公式/表格质量。
2. **检索层**：Recall@k、MRR、nDCG、命中页码、冗余度。
3. **回答层**：事实正确性、证据忠实度、引用准确率、完整性、拒答质量。

同时记录：模型、提示词版本、切分配置、Embedding、重排序器、延迟、token 和费用。

### 5.10 模型、隐私与费用

- Embedding 默认在本机运行。
- 云端 LLM 默认只接收当前问题、必要对话摘要和检索证据。
- 发送前显示当前范围：选区、当前论文或论文集合。
- API 密钥保存在 `.env` 或系统凭据存储中，永不写入 Git、日志和导出笔记。
- 模型提供商通过统一接口替换；聊天模型和 Embedding 模型独立配置。
- 保存每次调用的模型名、参数、token、估算费用和错误状态。
- 后期可接 Ollama 等本地接口，但不让本地模型部署阻塞第一版。

## 6. 成熟的论文阅读流程

### 阶段 0：一次性准备

1. 用户配置可选的云端模型 API。
2. 本地下载 Embedding 模型。
3. 创建研究主题集合，例如“Transformer 基础”。
4. 系统解释哪些数据留在本地、哪些内容可能发送给 API。

### 阶段 1：导入和质量检查

1. 用户拖入 PDF 或选择文件。
2. 系统计算文件指纹，检查是否重复。
3. 系统逐页解析，并尝试补全元数据。
4. 系统显示页数、文本提取状态和异常页。
5. 如果是扫描件或双栏解析失败，用户选择增强解析，而不是静默产生错误文本。
6. 论文进入“待读”状态。

产物：原始 PDF、分页文本、元数据、解析报告和初始索引。

### 阶段 2：第一遍快速建立地图

目标不是理解全部细节，而是知道论文在做什么。

1. 阅读标题、摘要、引言、主要图表和结论。
2. AI 可以生成“阅读导航”，但必须链接到对应章节或页码。
3. 用户记录自己的三个初始判断：研究问题、核心方法、最大疑问。
4. 系统根据论文结构生成章节阅读清单。
5. 论文状态变为“阅读中”。

产物：阅读地图、初始问题和需要精读的章节。

### 阶段 3：逐节精读

对每个重要章节循环执行：

1. 用户阅读原文。
2. 遇到语言问题时优先查词或翻译当前选区；译文与必要上下文并列显示，原文和页码始终保留。
3. 遇到概念问题时请求直觉解释和前置知识。
4. 遇到公式时请求变量、维度、步骤和作用拆解。
5. 遇到图表时检查实验设置、横纵轴、比较对象和结论是否匹配。
6. 用户可以高亮、写自己的理解或提出问题；原文、译文和个人理解分别保存，不相互覆盖。
7. AI 回答提供引用；用户点击引用回原文核对。
8. 有价值的回答由用户固定到本次阅读笔记；错误回答则标记反馈。

产物：高亮、个人备注、已解决问题、未解决问题和候选笔记。

### 阶段 4：方法与实验核对

1. 用自己的话复述方法的输入、处理流程和输出。
2. 让系统根据原文检查复述遗漏，但不能直接替用户重写。
3. 建立方法流程、关键公式和模块之间的对应关系。
4. 检查数据集、基线、指标、主要结果和消融实验。
5. 分开记录作者声称的贡献、证据真正支持的结论和用户自己的判断。
6. 记录可能需要复现才能确认的问题。

产物：经核对的方法说明、实验表和局限清单。

### 阶段 5：本次阅读收束

系统根据本次会话、高亮和用户笔记生成草稿，但由用户决定保留内容：

1. 今天理解了什么。
2. 哪些问题已经解决，以及证据在哪里。
3. 哪些问题尚未解决。
4. 下次应从哪一页、哪个问题继续。
5. 哪些内容值得进入正式论文卡片。

用户修改确认后保存；下次打开恢复页面、线程和未解决问题。

### 阶段 6：完成论文卡片

1. 系统按照固定模板汇总已经确认的阅读材料。
2. 未经用户确认的 AI 内容保留“草稿”标识。
3. 用户检查贡献、方法、实验、局限和每条关键引用。
4. 用户把状态改为“已确认”。
5. 系统导出普通 Markdown，并保留回到 PDF 页面的内部引用信息。
6. 论文状态变为“已精读”。

### 阶段 7：进入个人研究资源库

1. 给论文添加主题、方法、数据集和阅读状态标签。
2. 将论文与已有概念笔记、方法笔记和其他论文建立关系。
3. 在明确选择的论文集合内提出比较问题。
4. 将比较结果保存为新的主题笔记，并分别引用每篇论文。
5. 定期回顾未解决问题和可能需要复现的实验。

### 阶段 8：按需启动论文复现

只有当精读后的问题必须通过代码或实验回答时：

1. 创建复现任务，记录目标结论和对应论文页码。
2. 收集官方代码、数据、环境和硬件需求。
3. 再决定是否在 Windows/CUDA 上运行。
4. 将实验配置、结果和失败原因写回论文卡片。

复现始终由明确的阅读问题触发，而不是独立于阅读流程运行。

## 7. 本地数据与产物

建议的逻辑结构：

```text
library/
  papers/                 # 原始 PDF，不进入 Git
  metadata/               # 论文元数据与阅读状态
  processed/              # 分页文本、布局、坐标和切分结果
  indexes/                # 本地关键词与向量索引
  sessions/               # 聊天线程、引用和阅读进度
notes/
  drafts/                 # AI 草稿和本次阅读总结
  confirmed/              # 用户确认的 Markdown 笔记
evals/
  questions/              # 人工评测问题
  runs/                   # 小型、可提交的指标与配置
```

实现时不要求立即创建全部目录。用户可读、需要长期保存的最终产物是 PDF、确认后的 Markdown 和评测记录；数据库与索引随时可以由这些来源重建。

## 8. 推荐技术框架

```text
浏览器界面
React + TypeScript + PDF.js
        ↓ HTTP / streaming
Python 3.12 + FastAPI
        ↓
现有 PDF、切分、检索与卡片模块
        ↓
本地文件 + SQLite 应用状态 + 本地向量索引
        ↓
本地 Embedding / 可替换云端或本地 LLM
```

选择理由：

- PDF.js 适合真实 PDF 阅读、文本层、页码跳转和后续高亮。
- React 适合复杂的分栏、对话、引用跳转和持久状态；前端保持薄层，AI 核心继续用 Python 学习和实现。
- FastAPI 与现有 Python 代码直接连接，也支持后续流式回答。
- SQLite 只保存应用状态和关系；原始 PDF 与确认后的 Markdown 仍是核心资产。
- 不采用 Streamlit/Gradio 作为正式阅读器，因为复杂 PDF 交互、选区、高亮和引用定位会受到限制。

## 9. 开发阶段与验收顺序

### M1：阅读器外壳

- 资料库列出本地论文。
- 打开真实 PDF，支持翻页、缩放和恢复阅读页。
- 右侧出现尚未接模型的提问区域。

### M2：选区与现有检索接线

- 选择 PDF 原文并带上页码。
- 对当前论文执行关键词与语义检索；语义模型只从本机已有缓存加载，缺失时立即提示改用关键词，不让普通阅读请求暗中联网重试。
- 在证据面板显示命中片段和页码。

### M3：带引用的论文问答

- 接入一个模型 API。
- 只根据证据回答；引用可跳回 PDF；模型返回截断或失败状态时不保存不完整结果。
- 区分论文依据、推断和补充背景；证据不足时拒答。

### M4：检索质量提升

- 关键词与向量混合检索。
- 同一进程内可有界复用未变化问题与论文块的向量；论文文字变化必须自动失效，不把内存缓存当持久索引。
- 重排序、参考文献降权和可解释名次。
- 固定问题集、Recall@k 与 MRR 评测。

### M5：阅读记录闭环

- 保存每篇论文的问答记录和引用。
- 添加个人理解，并由用户明确确认。
- 确认后导出普通 Markdown。

### M6：成熟论文卡片

- 由用户为已确认记录选择栏目，再按固定模板确定性生成草稿。
- 显示草稿与正式笔记差异。
- 人工确认后导出 Markdown；修订时生成新版本，绝不覆盖旧文件。

### M6.1：第一版阅读体验补全

- 在网页内直接导入 PDF，并识别重复文件，不要求用户手动整理目录。
- 默认连续阅读与适合宽度，允许收起资料库和助手，在窄窗口中仍能阅读和提问。
- 选中原文后提供翻译、解释、公式拆解和提问入口。
- 在调用云端模型前明确显示数据范围；确认记录必须包含用户理解和论文卡片栏目。
- 提供 macOS 双击启动入口，减少终端操作。

### M6.2：论文结构导航与问题路由

- 优先读取 PDF 书签，没有书签时保守推断章节，并明确显示可靠性。
- 在阅读器旁显示分层目录，点击标题跳到真实 PDF 页码。
- 将页数、章节、标题、段落统计等结构问题与普通内容 RAG 分开。
- 结构问题在本地回答；无法可靠确定时明确失败，不让模型根据局部片段猜测。

### M6.3：论文专属阅读路线与会话

- 根据当前论文的结构动态生成阅读路线和推荐问题；每类任务只采用首个主章节，不因附录同名标题重复阅读任务。
- 同一论文允许建立多个可命名会话，分别整理方法、实验、复现等主题。
- 论文切换后，目录、推荐问题、会话、历史和论文卡片保持严格隔离。

### M6.4：章节感知检索

- 先统一阅读请求契约：论文、会话、原文锚点、任务类型、检索范围和语言策略通过同一个 `ReadingContext` 传递。
- 章节问题自动识别目标标题，并根据相邻标题计算可解释的页码范围。
- 默认优先在目标章节及必要邻近页检索，证据面板显示当前检索范围。
- 用户可以取消章节限定并回到全文检索；章节识别失败时安全回退全文。
- 用固定章节问题验证命中页码，同时确保现有全文检索评测不退步。

### M6.5：双语阅读基础层

当前进度（2026-09-28）：M6.5.1–M6.5.4 已实现语言偏好、选区上下文翻译、翻译复用和论文级人工术语表；M6.5.5 已加入原文语言的本地保守判断与人工覆写；M6.5.6 已实现独立于论文与模型任务的中英文界面切换，见 [开源拆解](research/2026-09-28-interface-language.md) 和 [验收](M6_5_6_VALIDATION.md)。

- 分离界面语言、原文语言、回答语言、翻译目标语言和术语策略。
- M6.5.2：选区翻译优先从当前 PDF 页本地恢复所在段落，并在请求前显示精确选区、恢复上下文和实际发送范围；页码、目标语言与当前会话保存在统一阅读记录。定位失败或跨页时只发精确选区并说明回退，不猜上下文。
- M6.5.3：同一论文与会话中，匹配相同原文选区、同页上下文、语言策略、模型和提示版本时复用已验证译文；命中明确标记“未调用 API”，用户可以重新翻译。失败和旧版本记录不可命中。
- M6.5.4：术语表按论文及目标语言隔离，只有命中选区/同页上下文的有限条目进入翻译提示；术语只代表用户译名偏好，不是论文证据。相关术语变化使旧译文缓存失效，未命中的术语变化不影响复用。
- M6.5.5：原文语言由 PDF 前几页的可抽取文本在本地保守估计为英文、中文、中英混排或未知；用户可按论文覆写英文/中文。判断与覆写不自动改变回答语言、翻译目标、检索证据或缓存复用。
- M6.5.6：界面语言属于浏览器使用者，不属于论文；以完整前端消息表实现中文/英文切换，并确保问答、翻译、证据和 PDF 原文不随 UI 文案切换。不得只翻译导航而留下半套混合界面。
- M6.6：当前页按需翻译是真正的论文翻译入口，原始 PDF 始终留在阅读区，译文以原文页码在右侧显示；首次点击才调用 API，后续本地缓存读取，可主动重译。中文目标的长输出若明显仍主要是英文，则失败关闭且不写缓存。它只是页级对照，不声称已有精确段落/公式对齐。见 [开源拆解](research/2026-09-28-page-translation.md) 和 [验收](M6_6_VALIDATION.md)。
- 原文、译文、页码、上下文范围和术语版本保存为统一阅读记录，可加入当前会话但不能自动确认。
- 增加论文级语言偏好、术语表与翻译缓存；论文切换时严格隔离。
- 中文提问继续直接检索英文原文，证据区不被译文替换。
- 此阶段不做整篇 PDF 重排；等 M7 建立可靠布局块和坐标后再增加章节/全文双语视图。

### M7：复杂论文解析与可靠双语对照（优先满足读论文目标）

- M7.1：当前页的本地解析质量关卡在翻译前显示可抽取字符数、明显乱码/空页/超长页以及数学符号复核提示；坏页拒绝发送 DeepSeek。它不代表阅读顺序与公式已经准确。见 [开源拆解](research/2026-09-29-page-extraction-quality.md) 和 [验收](M7_1_VALIDATION.md)。
- M7.2：为当前页可抽取文字建立带页码和 PDF 坐标的只读原文区域，点击区域在原 PDF 上高亮定位；不修改页级译文和阅读记录，也不宣称已完成段落顺序或译文对齐。见 [开源拆解](research/2026-09-29-page-source-anchors.md) 和 [验收](M7_2_VALIDATION.md)。
- M7.3：用固定双栏样本、真实公式页和表格页评测版面风险；在 M7.2 原文锚点上显示可解释的风险提示，阅读顺序继续标为未验证，不把几何坐标当作块级译文对齐。见 [开源拆解](research/2026-09-29-layout-risk-evaluation.md) 和 [验收](M7_3_VALIDATION.md)。
- M7.4：分步选择可验证的布局/公式/表格解析路径。M7.4a 针对真实论文中“一个视觉公式被文本层拆成两行”的明确失效扩大原图保护范围，复用页级译文而不声称逐块对齐；见 [开源拆解](research/2026-09-30-display-math-continuation.md)。M7.4b 对横线和文字边界都可唯一确认的简单表格，以原 PDF 图像替换待翻译的线性化表格文字，周围正文继续翻译，不宣称单元格已翻译；见 [开源拆解](research/2026-09-30-ruled-table-translation.md)。M7.4c 用真实双栏页与错序合成页建立翻译前顺序关卡：普通双栏候选只提示复核，明确多次跨栏交错则在本地阻断整页翻译，不自动重排；见 [开源拆解](research/2026-09-30-column-reading-order.md)。行内公式另设样本门槛，只有通过原图对照和顺序评测后才进入逐块双语对照。

## 10. 第一版成功标准

选择一篇真实的英语 AI 论文，用户能够：

1. 在 ResearchCopilot 页面打开并持续阅读 PDF。
2. 关闭后重新打开仍回到上次阅读位置。
3. 选择不理解的段落并获得中文翻译或解释。
4. 提出至少五类问题：概念、方法、公式、实验和局限。
5. 每个基于论文的回答都能点击引用返回正确页码。
6. 检查模型实际使用的原文证据，并识别一次证据不足的情况。
7. 将选中的问答和高亮整理为本次阅读总结。
8. 人工确认一份结构化论文卡片并导出 Markdown。
9. 在评测页比较至少两种检索或切分策略。
10. 界面语言和回答语言可以独立设置；中文问题可以定位英文证据，翻译结果可以回到未被替换的原文。

满足以上标准，才算完成“帮助读懂单篇论文”的第一版，而不是仅完成一个聊天界面。

## 11. 框架确认项

以下取舍建议作为默认决定：

1. 主界面使用本地网页，而不是依赖 Obsidian。
2. 阅读工作台以 PDF 为中心，右侧 AI 只是辅助区域。
3. 技术栈采用 FastAPI + React/TypeScript + PDF.js。
4. 当前论文问答默认只检索当前论文；跨论文需要用户明确切换范围。
5. 云端模型只接收检索证据；本地完成解析、Embedding 和索引。
6. AI 总结永远先进入草稿，只有用户确认后才进入正式 Markdown。
7. 先完成单篇论文阅读闭环，再做跨论文、知识图谱和 Windows 复现。
8. 翻译、解释、问答和总结复用统一阅读上下文、证据与记录模型，不建立平行的数据孤岛。

用户确认这些取舍后，后续里程碑不得随意改变主线；若需要改变，应先更新本蓝图并说明原因。
