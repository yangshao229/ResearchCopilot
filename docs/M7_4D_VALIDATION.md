# M7.4d 行内数学参数保护：阶段验收

日期：2026-10-02。

## 实现结果

- 先完成[开源论文阅读产品拆解](research/2026-10-02-inline-math-preservation.md)，再对真实 `sample.pdf` 第 7 页开发。
- 对从文字层抽到的希腊字母参数赋值，只有在当前 PDF 页找到唯一、同一视觉行的字符序列时，才用同页原图小裁片替换待翻译文字。周围散文仍由模型翻译；不推断或重写上下标。
- 原有展示公式、表格保护、页码、页级译文和 PDF 裁图组件继续复用。新增的 `inline` 属性缺省为 `false`，旧结构仍可读取；翻译缓存版本升级，旧译文不删除但不复用。
- 未唯一定位的表达式保持原流程，质量关卡提示数学内容需对照原 PDF；并未宣称整页所有行内公式都正确。

## 真实 PDF 与自动验证

- 目视核对 `sample.pdf` 第 7 页：原文为带下标的 `β₁`、`β₂` 和带上标的 `ϵ = 10⁻⁹`，文字抽取丢失这些排版信息。使用本地字符坐标后，三处参数获得同页小裁片位置，另两处独立公式仍按旧机制保护。
- 最初用**假翻译模型**走完整页服务流程：模型收到五个公式占位符而非三处参数的失真文字；结果保留页码和裁片坐标，缓存可读取。此步骤没有产生 API 费用。
- 新增测试覆盖多个参数、周围散文、视觉位置或源文本重复、PDF 缺失或字形不匹配、占位符缺失，以及希腊语普通散文不误报数学。
- 初次完整 Python 测试 `131 passed`；前端 TypeScript 检查与生产构建通过。构建仅有既有的大包提示。

## 2026-10-03 真实 API 与浏览器复核

- 确认项目 `.env` 已配置 DeepSeek，测试论文第 7 页目标语言为简体中文、抽取文字 3300 字符，且新提示版本无缓存后，**只发起一次**该页的真实翻译请求。HTTP 200；生成 5 处公式占位，其中 3 处为行内参数，所有占位符各出现一次，结果成功保存。周围训练、硬件及优化器段落译为中文。没有重复调用模型。
- 第二次读取返回 `cache_hit=true`。网页在最新服务上显示“已从本地缓存读取 · 未调用 API”；3 处行内参数嵌在中文句中，另 2 处独立公式显示原 PDF 图像。目视检查行内裁片包含原始上、下标；**尚未逐句人工校对整页译文**。
- 常用 `8000` 端口最初由 9 月 30 日启动的旧 ResearchCopilot 进程占用，曾显示旧版本缓存的普通参数文字。核实进程身份后将其重启；现在该端口的缓存 API 返回 5 处公式，其中 3 处为行内裁片。临时验收用的 `8001` 服务已停止，原入口仍为 `http://127.0.0.1:8000/`。
- 浏览器验收时发现提示文案仍暗示所有行内公式均未保护；已改为说明“唯一定位的部分行内参数会保留原图，其余仍需核对”。修正后完整测试通过，前端 TypeScript 检查与构建通过；构建仍仅有既有的大包提示。

## 局限与下一步

- 当前只支持狭窄的希腊字母参数赋值，不覆盖一般行内公式、复杂上/下标、扫描页、表格单元或双语逐块对齐。仅有一个真实论文页作为本阶段人工真值，不宜泛化为全面数学解析。
- 不唯一或无法核对原文的表达式不自动裁图；用户仍应以中间原始 PDF 为准。
- 下一阶段若扩展识别范围，先按项目约定拆解成熟开源方案，并为多种 PDF/表达式建立人工真值与误报评测。
