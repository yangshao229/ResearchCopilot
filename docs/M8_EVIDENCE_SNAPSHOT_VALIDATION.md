# M8 已查看证据快照：第三步

日期：2026-10-06。按[已查看证据与回答的一致性拆解](research/2026-10-06-evidence-snapshot.md)完成统一证据包的请求间交接；不改变排序、拒答门槛或模型。

## 完成内容

- 搜索接口在当前 PDF 版本可核验且属于内容问题时，返回短期 `X-Evidence-Snapshot` 令牌；令牌只引用服务进程内的深拷贝 `EvidenceSet`，不包含论文正文。
- 回答携带令牌时，必须逐项匹配论文、`paper_uid + pdf_sha256`、问题、检索模式、候选条数和范围偏好；匹配后直接使用用户刚查看的证据与编号，不进行第二次检索。
- 请求开始前 PDF 字节、问题或设置变化，令牌过期／淘汰、服务重启或伪造令牌都会返回 `409` 并提示重新检索，且不调用模型或写入历史。若 PDF 在模型生成过程中才变化，模型可能已经调用，但结果不会保存到历史。
- 前端只把当前搜索结果对应的令牌带入同一问题的回答请求；旧客户端不传令牌时继续兼容原有直接问答路径。
- 快照有 128 条上限和 15 分钟存活期，只存在内存中，不持久化到 Vault、阅读历史或翻译缓存。

## 自动验收

- API 先查看原始片段，再模拟底层抽取缓存内容变化；持令牌回答仍使用原片段、原引文和原编号，检索器总调用次数保持为 1。
- 问题、模式、条数、范围或 PDF 版本变化均在模型调用前拒绝；历史仍为空。
- 单元测试覆盖深拷贝隔离、来源锚点校验、TTL 过期、有界淘汰和跨论文键隔离。
- 阶段首次完整 Python 测试：`197 passed`；随后补充服务重启、无来源候选，以及模型调用期间 PDF 变化不能保存旧回答的回归。最新全量测试 `200 passed`，只有两条既有测试依赖弃用警告。
- 前端 TypeScript 与生产构建通过；仍有既有的大分块提示，不影响本阶段功能。

## 边界

这一步只保证“回答使用的是用户刚看过的那批证据”，不证明这批证据找对了、足够回答问题，或支持无答案拒答。M8.4e 的多语重排器仍未进入默认检索；下一步继续做失败例和证据充分性真值分析，不把快照令牌或模型分数解释为答案置信度。

本阶段没有调用 DeepSeek，没有修改论文、翻译缓存或用户阅读数据，也没有写用户真实 Vault。
