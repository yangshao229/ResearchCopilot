# M6.5.2 验收：选区上下文翻译

日期：2026-09-26

## 完成内容

- 新增同页选区定位与上下文预览。能唯一定位且有空行段落边界时取所在段落；PDF 文本层边界不可靠时只取有长度上限的同页窗口；无法匹配、选区重复出现或短页会导致整页发送时，退回精确选区。
- 预览在本地完成。阅读器展示论文页码、目标语言、选区、上下文和回退原因；只有用户点击“发送选区翻译”才调用 DeepSeek。
- 翻译请求使用 `task=translate` 和原文锚点。精确选区作为唯一翻译证据；同页上下文只用来消歧。翻译结果沿用当前论文、会话和语言偏好。
- 阅读记录保存任务类型、页码锚点和上下文文本；既有记录缺少这些字段时使用兼容默认值。
- 普通提问仍沿用检索链；不把译文混入论文检索，也不新增平行会话/历史存储。

## 验证

- 后端完整测试：`88 passed, 2 warnings`。
- 前端 TypeScript 检查与生产构建通过；Vite 仅提示现有 PDF 阅读器 bundle 超过建议大小。
- `sample.pdf` 本地验证：在 PDF 第 2 页选择 `significantly more parallelization`，恢复结果包含完整所在语境并标记为“同页有限上下文”；不需要联网、Embedding 模型或 DeepSeek API。
- 自动测试覆盖：段落恢复、PDF 换行/边界不可靠回退、无法匹配、重复匹配、避免整页发送、翻译只用当前选区证据、目标语言/上下文传给模型、引用页码、记录锚点/上下文、缺少锚点拒绝。
- 未调用真实 DeepSeek。当前运行环境访问 Hugging Face 超时，不影响本阶段，因为页内上下文来自已有本地 PDF 分页文本。

## 已知边界

当前 PDF.js/PyPDF 文本抽取并不总能表达真实段落布局。系统对此采取保守策略：只有明确空行边界才声称恢复了段落；否则说明使用同页有限文本窗口，或仅发送选区。多栏、跨页、公式和表格周围的结构化上下文需要 M7 布局解析，不在本阶段假装解决。
