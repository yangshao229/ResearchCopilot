# M7.3 阅读顺序与复杂版面风险验收

日期：2026-09-29。

## 目标与边界

本阶段不是逐块翻译，而是在 M7.2 原文坐标上增加可解释的版面风险提示，并建立固定样本验收。所有页面的 `order_verified` 继续为 `false`；即使没有风险标记，也不能推论顺序正确。

## 自动验证

- 完整 Python 测试：`114 passed`；前端 TypeScript 检查和 Vite 生产构建通过。
- 合成双栏页：返回 `multi_column_candidate`，保留左右两块独立坐标，不把 y 排序当阅读顺序。
- 合成横线表格页：返回 `table_rulings_candidate`，不声称已经识别表格单元。
- 合成小字形页：返回 `small_glyph_fragments`，不把上下标碎片当普通正文。
- 合成普通单栏页：风险列表为空，但 `order_verified=false`，不误授予“已验证”状态。
- 空白页和旋转页仍按 M7.2 显式降级，不能伪造原文区域。

## 真实论文检查

渲染 `data/raw/sample.pdf` 的第 5 页（公式）和第 6 页（带横线的表格）并目视检查。第 5 页布局风险为 `small_glyph_fragments`；第 6 页为 `table_rulings_candidate` 与 `small_glyph_fragments`。第 6 页的表格只有横线，现有 pdfplumber `find_tables()` 未找到表格；本阶段的信号只指出“这里像表格”，并未恢复单元格或数学表达。

## 产品验证

在本地阅读器的“译文”页签实际核对：第 5 页显示“小字形碎片”提示，第 6 页同时显示“类似表格的横线”和“小字形碎片”提示。具体风险出现在“原文位置”列表之前；界面明确提示以中间原 PDF 为准，且提示本身不会自动重译、产生 API 费用或修改现有译文缓存。

## 决策

当前证据不支持把 M7.2 区域列表直接作为逐块翻译输入。尤其是横线表格没有单元关系、公式上下标被文本层拆散。M7.4 应先确定布局解析和评测门槛，再决定使用轻量局部修复还是引入成熟模型；界面继续保留按页译文和原 PDF 对照。
