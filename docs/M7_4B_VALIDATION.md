# M7.4b 有横线的表格页安全翻译：阶段验收

日期：2026-09-30。

## 已完成

- 先完成[开源产品拆解](research/2026-09-30-ruled-table-translation.md)，再实现局部表格保护。
- 对有至少三条长横线、表内文字行和原文范围均可唯一定位的表格，在模型输入中以占位符替换表格单元文字。表题及表格之外的正文仍发送翻译。
- 右侧译文用当前论文的本地 PDF 裁图显示表格，标注“原文表格，尚未翻译”；窄栏可水平滚动，不将表格图像发送给 DeepSeek。
- 模型若丢失或重复表格占位符，拒绝保存译文。新版缓存不复用旧解析结果，旧文件也不会被删除。

## 验证证据

- 对真实 `data/raw/sample.pdf` 共 15 页做本地检测，第 6 页表 1 被保守识别；表题、后续 `3.5 Positional Encoding` 正文仍在待翻译文本中，表内单元格文字不在其中。其他页没有被这套有横线规则误判为受保护表格。
- 阅读器中实际点击第 6 页“翻译当前页”后，DeepSeek 返回中文表题和后续正文；中间仍是原 PDF，右侧显示同页原文表格图像。此验证调用真实 API 一次，可能产生费用。
- 刷新后第 6 页译文直接从本地缓存读取，没有再次调用 API。窄侧栏中的原图支持横向滚动，用户仍应与中间 PDF 对照。
- 合成测试覆盖有横线表格、无横线页、文字匹配不唯一、占位符丢失/重复。完整 Python 测试 `121 passed`，前端 TypeScript 检查与生产构建通过；仅有既有的依赖弃用警告和大体积 JS 提示。

## 明确边界与下一步

- 表格**尚未翻译单元格**，也没有识别行列结构。对无横线、跨页或定位不唯一的表格，本阶段不保护，仍须根据版面风险提示核对 PDF 原文。
- 这套规则在真实样本中只覆盖第 6 页；不能由此推断其他论文表格已安全处理。
- M7.4 整体尚未完成。下一小阶段先针对双栏顺序与行内公式建立真实样本和判定标准，再决定是否需要结构化解析器；不得直接宣称逐块双语对齐。
