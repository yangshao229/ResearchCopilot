# M8.U3：窄屏与 Safari/WebKit 基础兼容

日期：2026-10-05。依据：[开源产品拆解](research/2026-10-05-narrow-screen-safari-compatibility.md)与[成品化路线](PRODUCT_COMPLETION_PLAN.md)。

## 交付

- 应用外壳改为纵向 flex 布局，并同时保留 `100vh` 与 `100dvh`；顶部栏换行后，阅读工作区自动占据真实剩余高度，不再依赖固定的 76px 减法。
- 720 CSS 像素及以下时，顶部操作区允许换行，语言文字标签以可访问方式隐藏，资料库覆盖面板、页码与缩放控件、欢迎区和长路径都能在窄屏内换行或局部滚动。
- PDF 阅读区和助手内容保留各自滚动，并启用 WebKit 触摸惯性滚动；普通界面内容不要求页面级横向滚动。
- PDF 宽度在挂载时立即读取。浏览器支持 `ResizeObserver` 时继续精确观察；不支持时退化为监听窗口 resize，不因缺少该 API 而启动失败。
- 没有新增依赖、后端 API、模型调用或数据写入，也没有改变 PDF 文本层、引用页码、翻译与证据范围。

## 验证

- 完整后端测试 `177 passed`，仅有既有的两个依赖弃用警告。
- 前端 TypeScript 检查与生产构建通过；仍有既有的大分块提示。
- 已静态检查 320px 级别窄屏规则、动态视口回退、顶栏换行后的高度分配、长内容换行、局部滚动，以及 `ResizeObserver` 缺失时的回退路径。
- 受限环境无法安全启动 8010–8099 的临时本地服务，因此没有把静态构建冒充真实 Safari 浏览器验收，也没有停止、重启或替换任何已有进程。最终仍需用户在本机 Safari 中完成一次真实论文阅读闭环人工验收。
- 没有修改论文、阅读记录、Vault 或翻译缓存，没有读取密钥或调用 DeepSeek。

## 后续

自动化可用性收尾已完成。下一项成品门槛是用户在本机 Safari 中用一篇真实论文走完“导入 → 阅读／证据核对 → 确认个人理解 → 预览并保存到 Obsidian → 创建论文卡”的人工验收；真实 Vault 写入必须继续由用户逐次确认。M8.V4 等真实笔记数量足以暴露查找问题后再做，M8.4e 仍需用户允许下载并固定新 reranker。
