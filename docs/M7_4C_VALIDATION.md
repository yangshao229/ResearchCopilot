# M7.4c 双栏页阅读顺序关卡：阶段验收

日期：2026-09-30。

## 实现结果

- 依照[开源产品拆解](research/2026-09-30-column-reading-order.md)，增加本地双栏候选和明显交错检查。它只检查 PDF 文字抽取序列，**不自动重排**，也不宣称阅读顺序已验证。
- 对明显双栏但没有反复跨栏回跳的页面，质量状态为“需复核”，仍可按需翻译；对多次从右栏跳回左栏的正文，状态为“阻断”，禁止整页译文生成及旧缓存展示，提示改为划选单栏或段落。
- 修复窄中缝的原文区域分组：左右栏不再因为固定的较大间隙阈值合成一个横跨页面的高亮框。区域仍按视觉坐标展示，不代表阅读顺序。
- 两种检查都复用现有 PDF 页码、`PageQuality`、译文 API 和本地缓存，不增加数据库、云调用或新模型。

## 真实 PDF 核对

- 临时下载并渲染 [BERT 原论文](https://arxiv.org/pdf/1810.04805)，目视检查第 2、6 页；临时 PDF 和 PNG 未加入 Git。第 2 页是明显双栏，当前 `pypdf` 先抽左栏再抽右栏，报告为“需复核”而非误阻断。
- 第 6 页上方有通栏表格和说明，正文才是双栏。初版几何检查曾把表格说明的两次右到左跳转误认为正文错序；增加通栏文字边界排除后，第 6 页恢复为“需复核”。这是一次真实样本驱动的误报修复。
- 对 BERT 全 16 页做本地扫描：15 页为双栏候选，1 页未检出；没有页面被本规则硬阻断。这个扫描**不等于**确认 16 页都具有正确阅读顺序。
- 项目现有 `sample.pdf` 15 页均未被误认为双栏候选。BERT 第 2 页的原文位置不再出现横跨左右栏的单个框。未调用 DeepSeek。

## 自动验证

- 合成先左后右、逐行左右交错、通栏说明后接双栏、窄中缝、单栏/空白页五类情形；覆盖质量报告、服务端翻译与缓存读取、HTTP API 的阻断路径。交错页的假模型调用计数保持 0。
- 完整 Python 测试 `127 passed`；前端 TypeScript 检查及生产构建通过。仅有既有的测试依赖弃用警告和 Vite 大包提示。

## 局限与下一步

- 几何审计只捕捉**明显的反复交错**；复杂图表、脚注、单次错序、文字层损坏、旋转页和少量文字可能无法判断。无阻断绝不代表自动顺序正确。通栏内容以后的双栏页也可能因保守过滤而漏检。
- 检索和问答沿用原有文本索引，此关卡只保护整页翻译；不能据此宣称所有跨栏问答证据顺序可靠。
- 后续若要自动重排或逐块对齐，应建立更多有人工真值的论文页并比较成熟布局解析器；行内公式、表格单元格和扫描页仍各自需要独立验收。
