# 开源自测版验收记录

日期：2026-10-12。范围：准备公开源码自测版；不复制用户 PDF、Vault 或 `.env`。

## 已验证

- 用户选择 Apache-2.0；`LICENSE` 与 Apache 官网标准文本逐行一致，`pyproject.toml` 声明相同许可。
- `uv lock --check --offline` 通过，87 个包解析一致。在独立的 macOS 虚拟环境中运行 `uv sync --locked`，从网络下载缺失的公开依赖并成功安装 67 个包；再以此环境运行 `python -m pytest -q`：232 passed、2 个依赖弃用警告。这验证了本机的干净 Python 依赖安装，但不等于另一台电脑的安装结果。
- `npm --prefix web ci --dry-run --offline` 完成锁文件安装预演；现有本机前端依赖运行 `npm --prefix web run build` 通过，有包体积警告。尚未在干净的前端依赖目录中实际运行 `npm ci`。
- 增加 CLI 测试：`0.0.0.0`、`::`、局域网 IP 和普通域名在绑定前被拒绝；`127.0.0.1`、`localhost`、`::1` 可用。
- 检查了本机已安装的直接 Python／前端依赖元数据：直接依赖标示 MIT、BSD-3-Clause 或 Apache-2.0；`pdfplumber` 的分发元数据分类与自带 LICENSE 标示 MIT。这里只是直接依赖初筛，不涵盖全部传递依赖，也不是法律意见。
- `git diff --check` 通过。已做针对常见 Key 形态、个人绝对路径、历史中的 PDF／`.env`／密钥文件的保守扫描，未发现拟发布文件中有这几类命中。此扫描**不等于完整密钥审计**。

## 尚未验证／公测限制

- 还没有在独立电脑上运行完整的 macOS 与 Windows 安装及浏览器流程；Windows 命令只是按工具的跨平台语法写成，不能声称已通过 Windows 实测。
- 没有对用户的真实 DeepSeek Key、私人 PDF 或 Vault 执行自测，也没有把它们加入发布材料。
- 正式公开前需逐个核对拟提交清单及**全部 Git 历史**。不要使用 `git add .` 草率把个人资料一起加入。
- 传递依赖与未来若要分发的预构建前端包还需做许可证与来源核查；本轮的直接依赖初筛不能替代完整审计或法律意见。

下一次发布验收应让至少一位测试者用公开论文走通“安装 → 导入 → 阅读 → 关键词证据 → 可选 DeepSeek → 可选个人 Vault → 脱敏反馈”，并分别报告 macOS 与 Windows 结果。
