# M8.4b 真实双论文检索策略对照验收

日期：2026-10-04。设计依据见[开源产品拆解](research/2026-10-04-multi-paper-retrieval-strategy.md)。本阶段只做离线对照，不修改网页中的多论文证据 API 或默认检索方式。

## 固定条件

- 原始论文、SHA-256、6 个问题、人工页码锚点与已知无关页均沿用 [M8.4a 真值账本](evaluations/m8_4a_real_two_paper_truth.json)，每篇最多返回 3 个**不同 PDF 页**。
- 基线是当前 `/api/research/evidence` 的逐页全词匹配；候选是项目已实现的 1000 字符切块、100 字符重叠的语义与 RRF 混合检索。候选先取最多 24 个切块，再按排名去重为每篇 3 页。
- 本机 E5 模型为 `intfloat/multilingual-e5-small`，固定 Hugging Face 修订 `614241f622f53c4eeff9890bdc4f31cfecc418b3`，只从本地缓存加载。缺失时不联网下载。运行命令：`.venv/bin/python scripts/compare_real_multi_paper_retrieval.py`。
- 全程使用临时分页缓存；未调用 DeepSeek、读取密钥或更改 PDF、阅读历史、论文卡片和译文缓存。

## 同账本结果

| 策略 | 预期来源有结果 | 命中人工页锚点 | 正确无证据 | 已知无关页 / 返回页 | 范围泄漏 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前逐页关键词 | 5/9 | 5/9 | 3/3 | 3/15 | 0 |
| 语义切块 | 9/9 | 6/9 | 0/3 | 0/36 | 0 |
| 混合切块 | 9/9 | 8/9 | 0/3 | 0/36 | 0 |

混合检索在中文位置问题上命中 Transformer PDF 第 6 页和 BERT PDF 第 4 页；英文位置问题只命中 BERT 第 4 页，Transformer 第 6 页落在前三页之外。对 `masked language model`，Transformer 应当无此任务，但语义和混合都强行返回了页；对 `quantum entanglement`，两篇论文都被强行返回了页。因此“来源有结果 9/9”不是可信证据率，实质上只说明向量检索总会排序出一些内容。

“已知无关页”只标注了原账本中 `learning rate` 的少数页，是一个下界；候选策略的 `0/36` **不表示 36 页均相关**。尤其是明确无证据组合返回的 9 页已经构成误导风险，不能被这个数字掩盖。此小样本不能证明跨论文一般准确率。

## 验证与边界

- `tests/test_real_multi_paper_evaluation.py` 新增页去重及 Embedding 缓存回归测试；完整 pytest `148 passed`，前端 TypeScript 检查与生产构建通过。既有依赖弃用提醒及 Vite 大包提醒未在本阶段处理。
- 原始 PDF 及模型权重均不随 Git 同步；另一台电脑需要自行取得账本指定版本并缓存指定修订，否则候选策略明确失败。
- 对照没有把语义分数解释为“有证据”阈值，也没有把检索结果发给生成模型。

## 决策

保留 M8.3 当前证据接口不变，继续关闭跨论文比较答案及主题笔记生成。下一小步需要在固定账本上设计并评测可解释的无证据门槛，同时修复英文自然问句漏掉 Transformer 位置编码页；只有页码召回和拒答同时过关，才考虑把改进接入用户流程。
