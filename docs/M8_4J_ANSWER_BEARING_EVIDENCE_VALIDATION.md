# M8.4j：答案承载证据覆盖影子验收

日期：2026-10-08。状态：**离线诊断，不改变产品检索或回答**。

设计依据：[答案承载证据覆盖开源评测拆解](research/2026-10-08-answer-bearing-evidence-shadow.md)。

## 验收对象

M8.4i 只判断正确 PDF 页是否进入 Top-5。为了检查该页中真正回答问题的片段是否被取回，本轮为 RAG 论文的 4 组中英文正例增加 18 个必须覆盖的原文概念组。每组允许少量来自同一固定 PDF 文本层的等价短语；一个 Top-k 证据集合必须覆盖全部概念组才算“答案承载短语完整”。

该指标是确定性字符串覆盖，只能证明原文事实出现在送检片段中，不能证明关系理解正确、证据语义充分、引用忠实或最终回答正确。两道无答案题不参与短语覆盖计数，也不会因缺少短语而被自动判为可拒答。

## 真实离线结果

| 指标（8 条正例） | 混合检索 | mMARCO | BGE |
| --- | ---: | ---: | ---: |
| 正确页进入 Top-5 | 7/8 | 8/8 | 8/8 |
| 答案承载短语在 Top-5 完整 | 5/8 | 7/8 | 7/8 |
| 答案承载短语在 Top-1 完整 | 1/8 | 1/8 | 6/8 |
| 前五个不同页中的短语完整 | 5/8 | 5/8 | 6/8 |

最关键的失败例是中文“RAG-Sequence 的快速解码如何近似彻底解码”：正确 PDF 页 4 在 30 个候选中名次为 4，但候选池没有包含说明 Thorough Decoding 额外前向计算与 Fast Decoding 近似的那个片段，两个必须概念组均为 `0/2`。因此两种重排器都不可能补救；这是片段候选召回失败，而不是页码召回或重排失败。

页级去重也暴露新风险。mMARCO 的页命中仍为 `8/8`，但每页只保留最高片段后答案承载覆盖从 `7/8` 降到 `5/8`；BGE 从 `7/8` 降到 `6/8`。同一页的多个片段可能共同覆盖答案，简单去重会丢失互补证据，不能直接作为生成上下文策略。

## 兼容、隐私与失败边界

- 旧评测账本没有 `evidence_requirements` 时继续输出原指标，短语覆盖字段为 `null`，不改变旧结果。
- 英文／中文同义问题共享英文原文要求；译文缓存、会话和用户记录不参与。
- 只读取固定 PDF、E5 与本机模型缓存；PDF 哈希或模型快照不匹配时失败关闭。
- Unicode 与空白只做确定性归一化；抽取断词、未列出的同义表达、否定上下文和关系错误仍可能导致误判。
- 没有调用 DeepSeek、上传 PDF、修改用户论文、阅读历史、翻译缓存或真实 Vault。

## 自动回归与构建

- 新增纯函数测试覆盖多概念组、组内变体、跨片段累计和旧账本兼容。
- 新增回归明确证明“页码命中但答案承载事实不完整”会被分别记录。
- mMARCO 与 BGE 两个固定修订均完成真实离线复跑；候选池短语完整均为 `7/8`。
- Python 全量回归 `203 passed`，前端生产构建通过。

## 决策

**不把页命中率当证据充分性，不上线页级去重，也不接入任一重排器。** M8.4i 的 `8/8` 页覆盖被本轮收窄为 `7/8` 答案承载短语覆盖，而且这一缺口发生在重排前。下一步先在更多独立论文上冻结答案承载事实，并分析切分与候选生成为什么漏掉正确页中的关键片段；最终仍需把片段覆盖与生成拒答分别验收。

复现命令沿用 [M8.4i](M8_4I_INDEPENDENT_PAPER_VALIDATION.md)，评测器会在 JSON 结果的 `answer_bearing_evidence` 和每个 case 的 `*_evidence_coverage_*` 字段中给出新指标。
