# M7.2 原文区域定位验收

日期：2026-09-29。

## 范围

在现有逐页译文旁提供当前 PDF 页的本地原文位置列表，点击后滚动至原文并高亮区域。位置只是核对入口，不表示翻译已经逐段对齐，也不替换原始 PDF。

## 验证

- Python 完整测试：`113 passed`。新测试覆盖合成双栏 PDF 的左右区域不误合并、空白页、旋转页，以及 API 按论文/页码读取和错误路径。
- 前端执行 `npm run build`：TypeScript 检查和 Vite 生产构建通过；存在既有的大包体积提示。
- 真实 `data/raw/sample.pdf` 第 5 页：本地解析状态为 `ready`，提供 22 个原文区域，页尺寸 612 × 792 point。渲染该页目视确认包含正文、公式和小节标题。
- 本地浏览器验收：在“译文 → 原文位置（22 处）”点击区域 11（`3.2.3 Applications of Attention in our Model`），中间 PDF 滚动至第 5 页相应标题，并显示橙色高亮。检查结果仅来自本地服务，没有调用 DeepSeek。
- 后端只读端点：`GET /api/papers/{paper_id}/pages/{source_page}/layout`，原文区域带稳定 ID、页码和左上角坐标。切页或换论文清除旧高亮。

## 已知限制

- 区域列表是几何定位，不是可信段落划分；`order_verified=false`。双栏阅读顺序、表格结构和译文对应关系尚未确认。
- 第 5 页公式中的上下标在 PDF 文本层被拆成碎片，列表中的抽取文字不能当作数学表达；应查看高亮处的 PDF 原图。M7.2 不把这些碎片交给翻译流程。
- 旋转页不返回伪坐标，扫描页或无文字页返回空区域；OCR 留待后续阶段。
- 当前最多展示 80 个区域且只按需解析当前页；复杂大文件的性能仍需单独评测。

## 下一步

M7.3 先做一轮开源论文阅读产品拆解，再使用真实双栏、公式和表格样本评估内容类型与阅读顺序。只有通过质量门槛，才把原文块与现有按页译文流程对齐。禁止将本阶段的原文片段顺序直接发送给模型并称为“精确逐段翻译”。
