# ResearchCopilot 使用说明书

更新：2026-10-09。适用范围：Mac 上的本地论文阅读工作台。先读论文、核对原文，再决定哪些理解值得保存到 Obsidian；AI 回答不是已核实的研究笔记。

## 1. 启动与关闭

首次在这台电脑准备项目，在项目根目录执行：

```bash
uv sync --locked
npm --prefix web ci
npm --prefix web run build
```

若要使用 AI 问答或翻译，在项目根目录把 `.env.example` 复制为 `.env`，只在本机填写自己的 `DEEPSEEK_API_KEY`。没有 Key 仍能打开 PDF、看目录、做本地关键词检索与阅读记录；调用 DeepSeek 的按钮才需要 Key 和网络。不要把 Key 发给他人或提交到 Git。

以后在访达打开项目文件夹，**双击 `Start ResearchCopilot.command`**。启动窗口会打印完整的本机地址并自动打开浏览器。保持这个终端窗口运行；关闭它，网页服务也会停止。第一次被 macOS 拦截时，在访达右键启动文件并选择“打开”。普通使用不需要请 Codex 授权。

也可以在项目根目录手动启动：

```bash
uv run research-copilot serve
```

地址不一定是 `http://127.0.0.1:8000/`：如果 8000 已被占用，程序会选择 8001–8019。**以本次启动窗口打印的地址为准**，不要打开旧标签页。

## 2. 导入并打开论文

1. 在左侧资料库点击“+ 导入 PDF”，选择本机论文 PDF。导入不会把论文上传到云端；文件保存在项目的 `data/raw/`。
2. 左侧出现文件名和页数后，点击论文。重复导入同一份 PDF 不会产生第二份副本。
3. 中间阅读原 PDF。用“上一页／下一页”、页码输入框或连续滚动定位；右侧“目录”可跳到论文自带章节。PDF 的**文件页码**是引用依据，可能不同于论文页脚印刷的页码。
4. 中间 PDF 与右侧助手各自滚动。窄屏时可收起资料库或助手，给论文留出空间。

本项目已导入练习论文 `lora-hu-2021-v2.pdf`（26 页）。它是 [LoRA 原论文的 arXiv v2](https://arxiv.org/abs/2106.09685)；PDF 第 4 页的 “4.1 Low-Rank-Parametrized Update Matrices” 适合练习核对方法与公式。论文只保存在本机，不会随 Git 共享；在另一台电脑上使用时需重新导入。

## 3. 翻译英文论文

1. 打开目标 PDF 页，在右侧选择“译文”。先读页面质量提示：若提示扫描页、损坏文字层或明显双栏错序，请改用原文选区，不要信任整页译文。
2. 点击“翻译当前页”。只有这时，本页可抽取的文字才会发送给已配置的 DeepSeek；不会上传整篇 PDF。调用 API 可能产生费用。
3. 译文按 PDF 文件页码存到本机缓存。再次回到同一页，右侧会显示“已从本地缓存读取”；点击“重新翻译本页”才会再次调用 API。
4. 独立公式、部分行内参数与有横线的表格可能以原 PDF 裁图嵌在译文里；未识别的公式、特殊字符、双栏和表格仍须对照中间原文。选中较短原文可做选区翻译，适合复杂页面。

目标语言和专业术语偏好可在“提问”里的“论文语言偏好”修改。修改偏好后，新译文可能重新调用 API。不要把译文里的数学表达直接当作可复现公式。

## 4. 搜索、提问与核对证据

1. 在右侧“提问”输入具体问题，先点击“只查原文证据”。例如练习 LoRA：`4.1 Low-Rank-Parametrized Update Matrices 中，LoRA 训练哪些矩阵？W0 会更新吗？`
2. 点击证据卡片跳回相应 PDF 页，确认它确实回答了问题。例题应重点检查 PDF 第 4 页；**不要只因为页面显示引用就认为答案正确**。
3. 确认检索到合适证据后，点击“生成带引用回答”。同一问题、检索方式与范围下，系统会复用你刚核对的那批证据，不会暗中换片段；若 PDF、设置或短期快照已变化，页面会提示重新检索。回答会区分结论、解释、不确定性，引用可跳回原文。**复用同一证据不代表证据足够**；证据不合适时应缩小问题、指定章节或改用选区提问。
4. 关键词检索适合英文术语、缩写与精确名称；语义／混合检索适合中文问英文论文，但依赖本机已缓存的 Embedding 模型。模型未准备好时页面会及时提示；切到“关键词检索”仍可继续，也可以选中原文后直接提问。普通搜索不会偷偷联网下载模型。
5. 选中 PDF 中的一段原文，还可从选区操作直接提问、解释或翻译。选区会保留原文页码，适合核查某个具体段落。

若希望启用语义／混合检索且本机未缓存模型，可在**能访问 Hugging Face 的网络环境**中，于项目根目录单独运行一次：

```bash
uv run python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('intfloat/multilingual-e5-small', revision='614241f622f53c4eeff9890bdc4f31cfecc418b3')"
```

这是一次性、**主动**准备 [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) 的固定修订，不是在下载 DeepSeek。它把中文问题和英文论文片段变成可比较的向量；DeepSeek API 则负责生成回答／译文。模型下载不是阅读 PDF 的前提；模型、缓存和索引都只留在本机，不经 Git 同步。在同一次服务运行中，重复检索同一篇论文会复用已算过的片段向量；重启会重新计算，但不会重新下载。模型下载失败时先用关键词或选区，不要反复点击等待。

## 5. 把回答变成自己的阅读笔记

1. 成功问答后到当前论文的“笔记”标签页。新记录起初只是 **AI 草稿**。
2. 对照引用页，填写你自己的理解，并选择“方法／实验／局限”等类别；发现引用不匹配或理解不确定时不要确认。
3. 点击“核对完成，确认这条记录”。这一步只改变本机阅读记录，**不会自动写入 Obsidian**。
4. 若确认值得长期保存，再点击该记录的 Obsidian 预览，检查目标路径、原文页码、个人理解以及 Markdown 内容，最后点击“保存到 Obsidian”。预览后如果原记录、PDF 或 Vault 变了，保存会被拒绝，需要重新预览。

每篇论文的阅读历史与会话分开保存；切换论文不会把不同论文的提问混在同一张正式卡里。这里的人工确认应基于你实际读懂并核对过的内容；测试流程不会替你确认或保存到你的真实 Vault。

## 6. 连接 Obsidian、建立论文目录与正式论文卡

1. 在 Obsidian 中创建一个独立 Vault，例如 `ResearchCopilot-Vault`。不要把 Vault 建在源代码项目内。Obsidian Vault 是普通 Markdown 文件夹；没有 Obsidian 也能阅读论文。
2. 在网页左侧展开“Obsidian 知识库”，输入 **Vault 文件夹完整路径**，点击“连接并检查”。连接时校验现有 `Sources/`、`Papers/`、`Notes/` 文件；格式问题会显示出来，不会被悄悄改写。
3. 点击“预览论文目录入库”，核对将创建的来源文件，再点击确认。当前已导入的论文会分别成为 `Sources/<paper_uid>.md`，并创建 `ResearchCopilot 论文库.base`。在 Obsidian 左侧打开这个 Base，就能按阅读状态、页数和语言查看论文。新增 PDF 后再次预览、确认即可补入；已存在的来源文件不会被覆盖，阅读状态可直接在 Obsidian 中修改。
4. `Sources/` **只是论文目录**：保存文件名、稳定身份、PDF 指纹和页数，不自动生成摘要、论文观点或正式知识。PDF 原件仍在 ResearchCopilot 的 `data/raw/`，不会复制进 Vault；换设备时只有 Vault 不能直接打开原 PDF，需要在那台设备重新导入对应文件。
5. 先按第 5 节保存至少一条你亲自确认过、带原文页码的笔记。正式笔记位于 Vault 的 `Notes/`。打开该论文右侧“总结”，点击“预览正式论文卡”，核查后点击保存。`Papers/` 中的卡片只索引已保存笔记，不复制 AI 回答，也不会覆盖同名文件。
6. 在 Obsidian 修改笔记后，回到“总结”点击“重新读取”，即可查看 Vault 当前 Markdown。网页回读是只读的，不会用旧缓存覆盖外部编辑，也不会把个人笔记自动发送给模型。

**特别提醒：**“确认记录”和“保存到 Obsidian”是两次不同的人工决定。不要为了完成流程而把未经核对的 AI 内容当作你的笔记。

## 7. 数据、备份与隐私

- 原始论文：`data/raw/`；抽取文本／索引：`data/processed/` 等本机目录；未入库阅读记录：`artifacts/reading_history/`；默认论文身份映射：`data/.research_copilot/paper_identities/`（自定义论文目录在其相邻的 `.research_copilot/paper_identities/`）；论文目录与正式知识：你选定的 Obsidian Vault 中不同文件夹。
- `.env` 里的 API Key 只留本机，不要截图、提交或发给别人。回答只发送问题和少量命中证据；整页翻译只发送被点击的那一页可抽取文字。
- **Git 只同步源代码和文档**。PDF、Vault、密钥、模型、虚拟环境和索引不自动随 Git 同步。Obsidian Sync 也不是独立备份。具体保护范围见[备份与恢复说明](VAULT_BACKUP_RECOVERY.md)。

## 8. 常见问题

| 现象 | 先做什么 |
| --- | --- |
| 浏览器无法连接／显示空白 | 确认启动终端仍在运行；打开它打印的完整地址；关闭旧版服务标签页。代理／VPN 应让 `127.0.0.1` 绕过代理。 |
| 左侧没有论文 | 点击“+ 导入 PDF”；如果仍无内容，检查页面是否显示服务错误，不要把错误当成空资料库。 |
| 语义或混合检索提示模型未缓存 | 先切换关键词检索，或选中原文提问；需要时再按第 4 节单独准备本地模型。 |
| DeepSeek 无法回答或译文失败 | 检查本机 `.env` 的 Key、额度及网络；缩小问题或选区。未完成或格式不合格的模型输出不会作为可靠回答保存。 |
| 页码与论文印刷页码不一致 | 这里使用 PDF 文件页，从 1 开始；请以阅读器中对应的实际页面核对。 |
| 公式、表格或双栏看起来不对 | 回到原 PDF；整页质量提示为风险页时改用较短选区。扫描 PDF 目前不能自动 OCR。 |
| 不能建立论文卡 | 先保存至少一条属于这篇论文的已确认笔记；已有卡片不会被自动覆盖。 |
| Obsidian 打开后没有论文 | 确认连接的是当前 Vault，在网页左侧预览并确认“论文目录入库”；在 Obsidian 左侧打开 `ResearchCopilot 论文库.base`。来源目录与正式论文卡是两类文件。 |
| Obsidian 保存提示预览过期 | 重新读取 Vault 状态并重新预览；别用旧预览覆盖你或其他设备刚修改的文件。 |

## 当前能力边界

这是单人、本地优先的论文阅读工具，不是论文内容的事实裁判。整篇一键精确对齐翻译、通用公式／表格恢复、扫描件 OCR、可信的跨论文比较答案，以及 Windows 自动复现实验尚未达到可交付标准。先把“一篇论文读懂、证据可回查、自己的理解可入库”用稳，再扩展其他能力。
