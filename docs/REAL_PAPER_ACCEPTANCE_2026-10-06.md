# 一篇真实论文的阅读流程验收

日期：2026-10-06。论文：[Hu 等，LoRA: Low-Rank Adaptation of Large Language Models，arXiv:2106.09685v2](https://arxiv.org/abs/2106.09685)。本报告区分真实 PDF／真实 API、隔离测试数据与尚未进行的用户人工验收。

## 样本与范围

- 从 arXiv 获取修订版 v2 的 PDF，导入本机 `data/raw/lora-hu-2021-v2.pdf`；文件约 1.6 MB，26 个 PDF 文件页，SHA-256：`e9a0d3128767db616085dc0f4e6e455e672e89af823e8ed1282793682787395a`。
- 该 PDF 仅作为本机练习资料，`data/raw/` 被 Git 忽略，不把论文重新发布到仓库。PDF 本身的版权／许可不因导入改变。
- 用 PDF 渲染核对第 1、2、4 页：第 4 页包含 4.1 节及 LoRA 的低秩更新公式；原 PDF 文件页码是系统引用基准。

## 修复与回归

1. 缺失本地 Embedding 模型时，语义／混合检索改为明确的 503 提示；常规提问不会因 Hugging Face 重试而长时间卡住，关键词检索仍可用。
2. 真实 DeepSeek 问答明确关闭隐藏推理以把输出预算留给结构化回答；`incomplete` 或 `failed` 响应失败关闭，不把空／截断结果当成答案。
3. 阅读路线只取每类首个正文匹配章节，不把 LoRA 附录中的同类标题重复变成入门任务。
4. 设备本地的 `data/.research_copilot/` 身份映射加入 Git 忽略，避免自定义论文目录的状态被误提交。

当前完整后端回归：`181 passed`（另有两个第三方依赖弃用警告）；前端 TypeScript 检查和生产构建通过。构建器提示主 JS 包较大，这不阻止本次流程，但属于后续性能优化点。

## 尚未通过的成品门槛

- 不能把隔离 Vault 测试等同于用户本人已读懂论文。需要用户在 Safari 打开本机服务，核对 LoRA 第 4 页，写自己的理解，再亲自预览并决定是否保存到真实 Obsidian Vault。
- 宽泛问题可能找到次要证据，复杂页译文可能遗漏数学或排版信息。用具体章节／术语搜索、点击引用回到 PDF，并以原文为准。
- 本轮没有开展 Windows 复现实验或跨设备同步，也没有验证整篇一键翻译、OCR、表格／公式通用恢复。

日常操作见[使用说明书](USER_GUIDE.md)。

## 后续体验修复（同日）

- 固定本地 `multilingual-e5-small` 的修订版本，检索默认只读已缓存模型；命令行与离线评测也不在用户未明确准备模型时悄悄下载。Mac 上验证固定修订能离线加载。
- 同一服务运行期间复用相同问题和相同论文片段的向量，缓存有上限且按文本内容区分；换 PDF 或内容变化时不会复用旧向量。LoRA 两个连续的不同问题实测约 5.48 秒与 0.01 秒（仅为这台 Mac 的一次测量，不是性能承诺）。
