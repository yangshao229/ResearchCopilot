# ResearchCopilot 成品化路线与减法约束

日期：2026-10-05。依据：[产品蓝图](PRODUCT_BLUEPRINT.md)、[Obsidian 知识库蓝图](OBSIDIAN_KNOWLEDGE_VAULT_BLUEPRINT.md)、[本轮开源拆解](research/2026-10-05-vault-paper-index.md)。此处“成品”指单人本地读 AI 论文的可靠闭环，不指上线云平台或覆盖所有 PDF 类型。

## 一个闭环，而不是功能堆叠

```text
导入 PDF → 在原文中阅读／选区翻译／带页码提问 → 核对证据
        → 写自己的理解并确认 → 预览、入库 Obsidian
        → 一篇论文一张索引卡 → 回到原文继续读
```

原始 PDF 是论文事实权威；Vault Markdown 是人工知识权威；应用本地 JSON 只留运行中草稿、会话、检索索引和重建缓存。AI 回答和译文默认是辅助内容，不因“生成成功”自动成为已确认知识。Windows 复现实验暂不纳入成品门槛。

## 现有架构审计

- 领域对象、检索、阅读记录、PDF、Vault 已分层，勿再引入知识图谱、SQL 或第二套卡片模型。
- 集中式 `web_app.py` 约 1000 行、`AssistantPanel.tsx` 约 1000 行、样式约 2200 行，是后续维护风险。新增业务逻辑优先放入已有服务，HTTP 路由只做输入输出；前端新增流程优先复用现有“笔记／总结”界面，不复制整套状态管理。
- 旧 `artifacts/paper_cards/` 与 Vault 正式卡存在双权威风险：保留旧 API 兼容和可下载文件，但停止将旧导出呈现为正式入库。未来迁移需逐项人工选择。
- `paper_uid + pdf_sha256 + PDF 文件页码` 是唯一跨设备身份和证据协议；文件名、UI 当前页、译文或 DOI 均不得替代。
- 本轮工作树含未提交的多阶段改动，不批量重排或混合提交；先确保可测试和可恢复。

## 完成顺序与退出门槛

| 阶段 | 最小交付 | 退出门槛 |
| --- | --- | --- |
| V2b 正式论文索引 | 已保存笔记生成可预览、不可覆盖的论文卡 | 同论文链接、稳定身份、失败关闭、无 AI 自动入库。 |
| V3 回读与冲突 | 已完成只读回读：阅读器可查看 Vault 中已确认的卡片和笔记，外部编辑可见；未来更新必须另做版本检查 | Obsidian 修改后重新读取即反映；绝不以旧缓存覆盖。 |
| V4a 来源目录 | 已完成：预览后把本机 PDF 元数据建为 `Sources/` 与 Obsidian Bases 表格 | 能找到已导入的待读论文；不复制 PDF、AI 草稿或知识正文。 |
| V4 后续组织 | 只在人工确认记录足够时加待解问题与主题视图 | 能找到未解决问题；不复制知识正文。 |
| 可用性收尾 | 数据备份、首次启动、空资料库、API 失败与版本提醒、窄屏／Safari 基础兼容已完成 | 不依赖 Codex 权限即可启动；一篇真实论文完整流程通过本机 Safari 人工验收。 |
| 双设备准备 | 源码与 Vault 分别同步，Windows 本地重建环境和 PDF 配对 | 无密钥／索引同步；缺 PDF 和冲突有明确提示。暂不实施远程复现。 |
| 开源自测版 | Apache-2.0 许可、从干净源码启动的 Mac/Windows 指南、匿名反馈模板与发布前隐私检查 | 外部测试者可在本机运行，不要求 Codex；本版仅单人回环地址访问，不宣称可直接公网部署。详见[开源拆解](research/2026-10-12-self-hosted-beta.md)。 |

每一阶段先执行[开源产品拆解协议](OPEN_SOURCE_RESEARCH_PROTOCOL.md)，固定可观察的验收条件再编码。新增能力必须复用八类核心对象；若确有新模型，先证明现有模型不能承载。先删掉重复入口、状态和写入路径，再考虑新增按钮。回归测试至少覆盖单篇／跨篇、原文／译文、多会话、本地／云端、macOS／Windows 路径及失败场景。

## 本轮边界

V2b、V3 只读回读、M8.U1–U3 可用性收尾与 V4a 来源目录已完成。2026-10-06 已用 LoRA 原论文跑通真实 PDF 导入、页面浏览、检索、DeepSeek 问答、逐页翻译，并用隔离 Vault 验证了确认笔记、预览保存、索引卡、外部回读与防覆盖；详见[真实论文流程验收](REAL_PAPER_ACCEPTANCE_2026-10-06.md)。2026-10-09 用户真实 Vault 已有 4 篇 PDF 的来源元数据和 Bases 表格，但仍没有由用户核对、确认并保存的正式知识笔记；来源目录不代表研究结论。下一步需用户决定哪些理解值得正式入库。网页更新必须另立带文件版本校验与差异预览的里程碑。
