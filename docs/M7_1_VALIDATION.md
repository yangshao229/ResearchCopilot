# M7.1 逐页解析质量关卡验收

日期：2026-09-29。设计依据：[开源产品拆解](research/2026-09-29-page-extraction-quality.md)。

## 结果

- 空白页、明显损坏字符和超过单页安全长度的文字被标记为不可翻译；服务端也在发起 DeepSeek 请求前拒绝，不能只靠按钮禁用。
- 文字很少的页面仅提示人工复核，仍允许用户判断后尝试；检测到数学符号的页面提醒检查原 PDF 的行内公式和上下标。
- 只读质量 API 返回页码、字符数、状态和原因；不存在的论文返回 404，无效页码返回 422。不同论文仍按既有 `paper_id` 隔离；质量检查不调用模型、不写缓存。
- 真实 `data/raw/sample.pdf` 共 15 页；第 5 页实际渲染与原 PDF 视觉对照后，抽取 3181 字符，报告为 `review / math_review`。第 11 页抽取 3216 字符；本阶段不把字符充足等同于阅读顺序正确。
- 完整后端测试：`110 passed`；前端 TypeScript 检查与生产构建通过。未调用真实 DeepSeek API。

## 尚未覆盖

该质量关卡只拦截明显文本层失败，并不能识别所有 PDF 乱码、双栏顺序错误、表格错位、遗漏的行内公式或扫描页 OCR 需求。下一阶段需要可溯源的布局块及真实论文人工对照，不应把 `ready` 理解成“可无条件信任译文”。
