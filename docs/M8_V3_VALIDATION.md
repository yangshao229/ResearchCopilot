# M8.V3：Obsidian 外部编辑只读回读

日期：2026-10-05。依据：[开源产品拆解](research/2026-10-05-vault-external-readback.md)、[成品化路线](PRODUCT_COMPLETION_PLAN.md)与[知识库蓝图](OBSIDIAN_KNOWLEDGE_VAULT_BLUEPRINT.md)。

## 交付

- “总结”页列出当前论文稳定 UID 对应的正式论文卡和阅读笔记；点击后直接从已连接 Vault 读取当前 Markdown，而不是显示保存时的旧预览。
- 返回值包含校验后的相对路径、笔记元数据与当前文件 SHA-256；用户在 Obsidian 外部编辑后重新读取，可看到最新正文和新的内容指纹。
- 浏览器只提交论文 ID 与笔记 UID。服务端从完整 Vault 扫描结果定位文件，不接受绝对路径；跨论文 UID、删除、无效 YAML、重复 UID、符号链接、超限文件或读取期间变化均失败关闭。
- 回读内容明确属于“我的笔记”，不会写回阅读历史、替代 PDF 原文证据、进入模型上下文或触发 DeepSeek。页面以纯文本预览显示 Markdown，不执行其中的 HTML。
- 连续刷新、快速切换论文或在读取途中切换 Vault 时，页面忽略较早请求的迟到结果，避免把旧笔记误显示为当前文件。

## 验证

- `tests/test_obsidian_vault.py` 覆盖保存后读取、外部修改后读取最新字节与新摘要、跨论文拒绝、删除后 404、无效 YAML 和符号链接拒绝；HTTP 端到端覆盖论文卡读取。
- 当前全部后端测试 `177 passed`；仅有既有的两个测试依赖弃用警告。
- 前端 TypeScript 与生产构建通过；仍有既有的大分块提示。
- 测试只读写临时 Vault；未改用户真实 Vault、论文、阅读记录或翻译缓存，也未调用模型。

## 边界与后续

本阶段不提供网页内编辑、自动合并或覆盖。若以后允许从 ResearchCopilot 更新正式笔记，必须以本次返回的 SHA-256 为前置版本并显示差异，再由用户确认。真实 Vault 当前仍为空，因此外部编辑的真实个人笔记闭环要等用户主动保存第一条笔记后再人工验收。

M8.U1–U3 可用性收尾已完成。下一步由用户在本机 Safari 中用一篇真实论文完成全闭环人工验收；M8.V4 只在真实笔记数量足以暴露查找问题后增加轻量组织视图。
