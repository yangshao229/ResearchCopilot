# M8.4q：生成阶段拒答契约与安全修补

日期：2026-10-08—09。状态：**已修复现有问答服务的拒答展示和混合无效引用缺口；真实模型的语义拒答准确率仍未验证**。

按[开源产品与评测拆解](research/2026-10-08-generation-abstention-contract.md)，本轮不继续调检索、重排或相似度阈值，而是检查已经存在的 `insufficient_evidence` 字段是否真正约束用户所见内容。

## 发现的问题

旧服务在模型返回 `insufficient_evidence=true` 时，仍会原样展示模型的 `answer`、`explanation` 和它填入的有效引用编号。离线假模型复现了“自称证据不足，同时断言论文有某结论”的冲突；修复前中英文两例测试均失败。第二个漏洞是引用清单同时包含真实编号与伪造编号时，旧逻辑会静默丢弃伪造编号，仍展示结论；针对性测试先失败后通过。有效引用编号只能证明编号属于当前 `EvidenceSet`，**不能证明该片段支持模型写出的句子**。

## 最小修补

- 自报不足时不再显示模型原始回答、解释或引用；改为明确的安全拒答，保留当前原文证据与 PDF 页码供用户检查。显式英文偏好与默认英文问题显示英文提示，中文问题显示中文提示。
- 选区翻译若模型自报不足，也不显示残缺译文；原选区证据仍保留，现有失败译文不进入缓存的规则不变。
- 空证据、空引用或任一无效引用均使用服务端安全拒答，不再部分接受混合编号；正常且全部引用编号有效的回答不变。拒答继续复用同一个构造函数，减少重复状态组装。
- 对模型的提示补充“自报不足时不要写未经支持的结论”，但安全性依赖服务端约束，而非只依赖提示词。

## 验证、隐私与剩余风险

离线回归覆盖中英提示、默认英文问题、模型同时返回拒答标记与虚构结论、选区翻译失败、API 响应及写入的阅读记录均不含该结论；另覆盖真实与伪造引用混用。最终完整 Python 测试 `218 passed`，前端 TypeScript 与生产构建通过。原有第三方依赖给出 2 条弃用警告，前端仍提示主包较大。本地服务已用最新代码重启并通过 `/api/health` 检查。

**边界非常重要：这只是一条单向安全规则。** 如果模型错误地填 `insufficient_evidence=false`、又引用了一个真实但不支持答案的片段，现有确定性校验仍可能接受；因此不能宣称无答案题已被可靠识别。后续需要冻结人工语义真值，分别记录错误肯定、错误拒答、引用忠实与答案正确，而不能从相似度或 Cross Encoder 分数推断。真实 DeepSeek 输出没有在本轮重新调用或评测；服务提示词更新也不保证真实模型遵守。

只使用测试中的本地假模型；未调用付费 API、联网下载权重、改动论文原文、译文缓存或真实 Obsidian Vault。回答记录仍按现有流程保存，但自报不足的记录只含安全拒答文本，不含原始模型断言。macOS 已运行；Windows 未实机验证。
