# 章节感知检索：开源产品拆解

检索日期：2026-09-25

## 用户问题

读者知道要问“解释 3.2.1 节”或“总结 Results”，但目前问答会在整篇论文检索，可能给出其他章节的内容。需要在保留整篇检索的同时，理解清楚的章节意图，并让用户知道当前证据来自哪个范围。

## 参考项目与一手资料

1. [Docling 官方分块设计](https://github.com/docling-project/docling/blob/main/docs/concepts/chunking.md)：用结构化文档层级生成片段；片段携带标题、图注等上下文；混合分块只在超过 token 限制时细分，并在同标题下适当合并。
2. [Docling 官方标题层级实现](https://github.com/docling-project/docling/blob/main/docling/models/stages/heading_hierarchy/heading_hierarchy_model.py)：标题层级优先采用 PDF 书签，并将编号等信号作为后续推断依据；源代码说明单靠布局检测可能会把所有标题压平。
3. [SkimRead for Zotero 官方仓库](https://github.com/adellife/zotero-skimread)：利用文章章节结构指导全文阅读任务，排除参考文献；长文按章节边界分批处理，并保留暂停和恢复进度；默认显示的结果仍是临时阅读辅助。
4. [PaperQA 官方仓库](https://github.com/Future-House/paper-qa)：把文档搜索、证据收集和回答生成拆开；在答案上下文中使用相关性筛过的证据，并通过文档过滤配置限制允许使用的文档。

## 各项目的成熟做法

- Docling 的重点是结构先于检索：片段基于文档元素生成，并附带标题层级作为上下文。它避免仅从相似度片段反推章节。
- SkimRead 将全文任务按章节边界拆分，让各部分保持语义完整；使用者可以看到当前处理进展，产物不会未经确认写入长期注释。
- PaperQA 将召回与证据筛选分离，强调生成器只读经过收集和相关性检查的证据，并可限制文档范围。

## 对 ResearchCopilot 的取舍

| 决策 | 采用方式 |
| --- | --- |
| 章节来源 | 复用既有 `PaperStructure`，优先 PDF 书签，无书签时使用已有保守标题推断。 |
| 章节页码范围 | 章节从自己的起始 PDF 页开始，到下一个同级或更高级标题的前一页结束；若没有下一个边界，则到 PDF 最后一页。 |
| 章节意图 | 用确定性文本匹配已识别标题；只有唯一且足够明确的匹配才收窄范围。 |
| 检索执行 | 在现有关键词、语义、混合检索之前筛选分页文本；沿用相同切分与排序流程，不复制一套章节 RAG。 |
| 用户可见性 | 回答和证据对象保留解析后的范围信息；检索无命中或匹配不确定时回退全文，并说明范围状态。 |
| 明确范围控制 | `ReadingContext.scope` 是唯一范围来源；默认全文，章节命中后把规范化标题和起止页写入该对象。 |
| 拒绝事项 | 不按 Top-k 片段猜章节；不把章节边界永久硬编码到每种检索器；不因一次模糊标题匹配静默排除论文证据。 |

本轮只借鉴公开设计思想，不复制代码，不增加依赖。Docling 为 MIT；SkimRead 与 PaperQA 的许可证按官方仓库当前声明核对。后续如需复制代码或依赖，须重新检查许可证和平台成本。

## 架构影响与兼容性

- 复用 `ReadingContext.scope` 和 `ReadingAnchor`，不增加第九种核心对象。
- 复用 `PaperDocumentService` 的结构解析缓存；`ReadingService` 负责确定范围；`PaperSearchService` 将范围传到现有检索入口。
- `SearchHit` / `Evidence` 增加章节标题元数据或范围回显，`PaperAnswer` 继续保存证据及回答；历史记录保留问题和真实引用页码。
- HTTP 请求原有 `query`、`mode`、`limit`、`session_id` 均兼容。范围字段可选；旧客户端不传即按全文处理。
- 当前论文范围不改变会话隔离；不同论文继续使用独立 `paper_id`。
- 本地解析章节；外部模型只收到问题和筛选后的片段，不收到整篇 PDF。
- 原文页面和引用页码仍指向原始 PDF。当前只对原文文本做范围限制；未来译文必须继续使用相同页码锚点。
- 用户显式章节意图且无法唯一匹配时，全文回退并标明回退，不能静默给出假章节范围。
- 页码边界可能因 PDF 书签质量或规则推断不准；章节推断质量必须随结果显示，并允许全文重搜。
- 实现保持 Python 3.12 和标准文件处理，macOS/Windows 兼容；不引入额外模型。

## 验收标准

1. “解释 1.1 Motivation”只把 PDF 第 2–3 页（到下一个一级章节前）交给检索；证据保持真实页码。
2. “总结 Results”根据结构解析结果选择唯一对应章节，并在上下文或答复中显示该范围。
3. 未提及章节的问题仍在全文搜索，既有 Recall@5/MRR 行为不变。
4. 不存在或多义章节名不生成虚构页码；改用全文范围并明确回退。
5. 章节范围内无结果时，系统明确报告该范围未命中，并允许/提供全文搜索，而不是以章节内无命中冒充全文无证据。
6. 会话隔离、引用校验、用户确认和 Markdown 导出行为保持不变。

## 实现顺序

1. 为 `ReadingContext.scope` 添加显式来源与回退状态（若验收证明必要）。
2. 从问题中抽取章节名称并对照 `PaperStructure` 解析唯一章节范围。
3. 给现有检索函数增加可选页码过滤，全文默认保持兼容。
4. 把范围信息随证据返回并在 UI 显示；允许从章节限定改为全文搜索。
5. 使用合成 PDF 测试边界，再用至少三篇版式不同的真实 AI 论文验收。

## 暂不实现

- 字体布局或 OCR 驱动的全新复杂解析器。
- 跨章节综合检索、跨论文范围和多论文比较。
- 对无法识别目录的论文执行 AI 猜标题。
- 对章节检索结果自动写入正式笔记。
