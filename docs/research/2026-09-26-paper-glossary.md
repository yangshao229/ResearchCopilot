# M6.5.4 论文级术语表：开源产品拆解

检索日期：2026-09-26。以下仅参考产品行为和数据设计，不复制第三方代码。

## 用户问题

英文 AI 论文中同一术语、缩写常跨段落反复出现。若每次翻译用词不同，读者难以建立稳定概念；若把整份术语表送给模型，又增加费用、噪声和隐私暴露。本步让用户为**当前论文**指定术语译名，翻译时只带上与当前选区/同页上下文匹配的有限条目，并确保改词后不会复用旧译文。

## 对 ResearchCopilot 的取舍

| 决策 | 原因 |
| --- | --- |
| 采用论文级、用户维护的 `source → translation → target_language` 条目 | 每篇论文的术语意义可能不同；不预设跨论文词义，也不把 AI 猜测自动确认为知识。 |
| 采用确定性匹配和数量上限 | 只匹配当前选区及已恢复的同页上下文；英文词使用词边界，短词不匹配长词内部。最多 8 条，优先长词组。无命中不发送术语。 |
| 采用请求前预览 | 侧栏展示本次实际匹配的术语与目标语言；用户手动触发翻译才把术语、选区和有限上下文送至 DeepSeek。 |
| 采用译文缓存绑定术语快照 | 缓存键加入命中术语的稳定摘要；修改或删除相关术语后重新翻译，未命中的其它术语变化不影响缓存。翻译记录保存摘要，旧记录保守失效。 |
| 暂不采用整篇术语自动抽取、CSV、全局内置词库 | 这些需要质量审核、冲突解决和跨论文策略；当前先保证一个可理解、可纠错的阅读闭环。 |

## 架构、数据与隐私边界

新增 `GlossaryEntry` 作为论文级知识产物，文件位于现有本地 `artifacts/` 下，以论文 ID 隔离；它有独立增删生命周期，不能塞进仅表示默认语言设置的 `LanguagePolicy`，也不能冒充 PDF 原文证据或阅读记录。`ReadingService` 仍是统一入口：本地重建选区上下文、匹配术语、检查缓存、再调用现有 `PaperAnswerService`。术语只作为**用户偏好**进入模型提示，不视为论文事实；原文引用仍只能来自 PDF 选区。匹配摘要随 `ReadingRecord` 保存，以便安全复用。API 密钥不进入术语文件或记录。

## 兼容性矩阵

| 组合 | 预期行为 |
| --- | --- |
| 当前论文 / 另一论文 | 术语按论文 ID 隔离；另一篇论文的词不显示也不进入请求。 |
| 同论文不同会话 | 术语属于论文，可跨该论文的会话使用；问答历史和翻译缓存仍按会话隔离。 |
| 原文 / 译文 | 术语只影响译文措辞；PDF 原文、检索索引、页码引用不变。 |
| 中文 / 英文目标 | 每条术语带目标语言；只匹配当前翻译目标的条目。 |
| 本地 / 云端 | 增删和匹配全在本地；显式翻译时只发送命中的术语、选区及有限上下文。 |
| macOS / Windows | 仅使用 Python 标准库、Pydantic、本地 JSON 与浏览器接口，不同步模型或索引。 |
| 无匹配、重复、删除、旧记录 | 无匹配不发送术语；同源同目标语言重复拒绝；删除后相关缓存失效；旧缓存记录不复用。 |

## 实现顺序与验收标准

1. 术语实体与论文级本地存储、API；验证空值、长度、重复和论文隔离。
2. 实现纯函数匹配：大小写、词边界、长词优先、最多 8 条、目标语言过滤；预览返回命中项。
3. 仅翻译任务把命中术语传至现有模型提示；引用仍指 PDF；术语快照进入翻译缓存键。
4. 侧栏允许手动增删并展示当次命中术语；不自动调用模型。
5. 自动测试覆盖上述路径和修改/删除后缓存失效；用真实 `sample.pdf` 验证一个术语匹配。完整后端测试、前端构建通过；真实 DeepSeek 调用不作为离线验收前提。

暂不实现整篇 PDF 术语自动抽取、跨论文共享词库、CSV 批量导入、词义自动审核、正文高亮或双语整篇视图。
