# M7.4b 有横线的表格页安全翻译：开源论文阅读产品拆解

检索日期：2026-09-30。此记录先于功能编码完成。

## 用户问题

真实 `sample.pdf` 第 6 页的表 1 有四列：层类型、每层复杂度、顺序操作数和最大路径长度。现有页级纯文本把各行的列值串在一起，数学上下标也变形。直接翻译这些字符可能让读者误以为行列关系和公式已经得到正确重建。目标是在仍可翻译周围正文的同时，把**可唯一定位、有横线的表格**保留为同页原图，并明确告知用户表内内容尚无译文。

## 各项目的成熟做法

- **交互**：表格不是普通段落；用户应能看到原 PDF 图形，不能把未验证的字符串呈现成看似可靠的表格译文。
- **数据**：表格需要独立类型、来源页码与边框。标题说明、单元格结构和相邻正文不可混作一个字符串。
- **模型与检索**：只有检测并验证单元格结构后，才可翻译每个单元格；本阶段不让 LLM 由线性文本推测列关系。检索仍使用既有原文页码，不把本阶段的图像当新索引来源。
- **引用**：原图裁剪与其原文页码绑定，不另建一套页码或笔记实体。
- **隐私与失败**：裁剪由浏览器从本地 PDF 渲染，不上传图片。表格定位或文本范围不唯一时维持原有文本并显示“版面未验证”风险，不假装已完成表格保护。

## 对 ResearchCopilot 的取舍

| 方案 | 决定 | 原因 |
| --- | --- | --- |
| 对有三条平行横线、文字范围可唯一定位的简单表格，以原 PDF 裁图占位；正文照常翻译 | 本阶段采用 | 能修复真实第 6 页的误导性表格线性化，不需要新模型。 |
| 把所有检测到的表格线直接转换为 Markdown 表格 | 拒绝 | 横线本身不足以确定列标题、跨列单元格和数学表达。 |
| 把整页表格页全部挡在翻译之外 | 拒绝 | 会连同可读的相邻正文一起牺牲，妨碍读论文。 |
| 现在集成完整布局模型或 VLM | 暂缓 | 先建立真实样本和失败样本的门槛，再判断资源、许可证和跨设备成本。 |

## 架构影响与兼容性

复用现有页级译文、原 PDF 裁剪、占位符校验、`PageLayout` 风险提示和翻译缓存；新增与公式区别的 `TableRegion`，只保存标记、页码和 PDF 坐标。不新增数据库、索引、会话体系或额外云调用。算法变化更新译文缓存版本，旧缓存不删除。

| 场景 | 要求 |
| --- | --- |
| 当前论文 / 换论文 | 表格区域仅来自当前论文当前页；缓存仍按论文 ID、页码和原文版本区分。 |
| 原文 / 译文 | 原 PDF 完全不变；译文保留周围正文，把明确检测的表格替换为同页原图并标注未翻译。 |
| 不同会话 | 页面译文与会话无关，问答/笔记会话仍隔离；不从表格裁图生成伪证据。 |
| 本地 / 云端 | 本地确认表格位置；表格单元文字和图像不发送给 DeepSeek，周围正文仍按用户点击按需发送。 |
| macOS / Windows | 复用已存在的 Python PDF 库和浏览器 PDF.js，不下载模型或调用系统特有程序。 |

## 实现顺序与验收标准

1. 原图核对第 6 页表格边界，以及文字层首尾行和周围正文；仅接受可唯一匹配的范围。
2. 在模型请求前替换该表格的线性化文字为独立占位符；模型必须恰好保留该标记，否则拒绝保存。
3. 译文右侧从本地原 PDF 裁出表格，显示“原文表格，尚未翻译”，其余正文照常出现。
4. 测试真实第 6 页的表格去除和正文保留；测试无横线、不唯一、标记丢失或重复时安全回退/拒绝。
5. 全量 Python 测试、前端构建与浏览器验收通过；不因原图裁剪额外调用 DeepSeek。

## 暂不实现的内容

不提取单元格值、不自动翻译表内公式、不处理无横线表格或跨页表格，不将表格识别结果用于问答/检索，不宣称双栏阅读顺序或行内公式已验证。下一步若要翻译单元格，必须先定义行列结构的独立评测集。
