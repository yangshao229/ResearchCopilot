# M6.5.6 中英文界面消息表与切换：开源产品拆解

检索日期：2026-09-28。只借鉴交互、消息组织和测试方法，不复制第三方代码。

## 用户问题

ResearchCopilot 已经把论文原文语言、回答语言、翻译目标和术语策略分开，但当前网页界面仍以中文字符串散落在多个 React 组件中。英语使用者无法完整切换界面；开发者新增按钮或错误状态时也容易漏掉另一种语言。界面语言如果误放进论文级 `LanguagePolicy`，还可能改变模型回答、译文缓存或论文数据。

本阶段解决的是浏览器界面的可读性和一致性：用户应能即时切换简体中文或 English，刷新后保留选择；切换只改变按钮、标签、状态、无障碍文本和前端错误提示，不改变论文原文、提问、回答、翻译、术语、会话或已保存记录。

## 参考项目与一手资料

| 项目 | 一手资料与成熟做法 | 许可证与借鉴边界 |
| --- | --- | --- |
| [Marginalia](https://github.com/EurFelux/marginalia) | 本地优先的 PDF/ePub AI 阅读器，官方 README 明确提供 English/简体中文界面并跟随系统语言。其 [package.json](https://raw.githubusercontent.com/EurFelux/marginalia/main/package.json) 使用 `i18next`/`react-i18next`，并提供 `i18n:extract`、`i18n:lint`、`i18n:status`，说明完整性检查应成为构建流程的一部分，而不是仅靠人工查找。 | GPL-3.0-or-later。只借鉴“系统默认 + 消息目录 + 自动检查”的产品思想，不复制代码或资源。 |
| [Spindle](https://github.com/fukuyori/Spindle) | 官方 README 提供 Automatic/日本語/English 三种 UI 语言选择；界面语言与翻译目标、原文/双语/译文模式、按目标语言隔离的翻译缓存互相独立。它使用 Qt Linguist 编译 UI catalog，并在源字符串变化后刷新目录。 | Apache-2.0。只借鉴“UI 语言是应用偏好而非文档属性”和“目录由工具检查”的结构，不引入 Qt 代码。 |
| [JabRef Localization](https://devdocs.jabref.org/code-howtos/localization.html) | 文献管理器要求所有用户可见标签、说明和消息进入 ResourceBundle；参数化消息使用占位符而不是字符串拼接；`LocalizationConsistencyTest` 检查缺失键和废弃键。英文目录是键的权威来源，其他语言保持同一键集合。 | GPL-3.0。只借鉴消息键、占位符和一致性测试方法，不复制翻译或 Java 实现。 |

这三个项目共同说明：论文或书籍内容的语言不能代替界面语言；界面文字必须有单一目录；语言目录是否完整需要机器检查；动态数字、页码、论文名等通过占位符插入，不能在组件里拼接两套句子。

## 各项目的成熟做法

### 交互流程

1. 首次访问时按浏览器/系统语言选择中文或英文；无法识别时采用稳定默认语言。
2. 页面上提供始终可见的语言选择器，切换即时生效，不要求刷新。
3. 用户显式选择保存在浏览器本地；再次打开页面时优先使用已保存值。
4. 切换界面语言不触发论文 API、模型调用、重新检索或译文缓存失效。

### 消息与状态结构

- 使用一组稳定、语义化的扁平消息键；中文和英文目录包含完全相同的键。
- 动态值通过命名占位符插入，覆盖篇数、页码、记录数、会话名和术语名。
- React 组件只消费 `t(key, params)`，不直接决定当前语言。
- 日期按界面语言格式化；论文原文、用户输入、模型回答和 Markdown 内容保持原样。

### 隐私与失败处理

- 界面语言只存在浏览器 `localStorage`，不写入论文或阅读记录，也不发送给后端和模型。
- `localStorage` 值损坏、缺失或不受支持时回退到浏览器语言；非中文浏览器使用英文。
- 英文界面遇到中文后端诊断时显示本地化的操作级错误，不把中文内部消息误当英文 UI；中文界面仍可显示后端提供的具体诊断。
- 消息目录缺键在测试中失败；运行时仍回退到中文基准目录，避免空白按钮。

## 对 ResearchCopilot 的取舍

| 决策 | 理由 |
| --- | --- |
| 增加轻量 `I18nProvider`、`useI18n` 和两个 JSON 消息目录，不引入第三方 i18n 依赖 | 当前只有两种语言、没有复杂复数规则；先保持实现透明，等语言数量或复数需求增长后再评估 i18next。 |
| `zh-CN` 目录是键集合的权威来源，英文目录必须一一对应 | 现有界面以中文为基线；与 JabRef 的单一权威目录和一致性测试思想一致。 |
| 界面偏好使用独立键 `research-copilot:ui-language` | 它属于浏览器使用者，不属于任何论文、会话或 `LanguagePolicy`。 |
| 首次访问中文浏览器使用中文，其余浏览器使用英文；用户选择后覆盖自动判断 | 对当前中英文范围可预测，同时满足跨平台浏览器。 |
| 所有前端拥有的标题、按钮、帮助、状态、占位符、ARIA、加载和错误回退进入消息表 | 避免视觉界面已翻译但屏幕阅读器或失败状态仍混用中文。 |
| 论文标题、PDF 原文、用户问题、会话标题、模型回答、阅读记录、卡片 Markdown 和后端生成的研究内容保持原样 | 这些是内容或模型任务，不是界面外壳；翻译它们会破坏可追溯性，并可能改变“跟随提问语言”的回答行为。 |
| 选区快捷动作继续生成由“回答语言”约束的任务提示，不随 UI 语言切换 | 界面语言必须与模型任务独立。按钮可显示 English，但不应因为界面切换就改变保存的问题或回答语言。 |
| 不复制 Marginalia、Spindle 或 JabRef 的实现和翻译 | 许可证不同且技术栈不同；本项目自行实现最小消息层。 |

## 数据与隐私边界

新增状态只有一个浏览器本地字符串：`zh-CN` 或 `en`。它不进入 Python API、`ReadingContext`、`LanguagePolicy`、论文 JSON、阅读历史、翻译缓存或术语表。切换语言不发网络请求，也不读取 PDF。现有 API 错误的技术细节仍只用于诊断；英文界面优先显示本地化的操作级错误，避免混合语言。

## 架构影响与兼容性矩阵

不增加第九种领域核心对象。新增的是纯前端横切层：消息目录负责字符串，Provider 负责当前界面语言和持久化，现有 `App`、`PdfReader`、`AssistantPanel`、`GlossaryManager`、各 Assistant View 仅消费翻译函数。

| 情况 | 预期 |
| --- | --- |
| 当前论文/另一论文 | 同一浏览器界面语言保持一致；不按论文保存。 |
| 英文/中文/混排/未知原文 | 只改变界面标签；原文判断与人工覆写不变。 |
| 中文/英文回答与翻译目标 | UI 可与回答、译文同语言或不同语言，互不自动联动。 |
| 不同阅读会话 | 会话标题和历史内容不翻译，界面控件统一切换。 |
| 本地/云端模型 | 切换 UI 不调用任何模型，也不改变发送数据。 |
| 刷新/损坏偏好 | 有效选择恢复；无效值安全回退到浏览器语言。 |
| macOS/Windows | 只依赖标准浏览器语言和 `localStorage`，无系统原生依赖。 |
| 缺失翻译键 | 自动测试失败；运行时回退中文基准字符串。 |

## 实现顺序

1. 建立中英文 JSON 消息目录、类型安全翻译函数、浏览器语言选择与持久化 Provider。
2. 在顶栏加入语言选择器，并让文档 `lang` 属性与当前界面语言同步。
3. 迁移所有 React 组件中的用户可见文字、ARIA、加载/错误回退和动态计数。
4. 对 API 错误增加按当前 UI 语言选择的安全回退；不改变后端论文/模型内容。
5. 增加目录键一致性、非空值、关键界面覆盖和偏好逻辑测试。
6. 运行完整 Python 测试和前端构建，再用真实页面验证切换、刷新和语言独立性。

## 验收标准

1. 顶栏可在简体中文和 English 间即时切换，刷新后保留选择；无效本地值不会导致白屏。
2. 资料库、PDF 工具栏、助手六个标签页、问答表单、选区操作、术语表、记录、卡片和信息页的用户可见 UI 均切换语言。
3. 按钮、输入框、导航的 `aria-label` 和加载/空状态/失败状态同步切换。
4. 中英文目录键集合完全一致、值非空，动态占位符集合一致；测试能在缺键或占位符漂移时失败。
5. 切换 UI 后，论文级 `LanguagePolicy`、问题内容、回答语言、翻译目标、术语表、PDF 页码、会话和历史记录不变化；不产生 API 请求。
6. 完整 Python 测试通过，`npm --prefix web run build` 通过。
7. 真实页面在中文和英文下完成一次目录浏览、证据页、设置区和术语区检查；窄屏布局没有因英文文案明显溢出。

失败场景：把 `localStorage` 中的界面语言改为未知值后刷新，页面必须按浏览器语言或中文基线正常启动；删除英文目录中的任一键后，一致性测试必须失败。

## 暂不实现的内容

- 除简体中文和英文之外的语言、在线翻译平台或社区翻译工作流。
- 自动翻译论文原文、用户笔记、模型回答、会话标题或 Markdown 卡片。
- 由 UI 语言自动修改回答语言、翻译目标、原文判断或术语策略。
- 服务端按 `Accept-Language` 返回本地化研究内容；后续只有出现多客户端共享需求时再评估结构化消息码。
