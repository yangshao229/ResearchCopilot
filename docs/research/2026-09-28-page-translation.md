# M6.6 当前页论文翻译：开源产品拆解

调研日期：2026-09-28。只借鉴产品流程，不复制第三方代码。

## 要解决的实际问题

目前只有“划词后翻译选区”。用户的主要目标是在阅读英文论文 PDF 时，直接在同一页面看到中文译文并随时核对原文。界面语言切换不等于论文翻译，不能替代这一能力。

## 一手开源项目

| 项目 | 已验证的做法 | 取舍 |
| --- | --- | --- |
| [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next) | 面向科研 PDF 的全文双语翻译，强调保留公式、图表、目录和原排版，支持多种翻译服务。 | 其完整 PDF 重排依赖布局解析；本阶段不声称能完成相同质量，也不复制 AGPL 代码。 |
| [VReader](https://github.com/lllyys/vreader) | 原文与译文并排/逐段对照，译文缓存，允许按书与章节重译，并显示失败时保留原文的恢复路径。 | 借鉴“原文始终可见、按需翻译、缓存与重译”；不直接引入其移动端代码。 |
| [Spindle](https://github.com/fukuyori/Spindle) | 原文/双语/译文模式分开，选择翻译与章节翻译并存；缓存按书与目标语言隔离，术语表只注入命中项。 | EPUB 结构比 PDF 可靠；本阶段先以 PDF 原生页码为锚点，不伪造逐段对齐。 |

## 本项目的最小可用流程

1. 用户在中间阅读原始 PDF；右侧“译文”标签跟随当前 PDF 页。
2. 先读取本地缓存，不触发付费 API；没有缓存时显示“翻译当前页”按钮和数据范围提示。
3. 用户主动点击后，系统仅发送当前页可抽取文本、目标语言及当前页命中的人工术语给 DeepSeek；不发送整篇 PDF。页面过长或没有文本时明确失败，不假装译好了。
4. 译文在右侧按“PDF 第 N 页”展示，PDF 原文始终保留。切换页面后读取对应页的译文；翻译错误不覆盖原文或先前缓存。
5. 用户可主动重译；缓存按论文、页码、原文内容、目标语言、术语策略、命中术语、模型和提示版本失效。

## 架构、数据与隐私边界

- 复用 `Paper`、论文级 `LanguagePolicy` 和人工术语表。新增的 `PageTranslation` 只是页面译文的派生缓存，不是新的领域核心对象，不进入阅读问答记录或已确认论文卡片。
- PDF 原文不修改；当前页译文只做页级对照。双栏、公式、表格、脚注的准确块级对应等待 M7 布局解析。
- 翻译是显式的、可能产生 API 用量的操作；切页、刷新、切换界面语言均不自动调用模型。
- 缓存在 `artifacts/page_translations/`，不随 Git 同步。API Key 留在本地环境变量，不进入浏览器或文件。
- 只发送本页文本，不把用户笔记、其他论文或整篇 PDF 放进翻译请求。

## 验收与失败场景

- `sample.pdf` 页面可显示“翻译当前页”；无 API Key 时显示可理解的错误，不白屏；有缓存时重开无需模型请求。
- 切到另一页不会错配译文，切换论文/目标语言/命中术语/模型后旧译文不误用。
- 扫描页、超长页和空译文有明确状态；翻译失败不写缓存。
- 界面语言可中英切换，但不会改变目标语言或主动发起翻译。
- 完整测试、前端构建和真实页面检查通过；测试不调用真实 DeepSeek。
