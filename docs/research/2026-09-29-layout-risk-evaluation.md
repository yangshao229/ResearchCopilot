# M7.3 阅读顺序与复杂版面风险：开源论文阅读产品拆解

检索日期：2026-09-29。此文先于功能实现记录取舍。

## 用户问题

目前“原文位置”只能指向 PDF 坐标，不能说明列表顺序是否符合阅读顺序。多栏、表格和数学上下标会把文本层切成碎片；若直接把这些区域串起来翻译，容易生成看似流畅但实为错序的中文。用户首先需要知道哪些页必须回到原图核对，产品也需要可重复的质量门槛，才能决定何时做块级双语对照。

## 参考项目与一手资料

| 项目 | 官方资料 | 借鉴点 | 许可与运行成本 |
| --- | --- | --- | --- |
| [Docling](https://github.com/docling-project/docling) | [DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/) | 内容对象的坐标与阅读顺序分开表示；文档树的子项顺序才表达阅读顺序，bbox 本身不表达顺序。 | MIT；完整解析流水线及模型有额外内存/下载成本，本阶段不引入。 |

| [MinerU](https://github.com/opendatalab/MinerU) | [官方仓库](https://github.com/opendatalab/MinerU)、[输出文件说明](https://github.com/opendatalab/MinerU/blob/master/docs/en/reference/output_files.md) | 将多栏、公式、表格解析作为独立能力，导出结构与阅读顺序；页面几何和内容类型都需要保留。 | 有附加条款及较重模型流水线；本阶段只借鉴失败处理思路。 |
| [olmOCR-Bench](https://github.com/allenai/olmocr) | [官方评测实现](https://github.com/allenai/olmocr/blob/main/olmocr/bench/tests.py) | 用独立测试分别核对文本先后、表格单元关系、数学表达，而不是只看“抽到多少字”。 | 代码 Apache-2.0；完整评测数据和 OCR 模型不需下载，本项目只做小型固定样本。 |

## 各项目的成熟做法

- **交互**：保留可见原 PDF，对不确定的页面给出核对提示；结构化文本是阅读辅助，不应掩盖原图。
- **数据**：页码、坐标、内容类型、阅读顺序和置信状态是不同属性。仅有原文框不能自动推出译文框。
- **检索与模型**：复杂页需布局/OCR/表格/数学专门处理；不能让语言模型在原文顺序未知时“补全”布局。
- **引用**：无论页面文字是否可抽取，引用仍应指向原 PDF 页，区域框只辅助核查。
- **隐私与失败**：可先在本地判定风险并提供回退；判断不确定时明确“需要人工核对”，而不是伪造精确段落。

## 对 ResearchCopilot 的取舍

| 方案 | 决定 | 原因 |
| --- | --- | --- |
| 在现有 `PageLayout` 加保守风险信号 | 采用：标注可能的多栏、表格线框、细小字形碎片，且 `order_verified` 仍为 `false`。 | 不建立第二套页面/会话/译文数据；阅读者能知道为何须对照 PDF。 |
| 用固定样本做分项验收 | 采用：合成双栏、普通单栏、真实 `sample.pdf` 第 5 页公式和第 6 页表格。 | 对应成熟评测中顺序、数学、表格分项，且测试可离线重跑。 |
| 只按 y 坐标重排成段落并逐段翻译 | 拒绝。 | 双栏和横跨栏标题会错序，公式、表格也会被错误线性化。 |
| 直接安装完整 Docling/Marker/MinerU | 暂缓。 | 先度量错误类型和用户收益；模型成本、权重许可、Mac/Windows 资源需单独评估。 |

## 架构影响与兼容性矩阵

复用 M7.2 `PageLayout`、现有 PDF.js 阅读器、页级译文和 `ReadingContext`。只在布局响应中增加风险字段，前端译文页签显示提醒；不改变 DeepSeek 请求、检索证据、论文卡片或缓存键。

| 场景 | 预期 |
| --- | --- |
| 当前论文/换论文 | 只读取当前 `paper_id` 的 PDF；换论文清除原高亮。 |
| 原文/译文 | 风险从原 PDF 计算，译文仍按原页码展示；风险不被误作译文质量分数。 |
| 不同会话 | 同一论文页面风险与会话无关；问答记录仍按会话隔离。 |
| 本地/云端 | 风险计算仅在本机；不额外向 DeepSeek 发送内容。 |
| macOS/Windows | 复用已锁定的 Python 3.12 + pdfplumber，无系统专属路径或模型下载。 |

## 实现顺序与验收标准

1. 先做固定样本并记录肉眼真值：普通页、双栏、数学页、带横线表格页。PDF 原图是人工核对标准。
2. `PageLayout` 返回可解释的风险标记，不产生“安全可自动对齐”结论；页码、坐标和现有字段保持兼容。
3. UI 在原文位置附近显示具体风险及“原图为准”；不增加调用模型按钮或新的存储。
4. 自动测试覆盖四类页面和空白/旋转的失败场景；前端构建通过，真实论文页面手动检查。

## 暂不实现

不自动认定双栏阅读顺序、提取表格单元、把行内公式转 LaTeX，也不把区域列表直接变成逐块译文。下一步要根据本轮误差记录，选择轻量局部改进或成熟布局模型，并在有原图核对的样本上设合格门槛。
