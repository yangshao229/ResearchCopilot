# M8.4b 多论文检索策略对照：开源产品拆解

检索日期：2026-10-04。先对照现成策略，再决定产品改动；不复制第三方代码。

## 用户问题

M8.4a 的两篇真实论文、六个固定问题显示：逐页全词匹配的来源及页锚点覆盖仅 `5/9`；中英文自然问句的四个预期来源全部漏检，15 个命中页中有 3 个已知无关页。用户需要的是读懂论文时能找到可信的原文页，而不是看到一段貌似合理的跨论文回答。必须在允许生成比较之前，先测出更合适的检索方式。

本阶段只做离线、可复现的候选策略对照。继续锁定原 PDF 哈希、问题、人工页码真值与每篇最多 3 个结果；不删困难问题，不凭固定答案页写规则。

## 流程与架构取舍

1. 实验复用 M8.4a 的真值账本、`PaperSearchService`、`SearchHit` 与本地 E5 模型。两篇论文分别检索，不建立第二套索引、存储、会话或云端请求。
2. 固定逐页全词匹配为基线；另外试运行项目已有的语义与混合检索，按页去重后取每篇前三个页码。评分仍区分来源覆盖、人工锚点覆盖、已知无关页、明确无证据、范围泄漏。
3. 页码统一为 PDF 文件从 1 开始的页序，保持每条结果的原文及论文身份。译文和阅读卡片不是检索真值来源；不能因翻译好读就替代 PDF 页证据。
4. 若模型本地缓存缺失，候选策略明确报告不可运行；不偷偷联网下载，也不上传论文或调用 DeepSeek。若候选策略引入大量误命中，即使召回提高也不得直接设为用户默认。

| 兼容场景 | 验收要求 |
| --- | --- |
| 当前论文 / 显式多论文 | 单篇检索仍保持原行为；离线比较仅包含用户选择的两篇，逐篇计分。 |
| 英文术语 / 中英文自然问题 | 分开记录，不用平均分掩盖自然问句失败。 |
| 原文 / 译文 | 只检索 PDF 抽取的原文，译文缓存不参与排名。 |
| 不同会话 | 离线评测不读写阅读会话或提问历史。 |
| 本地 / 云端 | E5 仅从本地缓存加载；不调用 DeepSeek。 |
| macOS / Windows | 同一真值账本与 SHA-256；模型未缓存时明确跳过该候选，不给出虚构成绩。 |

## 验收标准与失败场景

- 三种策略使用同一批 PDF、六个问题和每篇三个页结果，输出每题每篇的页码和总体指标。
- 策略比较不改变生产 API 或用户资料；论文缺失、哈希不符、模型不可用时明确失败。
- 必须展示无证据问题是否误命中；如果语义/混合策略对 `quantum entanglement` 返回伪证据，不能只报召回增益。
- 报告说明样本仅两篇、人工锚点并非穷尽相关页，不能推断一般检索准确率。

## 暂不实现

不新增跨论文生成、LLM 查询重写、词典硬编码某个测试问句、OCR、整篇翻译或逐段双语对齐。只有离线结果支持且失败边界清楚时，才另立产品改动里程碑。
