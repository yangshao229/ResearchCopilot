# 检索片段与同页上下文：开源方案拆解

日期：2026-10-08。范围：**先做离线影子实验，不改网页检索或 DeepSeek 输入**。

## 用户问题与本项目反例

阅读 [RAG 原论文 v4](https://arxiv.org/abs/2005.11401) 时，问“RAG-Sequence 的快速解码如何近似彻底解码”。现有混合检索前五含 PDF 第 4 页的第 0 个片段，因此原先的“正确页 Top-5”指标算成功；但真正解释“将未在某文档束搜索中生成的假设概率近似为 0，以免额外前向计算”的正文在同页第 1 个片段。它甚至未进入前 30 个候选。重排前 30 个候选无法补救一个未被召回的片段。

相反，“参数化／非参数化记忆”问题在 PDF 第 1 页摘要就已有完整解释，原真值只标第 2 页，因此这题的页级评测又低估了产品实际得到的证据。两种偏差表明：**页码命中不等于片段足以回答，单一人工页锚点也不一定覆盖全部有效原文。**

## 成熟开源做法

- [LlamaIndex 官方 SentenceWindowNodeParser 示例](https://docs.llamaindex.ai/en/v0.10.22/examples/node_postprocessor/MetadataReplacementDemo/)把可检索的小文本与交给回答模型的相邻文本窗口分开：先以小节点定位，再以邻近上下文补足含义。
- [LlamaIndex 官方生产 RAG 指南](https://docs.llamaindex.ai/en/v0.10.18/optimizing/production_rag.html)把这称为小到大检索的取舍：大块易丢细节，小块又可能不足以合成答案。
- [Haystack 官方 `SentenceWindowRetriever` 源码](https://github.com/deepset-ai/haystack/blob/main/haystack/components/retrievers/sentence_window_retriever.py)要求用 `source_id` 和有序 `split_id` 约束邻居，按原始偏移合并重叠文本，并在缺少必要元数据时失败或显式跳过。该实现说明邻居窗口必须保留来源边界、顺序和可核对的重叠规则，不能只凭检索排名拼接任意文本。
- [LangChain 官方 `ParentDocumentRetriever` 参考](https://reference.langchain.com/python/langchain-classic/retrievers/parent_document_retriever/ParentDocumentRetriever)用小块做检索，再回取较大的父文档；本项目不引入其父文档存储，因为已按 PDF 页保留有序片段。
- [Haystack 官方 `AutoMergingRetriever` 文档](https://docs.haystack.deepset.ai/docs/automergingretriever)展示了另一种有条件的父文档合并：多个叶片段命中才达到合并阈值，而非每次固定扩大所有证据。

检索日期均为 2026-10-08。LlamaIndex 仓库采用 MIT 许可证，Haystack 源码标注 Apache-2.0；本轮只借鉴“检索小片段、展示相邻上下文”和“以来源/顺序元数据约束窗口”的设计思想，**不复制第三方代码、不增加依赖**，因此没有把第三方实现或许可证带入产品。若将来引入任一框架，还须另行核对固定版本的许可证、依赖体积和 Mac/Windows 成本。ResearchCopilot 已有按 PDF 页保存的顺序片段和来源指纹，可直接验证“同一页、相邻一个片段”的窄实验。与通用父子检索相比，本实验不跨页、不跨论文、不自动读取用户 Vault，避免把别处文本接到引用中。

## 对 ResearchCopilot 的取舍

| 决策 | 采用／调整／拒绝 | 理由 |
| --- | --- | --- |
| 小片段负责命中、相邻文本负责补语义 | 采用为离线影子视图 | 直接对应 RAG 快速解码答案被切到同页下一片段的失败例 |
| 以来源 ID 与顺序 ID 限制邻居 | 调整为 `PDF 版本 + 文件页 + chunk_index` | 复用现有来源模型，并进一步禁止跨 PDF 页拼接 |
| 按已知偏移自动合并所有重叠 | 暂不采用 | 当前生产片段只保存固定重叠长度而非绝对字符偏移；影子实验仅删除完全相等的 100 字符边界 |
| 双向固定窗口直接进入生成上下文 | 拒绝 | 单篇论文没有增加覆盖，却把平均文本量提高到约 2.29 倍 |
| 在模型输入中加入用户未见的邻居 | 拒绝 | 会破坏“已查看证据快照”与实际模型上下文一致的安全约束 |
| 为窗口新增父文档数据库／新框架 | 拒绝 | 现有有序片段足够完成验证；额外存储会让来源和版本同步更复杂 |

## 架构影响

复用 `chunk_pages` 的 `source_page + chunk_index + text`、固定 PDF SHA-256、现有混合检索结果和 M8.4j 人工短语账本。新增的 `context_window_evaluation` 只提供纯函数影子视图；脚本只读固定论文并统计覆盖和字符成本。没有修改 `EvidenceSet`、搜索 API、网页、回答服务、会话或持久化。如果以后进入产品，必须先让扩展后的完整窗口成为用户可见、可核对且由快照签名的证据，而不能只在生成阶段暗中扩展。

## 兼容性矩阵

| 组合 | 本轮处理 |
| --- | --- |
| 当前论文／跨论文 | 只允许同一固定 PDF；不跨论文扩展，也不推断跨论文效果 |
| 同页／跨页 | 只取同页相邻 `chunk_index`；页边界处停止 |
| 英文／中文问题 | 两种问法使用同一英文原文短语，分别统计；不自动翻译查询或证据 |
| 原文／译文 | 只读取原文片段；翻译缓存不参与 |
| 不同会话 | 离线脚本不读取会话或历史 |
| 本地／云端 | 仅本机 PDF 与已有 Embedding 缓存；不调用 DeepSeek |
| macOS／Windows | 纯 Python 顺序与字符串逻辑可跨平台；本轮只在 macOS 实测，Windows 未实机验收 |

## 失败场景

- 命中片段文本与当前 PDF 切分不完全相同：拒绝扩展，避免旧缓存或另一版本 PDF 的邻居混入。
- 相邻索引不存在或已跨页：停止扩展，不用别页文本填充窗口。
- 重叠不是精确的 100 字符：保留换行与完整文本，不做模糊裁剪，避免误删。
- 同一事实存在另一处完整表述：人工单页锚点可能低估检索表现，报告必须同时保留短语覆盖限制。
- 无答案题得到更多相关上下文：不得据此判定可回答或可拒答。
- 公式、双栏错序或抽取异常：本轮字符窗口不能证明阅读顺序正确，不能越过既有 PDF 布局关卡。

## 验收标准

- 至少三个官方文档、官方源码或论文来源完成拆解，并记录许可证与是否复制代码。
- 固定 PDF 哈希、真值账本和现有混合检索 Top-5；不通过调参选择结果。
- 测试证明窗口不跨页、精确重叠可去除、过期／改变的命中文本会失败关闭。
- 正例分别报告原片段、向后一个邻居、前后各一个邻居的短语覆盖与字符成本；无答案题返回 `null`，不能冒充拒答。
- 完整 Python 测试和前端生产构建通过；不调用 DeepSeek，不修改论文、阅读记录、翻译缓存或用户 Vault。

## 影子实验与上线门槛

固定现有检索结果和 PDF 版本，只比较原前五片段、每片段向后补一个相邻片段、向前后各补一个相邻片段三种**上下文视图**。同页原文必须保持顺序，重叠 100 字符仅在完全匹配时去除；不重新排序、不增加证据编号、不改变来源页码。记录每题人工指定的答案承载语句是否进入视图，以及五条证据总字符数。中文／英文同义问题和无答案题分别报告；负例不能因为附近有相关术语就被称为可答。

首轮只有一篇新论文、四个概念的片段级人工真值。这只能发现边界缺陷，不足以宣称通用召回提升。第二轮计划用已有 LoRA、Transformer、BERT 三篇论文复测；它们以前参与过模型比较，因此是**旧语料稳健性检查，不是新论文独立测试**。即使窗口能补回个别答案，仍需更多不同版式 PDF 的独立人工标注、双栏／公式安全检查和总 token／延迟预算，才考虑改生产检索。搜索与回答必须继续使用**同一已展示证据快照**，不能只在模型输入里偷偷加入用户未看过的文字。
