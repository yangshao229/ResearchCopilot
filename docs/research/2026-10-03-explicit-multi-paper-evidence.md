# M8.3 显式多论文研究集合与证据聚合评测：开源产品拆解

检索日期：2026-10-03。此记录先于功能代码完成。只借鉴范围、证据和评测设计，不复制第三方实现。

## 用户问题

M8.2 能在资料库中定位原文，但它不是一个稳定的“研究集合”，也没有逐篇说明哪些论文命中、无命中或不可搜索。若直接把若干搜索结果交给模型，用户无法确认系统究竟比较了哪些论文，强势单篇的高分片段还可能挤掉其他论文，形成虚假的“跨论文结论”。M8.3 的最小目标是让用户明确勾选 2–8 篇论文、始终看见当前范围，并只做按论文分组的本地证据聚合与固定评测；不生成答案或主题笔记。

共同结论：跨论文研究必须先固定语料范围；证据节点必须携带论文和位置身份；每篇论文的无命中/不可搜索不能在全局排序中消失；答案生成是证据检索之后的独立阶段，只有评测证明覆盖和隔离可靠后才能开放。

## 各项目的成熟做法

### 交互流程

1. 用户从当前可见资料库逐篇勾选，至少 2 篇、至多 8 篇；界面持续列出论文名和数量。
2. 用户提交研究问题时，确认文字明确写出“只整理证据，不生成答案”。
3. 后端只接受请求中列出的稳定论文 ID，逐篇独立执行本地检索。
4. 返回结果按用户选择顺序分组；每组显示 `matched`、`no_match` 或 `unsearchable`，命中保留真实 PDF 页码与原文片段。
5. 点击证据只打开对应论文页；修改选择会清空旧结果，防止旧证据被误认为新范围。

### 数据结构、检索、引用和失败处理

- 研究集合不新建论文副本，也不修改 M8.1 持久集合；浏览器仅保存所选稳定论文 ID，请求每次完整发送范围。
- 新的聚合响应是 `paper_id + paper_name + status + hits[]`；命中继续复用 M8.2 的本地分页原文、真实一基页码和纯文本片段。
- 每篇论文使用相同上限，避免单篇重复命中挤掉其他论文；不再把所有片段压成一个全局排行榜。
- 未知 ID、少于 2 篇、超过 8 篇和重复后不足 2 篇均拒绝；任何范围错误都不能退化为全库。
- 单篇解析失败标为 `unsearchable` 并保留在响应中；有文本但查询无命中标为 `no_match`；两者不能混淆。
- 不调用模型，因此不存在生成引用；证据编号和论文/页码只供用户核对，并为后续生成阶段提供不可变输入边界。

### 固定评测

- 使用机器可读的合成多论文真值账本，声明每个问题的所选论文、预期命中论文/页码、无命中论文和不可搜索论文。
- 量化：预期来源覆盖率、预期页码召回率、范围泄漏率和状态判定准确率。
- 合成账本只验证聚合、范围和状态逻辑，不代表真实跨论文语义检索准确率；真实多论文结论仍保持关闭。

## 对 ResearchCopilot 的取舍

| 决策 | 理由 |
| --- | --- |
| 当前研究集合保存在浏览器并每次显式随请求发送 | 它是当前任务范围，不是 M8.1 长期组织元数据；服务端不需要另一套集合存储。 |
| 后端要求 2–8 个去重后论文 ID | “跨论文”至少两篇；上限控制本地解析成本和界面可核对性。 |
| 响应按论文分组，不做单一全局 Top-K | 让来源覆盖、无命中和失败状态可见，防止单篇垄断。 |
| 复用 M8.2 的全部词本地匹配 | 先评测范围与聚合，不同时引入语义模型变量。 |
| 只显示证据，不生成比较结论 | 当前没有真实多论文问题集，不能把合成覆盖指标包装成回答质量。 |
| 固定账本锁定问题、范围和预期页码 | 防止通过删难例或扩大范围获得虚高覆盖率。 |

明确拒绝：隐式使用当前全部资料库、自动扩充论文、全局片段竞争、DeepSeek 调用、跨论文答案、主题笔记、引用生成、embedding 下载和把合成账本称为真实研究准确率。

## 数据与隐私边界

研究集合只在当前浏览器 `localStorage` 保存论文 ID；后端不持久化问题或聚合结果。证据检索只读取所选 PDF 和现有/可重建的本地分页缓存，不读取译文、术语表、会话或阅读历史。不会修改论文、翻译缓存、阅读记录、M8.1 集合标签或论文卡片，不访问网络、不调用 DeepSeek。

## 架构影响与兼容性矩阵

新增多论文证据领域模型与只读 `/api/research/evidence`；复用 `PaperLibrary` 的安全 ID→路径解析、`PaperSearchService.search_library_text` 和 M8.2 命中模型。前端仍在资料库面板选择论文，在独立证据区展示分组结果；当前 `AssistantPanel` 继续严格绑定单篇论文。

| 情况 | 预期 |
| --- | --- |
| 当前论文 / 研究集合 | 当前阅读论文可在集合内或外；集合变化不自动切换 PDF，点击证据才切换。 |
| 跨论文 / 单篇问答 | 聚合端点只返回分组证据；单篇 `/answer` 不接收研究集合，也不改变范围。 |
| 原文 / 译文 | 只检索 PDF 原文；不读取或改写译文。 |
| 当前会话 / 其他会话 | 研究集合和证据不进入任何会话或历史。 |
| matched / no_match / unsearchable | 三种状态逐篇保留，不能因全局无结果被折叠。 |
| 本地 / 云端 | 纯本地关键词聚合，不加载 embedding、不调用生成模型。 |
| macOS / Windows | 复用浏览器 localStorage、pathlib、pypdf 与 JSON；无新增系统依赖。 |
| 中文 / 英文界面 | 范围、选择上限、状态、证据和错误进入两套消息表；原文不翻译。 |

## 实现顺序

1. 新增分组证据领域模型和严格范围请求；复用 M8.2 检索逐篇产生三态响应。
2. 新增固定合成真值账本与回归驱动器，计算来源覆盖、页码召回、泄漏和状态准确率。
3. 前端增加研究集合勾选、范围确认、本地证据查询和逐篇结果；选择变化清除旧结果。
4. 补中英文消息、API 回归，运行完整 pytest 与生产构建。
5. 若真实本地论文不足两篇，只做单篇只读锚点，不宣称完成真实跨论文质量验收。

## 验收标准

1. 2–8 篇去重范围被接受；未知、少于 2 篇、超过 8 篇均明确拒绝且不扩大范围。
2. 返回顺序与用户选择一致；每篇均保留 `matched`、`no_match` 或 `unsearchable`，命中带正确论文 ID、真实页码和原文片段。
3. 每篇独立上限生效，一篇高频论文不能挤掉另一篇命中论文。
4. 固定账本的预期来源覆盖率、页码召回率、状态准确率均为 `1.00`，范围泄漏率为 `0.00`；结果明确标记为合成聚合逻辑评测。
5. 页面可明确选择、移除、清空 2–8 篇论文；选择变化清除旧证据；点击证据只定位原文。
6. 完整测试与前端生产构建通过，不调用 DeepSeek，不修改用户论文、阅读记录或翻译缓存。

失败场景：用户只选一篇或请求含不存在论文时返回校验/范围错误；其中一篇损坏时仍返回其他论文证据，并把损坏论文保留为 `unsearchable`，不能静默丢弃。

## 暂不实现的内容

- 跨论文答案、比较表、主题笔记、自动引用、矛盾检测或模型综合。
- 语义/混合跨论文检索、查询分解、重排序、来源质量估计或自动扩展论文范围。
- 服务端研究集合持久化、分享、协作、同步和权限。
