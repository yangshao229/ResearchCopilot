# 候选重排、答案证据和拒答分离：开源方案拆解

日期与官方资料复核日期：2026-10-08。范围：**离线影子比较，不改产品默认问答**。

## 用户问题

三篇论文的旧评测表明，部分必要答案片段在前 30 个候选里，却不在前 5；同页邻居窗口只补回 2/12 个问句，文本量约增加 73%。我们需要验证已有本地重排器是否能把真正含答案的原文排到前五，同时避免把“最相关的一段”误称为“这道题可回答”。

## 参考项目与一手资料

- [Sentence Transformers 官方 Retrieve & Re-rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)与[Cross Encoder 官方文档](https://www.sbert.net/docs/cross_encoder/usage/usage.html)：先快速召回有限候选，再对问题—段落成对评分。评分是候选排序，不是来源真实性或答案可得性的证明。
- [BEIR 官方仓库与评测框架](https://github.com/beir-cellar/beir)：冻结查询、语料和相关性判断，分别比较词法、稠密与重排检索；其官方代码使用多个 K 值，避免只报对自己有利的一题。其 Apache-2.0 项目不被引入本仓库。
- [SQuAD 2.0 原论文](https://aclanthology.org/P18-2124/)：无答案问题刻意与上下文相关，说明模型需要独立判断能否回答，不能以最高相关片段或相似度替代拒答。
- [现有 mMARCO Cross Encoder 官方模型卡](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)：仅用固定修订、已在本机缓存的权重。前期[模型候选拆解](2026-10-06-retrieval-reranker-candidate.md)已记录许可证、体积与跨平台限制。

## 流程与取舍

| 流程 | 成熟方案 | 本轮取舍 |
| --- | --- | --- |
| 用户提问与范围 | 先确定查询对应的语料 | 单篇固定 PDF、固定中英问题；不碰跨论文产品行为 |
| 候选与重排 | 第一阶段召回，第二阶段只重排有限候选 | 复用现有 `hybrid_search_chunks` 和 `rerank_candidates`；不增加模型或新索引 |
| 答案来源 | 相关性真值与答案真值分开 | 用人工冻结的同页必要原文短语统计前五证据；保留页码与片段两个指标 |
| 无答案处理 | 需真实负例与独立拒答判断 | 只检查负例分数是否和正例重叠；绝不以单一分数阈值上线拒答 |
| 用户引用 | 原文可回查 | 此轮不生成答案；未来若上线，用户展示、模型上下文和引用须共用同一 `EvidenceSet` 快照 |
| 失败处理 | 不完整模型／资料不得假装成功 | 本地权重或 PDF 指纹不匹配时退出；任何模型异常不影响正式检索 |

不复制上述项目代码，不增加外部依赖或联网下载。计算只读本机 PDF 和已缓存模型。若未来引入第三方新权重或框架，需要另核许可证、Mac/Windows 内存与延迟、模型版本及文件格式。

## 架构影响与兼容性

只扩展已有离线窗口评测脚本的可选重排分支，复用 PDF 哈希、既有 Top-30 候选、`source_page/chunk_index` 与人工支持短语账本。不新增产品领域对象、API、界面、会话、笔记格式或 Vault 写入。原 Top-5 与重排 Top-5 必须分别取各自真实候选流程，不能因候选池大小变化而偷换基线。

当前论文只用本篇原文；跨论文不借用其他论文文本；中英问题共用英文原文必要事实但分别计数；译文缓存与不同会话均不参与；只在本机离线运行，云端 DeepSeek 不参与；纯 Python 评测应可在 macOS/Windows 运行，但本次只在 Mac 验证。若模型文件缺失，明确失败，不联网获取。

## 验收标准与暂不实现

1. 固定原有 RAG 与 LoRA／Transformer／BERT 问题、PDF SHA-256 和支持短语，原始 Top-5 与 mMARCO 重排 Top-5 分别报告同页答案短语完整数、提升与退化，不能删掉失败题。
2. 在 RAG 的中文／英文无答案题上输出重排最高分与正例区间，明确“分数是否可被一个阈值分开”；这仅是反例诊断，不能宣称可拒答。
3. 记录每题 CPU 重排耗时和总体中位数、前五证据字符量；至少一个测试证明不同页的短语不会拼成完整答案。
4. 本地模型缺失、PDF 或账本不匹配时失败关闭；旧的无重排脚本用法、全量 Python 测试与网页构建保持通过。

不实现自动路由、生成答案、分数阈值拒答、默认重排、额外模型下载、整页塞进提示词或写 Obsidian。若排名收益只来自熟悉旧题且负例风险未解决，保持影子状态。
