# 双语论文阅读基础层：开源产品拆解

检索日期：2026-09-25

## 用户问题

读英文 AI 论文时，界面显示中文、提问用中文、期望的回答语言、原文语言与翻译目标不是一回事。当前选区动作把翻译指令拼进普通问题，DeepSeek 回答又固定为中文；论文切换时也还没有独立保存语言偏好。若把所有状态合并成一个“中英文切换”，会导致界面和回答互相牵连、译文替代原证据，或不同论文的术语偏好串线。

本轮实现边界：先落地“论文级回答/翻译语言偏好 + 每条阅读记录保存实际语言策略 + 回答按明确语言输出”。选区上下文翻译、术语表、缓存和完整界面英文化分后续小步接入同一契约，不在本次一并扩张。

## 参考项目与一手资料

### 1. Zotero Context Translate

- 官方仓库与 README：<https://github.com/maverickzyc/zotero-context-translate>
- 英文工作流说明：<https://github.com/maverickzyc/zotero-context-translate/blob/main/README.en.md>
- 当前许可证：AGPL-3.0-or-later。

成熟做法：选区翻译不是只提交被选中的几个词；系统恢复句子、段落和相邻段落，并且可注入资料库术语表。相同文档、页码和原文可使用翻译缓存；查词、翻译有各自历史。它明确显示发送到模型的上下文与隐私边界。

### 2. Zotero PDF Translate

- 官方仓库与使用文档：<https://github.com/windingwind/zotero-pdf-translate>
- 官方翻译 API 源码：<https://github.com/windingwind/zotero-pdf-translate/blob/main/src/api.ts>
- 当前许可证：AGPL-3.0。

成熟做法：翻译直接从阅读器选区发起，并可加入批注或笔记；原文替换不是默认行为。界面语言与目标语言设置彼此分开，插件 API 也把来源语言和目标语言作为独立参数。

### 3. Open Notebook

- 官方仓库：<https://github.com/lfnovo/open-notebook>
- 用户指南：<https://github.com/lfnovo/open-notebook/blob/main/docs/3-USER-GUIDE/index.md>
- 转换/笔记流程：<https://github.com/lfnovo/open-notebook/blob/main/docs/3-USER-GUIDE/transformations.md>
- 当前许可证：MIT。

成熟做法：来源、对话、笔记和批量转换作为少量稳定对象协作；一次探索性问答与对多份来源执行同一个结构化转换是不同任务。AI 输出仍能保存为用户可检查的笔记，不要求每个动作造一套独立资料格式。

## 成熟流程归纳

```text
当前论文 + 当前会话 + 原文选区/页码
  ↓
明确任务（提问 / 翻译 / 解释）与目标语言
  ↓
只发送必要原文证据及有限上下文
  ↓
结果仍关联原文页码，并保存实际使用的语言策略
  ↓
用户核对后再进入正式论文卡片
```

## 对 ResearchCopilot 的取舍

| 采用或调整 | 本项目决策 |
| --- | --- |
| 采用 | UI 语言、回答语言、翻译目标语言分别设置，不用一个总开关。 |
| 采用 | 论文偏好随论文切换恢复；单次请求可覆盖偏好，且结果记录实际策略。 |
| 调整 | 当前版本继续把原始 PDF 和英文证据作为权威内容；模型结果附带页码，不替换证据面板。 |
| 调整 | 首轮只提供回答语言/翻译目标偏好和记录追踪；选区上下文扩展、缓存与术语管理分别后续实现并评测。 |
| 拒绝 | 不复用 AGPL 项目代码；只采用产品交互与数据流思想。 |
| 拒绝 | 不在 M6.5 提前生成整篇双语 PDF/HTML；布局与区域锚点要等 M7 可靠。 |
| 拒绝 | 不让语言偏好成为论文全局共享状态；论文之间必须隔离。 |

## 架构影响

- 复用既有 `ReadingContext.language`、`PaperAnswer`、`ReadingRecord`、`ReadingHistoryStore` 和本地 JSON 存储。
- 增加的偏好存储是论文资料的本地设置，不新增核心领域对象、会话系统或模型调用链。
- 回答请求可携带语言策略；阅读记录保存策略快照，之后修改偏好不会改写旧记录。
- 检索仍针对原始论文文本；语言策略只影响生成目标，不能把译文混入证据索引。
- 现有记录若缺少语言字段，读取时使用中文默认值，保持旧 JSON 兼容。

## 兼容性矩阵

| 维度 | 本轮应保持的行为 |
| --- | --- |
| 当前论文 / 切换论文 | 当前论文偏好读写隔离；切换回来可恢复。 |
| 原文 / 译文 | PDF 原文和证据卡保持原样；回答语言不改写检索来源。 |
| 不同会话 | 论文偏好共享于同一论文，但每条记录仍保留自己的会话 ID 与语言快照。 |
| 本地 / 云端 | 偏好和记录只保存在本机；DeepSeek 只收到问题、目标语言指示和既有检索证据。 |
| macOS / Windows | 使用 Python JSON 存储和浏览器标准控件，不依赖操作系统专属语言 API。 |

## 验收标准

1. 中文 UI 下可要求英文回答；回答语言选择不改变 UI 文案。
2. 论文 A 与论文 B 可分别设置回答语言和翻译目标；切换后不互相污染。
3. API 接收语言策略并把明确目标语言传入模型生成指令。
4. 新阅读记录保存该次语言策略；已有记录缺省兼容为中文/中文翻译目标。
5. 旧版请求省略语言字段仍可正常问答；无语言策略时行为与原版一致。
6. 证据文本仍是 PDF 原文，点击引用仍跳到原始页码。
7. 非法语言值被请求校验拒绝；模型/API 失败不得修改偏好或旧记录。

## 数据与隐私

- 论文级语言设置、术语偏好及阅读记录在本地存储，不同步进向量索引。
- API 调用范围遵守现有证据策略，不上传整篇 PDF。
- 语言策略快照不得保存 API 密钥、供应商凭证或用户隐私信息。

## 实施与非目标

本次只实施回答语言与翻译目标语言的论文级偏好、传入统一阅读上下文、回答输出指令、记录快照和中文 UI 控件。完整英文 UI、本地术语表、相邻段落上下文恢复、翻译缓存和中英双栏视图不在本次验收范围内；后两项依赖 M7 的结构化内容块。
