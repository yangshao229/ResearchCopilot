# 论文专属阅读路线与独立会话：开源产品拆解

检索日期：2026-09-22

## 用户问题

不同论文的研究问题、章节结构和阅读重点不同，不能共用一套固定提问模板。即使是同一篇论文，“理解方法”“检查实验”“准备复现”也属于不同任务；如果全部问题永久堆在一个列表里，后续很难恢复上下文、核对证据和整理笔记。

本功能要解决两个具体问题：

1. 根据当前论文实际目录生成可核对的阅读路线和推荐问题，而不是生成一套与论文无关的通用按钮。
2. 在同一篇论文内建立多个独立会话，并确保不同论文、不同会话的问答记录不会混合。

## 参考项目与一手资料

1. [Open Notebook](https://github.com/lfnovo/open-notebook) 及其 [Chat Effectively 官方指南](https://github.com/lfnovo/open-notebook/blob/main/docs/3-USER-GUIDE/chat-effectively.md)：支持 Notebook 内多个聊天会话、显式选择资料范围，并区分连续对话与一次性 Ask。
2. [SkimRead for Zotero](https://github.com/adellife/zotero-skimread)：基于章节边界提取核心叙事，区分 Goal / Method / Result / Novelty 与补充证据，结果默认是临时阅读辅助。
3. [Zotero Research Copilot](https://github.com/OneOneLiu/Zotero-Research-Copilot)：分开当前论文阅读器对话、文库助手和显式选择范围的多论文分析；会话状态可保存和恢复。
4. [PaperQA2](https://github.com/Future-House/paper-qa)：研究问题被保存为独立 session；搜索、证据收集和回答是可重复的明确流程，默认不会自动注入过去所有答案。

## 各项目的成熟做法

### Open Notebook：会话有固定范围，长对话应当结束

Open Notebook 在进入对话前先选择资料范围，后续追问沿用同一范围；官方指南建议长会话归档后重新开始，避免历史无限增长。它还区分 Chat 和 Ask：Chat 用于围绕同一主题逐步理解，Ask 用于一次完整搜索和回答。

对本项目的启示是：会话不只是前端标签，而应有稳定 ID、名称、论文归属和创建时间；问答记录必须显式属于一个会话。第一版仍只允许“当前论文”范围，不自动扩大到文库。

### SkimRead：阅读路线来自结构和论文角色

SkimRead 从整篇论文和章节关系中选择核心叙事，并用 Goal、Method、Result、Novelty 等修辞角色组织阅读；长文档沿章节边界分批。它同时警告默认角色更适合实证型论文，理论、人文或非标准结构需要自定义或自动发现。

对本项目的启示是：推荐问题应引用当前论文真实标题，例如“解释 Model Architecture 的核心设计”，并按概览、方法、实验、批判性阅读组织；识别不到相应章节时不能硬生成“实验结果”问题。

### Zotero Research Copilot：范围入口必须分开

该项目把当前论文侧边栏对话、文库助手和多论文分析分为三个入口。多论文流程只有在用户明确选择论文集合后才启动，会话状态也可以保存与恢复。

对本项目的启示是：本阶段只实现当前论文下的多个会话。未来增加多论文时应另设范围选择，不允许会话历史暗中把其他论文带入当前回答。

### PaperQA2：研究问题是独立、可追踪的 session

PaperQA2 的 agent 查询产生独立 session，并将问题、回答和证据流程作为可保存对象；默认不把之前的所有答案注入新查询。它的固定路径可以是 search → gather evidence → answer，减少不必要的代理步骤。

对本项目的启示是：先实现确定性的会话归属和本地推荐问题，不急着让 Agent 自主决定阅读任务。会话用于组织记录，不意味着下一次回答自动携带完整聊天历史；真正的多轮上下文要等证据与成本策略明确后再加入。

## 对 ResearchCopilot 的取舍

| 决策 | 借鉴来源 | 本项目做法 |
|---|---|---|
| 每篇论文拥有独立会话列表 | Open Notebook、PaperQA2 | 会话对象包含 `id`、`paper_id`、名称、创建时间；问答记录保存 `session_id`。 |
| 保留默认会话兼容旧记录 | Open Notebook | 旧记录自动归入“默认阅读”，不迁移或破坏现有 JSON。 |
| 推荐问题绑定真实章节 | SkimRead | 从当前目录识别概览、方法、实验、结论角色；问题文本带具体章节名和页码范围。 |
| 推荐问题只填入输入框 | SkimRead | 用户点击后仍需决定是否发送，不自动调用 DeepSeek，也不自动写入笔记。 |
| 当前论文是固定范围 | Zotero Research Copilot | 会话不能跨论文；切换论文时只读取该论文的会话和历史。 |
| 会话先用于组织，不自动携带全部历史 | PaperQA2 | 第一版每次回答仍以当前问题和检索证据为依据，避免成本和错误累积。 |
| 长期可归档，不做无限对话 | Open Notebook | 本阶段支持新建与切换；归档和重命名放到后续小版本。 |

明确拒绝：

- 不根据文件名或单个摘要生成看似具体、实际空泛的整套问题。
- 不在用户点击推荐问题时立刻发送 API 请求。
- 不把其他论文的会话、历史或推荐问题显示在当前论文中。
- 不把会话名称当成模型上下文；范围必须由 `paper_id` 和后端查询共同保证。
- 不直接复制 AGPL 项目代码；这里只借鉴交互和数据边界思想。

## 数据与隐私边界

- 会话、推荐问题和目录角色判断全部在本地保存或计算。
- 新建、切换会话不调用任何模型 API。
- 点击推荐问题只填充本地输入框。
- 真正提交内容问题时，仍只发送当前问题与当前论文最多 5 段检索证据。
- 会话 ID 不能覆盖论文 ID 的范围校验；后端必须同时验证二者归属。

## 许可证检查

- Open Notebook：MIT，可参考公开设计；本阶段不复制源代码。
- PaperQA2：Apache-2.0，可参考 session 和确定性流程；本阶段不引入其依赖或源代码。
- SkimRead：AGPL-3.0-or-later，只借鉴章节角色和临时阅读辅助理念，不复制代码。
- Zotero Research Copilot：AGPL-3.0，只借鉴范围分离和会话恢复理念，不复制代码。

本阶段继续使用项目现有 Python、FastAPI、React 和本地 JSON，不增加第三方依赖。

## 实现顺序

1. 建立按 `paper_id` 分文件保存的会话对象，并为旧记录提供“默认阅读”会话。
2. 让每条新增问答记录显式保存 `session_id`，并提供按会话读取历史的 API。
3. 在当前论文页面增加会话选择、新建会话和范围提示。
4. 根据 `PaperStructure` 生成本地阅读路线；只为实际存在的章节角色生成问题。
5. 点击推荐问题时填充提问框，保留用户确认动作。
6. 使用两篇测试论文验证会话与推荐问题完全隔离。

## 验收标准

1. 同一论文建立“理解方法”和“检查实验”两个会话后，各自只显示自己的问答记录。
2. 切换到另一篇论文时，看不到前一篇论文的会话和记录。
3. 旧问答记录仍能显示，并自动归入“默认阅读”。
4. 含 Method、Results、Conclusion 的论文会生成对应章节问题，问题包含真实标题。
5. 没有实验章节的论文不会生成虚假的实验问题。
6. 点击推荐问题只填充输入框，不产生历史记录和 API 调用。
7. 伪造其他论文的 `session_id` 提交回答时，后端拒绝请求。
8. 会话与阅读路线接口、迁移兼容和跨论文失败场景均有自动测试。

## 暂不实现的内容

- 自动把之前全部问答发送给 DeepSeek 的真正多轮模型上下文。
- 会话删除、归档、重命名和跨设备同步。
- 当前论文以外的文库问答或多论文综合。
- 用模型自动判断论文类型；第一版只使用可解释的目录角色规则。
- 将推荐问题自动加入正式论文卡片。
