# 答案承载重排与拒答分离：开源评测拆解

日期：2026-10-08。范围：**离线影子评测，不改变生产检索、回答或网页**。

## 用户问题

M8.4l 发现三篇论文的部分答案片段已进入前 30 候选，却没有进入用户实际看到的前 5；固定邻居窗口只能补回 `2/12`，且文本量近乎翻倍。下一步需要直接检查两种现有重排器能否把“真正含有全部答案短语”的片段移入前 5，同时把无答案问题独立评测，避免把“排序改善”误写成“会拒答”。

## 参考项目与一手资料

1. [mMARCO 原始论文](https://arxiv.org/abs/2108.13897)与[官方仓库](https://github.com/unicamp-dl/mMARCO)：多语 passage ranking 以翻译后的 MS MARCO 训练并报告跨语零样本结果，支持把中英问题分别统计，而不是把“多语模型”当作已验证结论。
2. [BGE-Reranker 官方文档](https://bge-model.com/bge/bge_reranker.html)与[官方模型卡](https://huggingface.co/BAAI/bge-reranker-base)：先召回较大的候选集，再以 Cross Encoder 重排少量结果；模型分数用于相对排序，不天然是跨问题可比较的拒答概率。
3. [BEIR 原始论文](https://arxiv.org/abs/2104.08663)与[官方仓库](https://github.com/beir-cellar/beir)：异构数据集上的零样本表现会显著变化，重排通常提高效果但计算成本更高，因此必须保留逐论文、逐语言和失败例，而不能只报平均数。
4. [SQuAD 2.0 原始论文](https://aclanthology.org/P18-2124/)：不可回答问题与含有貌似相关答案的上下文共同评测，说明拒答必须使用冻结负例，不能根据“没有关键词”推断。

检索日期均为 2026-10-08。现有 mMARCO 与 BGE 本机模型快照均标注 Apache-2.0；本轮不下载新模型、不复制上述仓库代码或数据、不增加依赖，只使用公开论文方法定义评测。因此没有新增许可证传播要求。

## 各项目的成熟做法

| 来源 | 成熟做法 | 本轮采用 |
| --- | --- | --- |
| mMARCO | 多语问句必须逐语言验证 | 同一事实的中英问句分别统计答案短语覆盖 |
| BGE | 召回与重排是两个阶段 | 固定相同前 30 候选，只比较排序后的前 5 |
| BEIR | 关注跨数据集稳健性与计算代价 | 保留 LoRA、Transformer、BERT 分论文结果，不用单一总分掩盖回退 |
| SQuAD 2.0 | 正例与困难无答案题同时评测 | 冻结三篇论文各一组中英无答案题，并单独检查分数是否与正例分离 |

## 对 ResearchCopilot 的取舍

| 决策 | 采用／拒绝 | 理由 |
| --- | --- | --- |
| 将 M8.4l 的人工短语写入独立冻结账本 | 采用 | 可直接判断重排后的前 5 是否真的含有回答所需事实 |
| 比较混合检索、mMARCO 与 BGE 的答案承载覆盖 | 采用 | 三者使用同一候选池与同一事实真值，避免页命中替代片段证据 |
| 以正例最低分和负例最高分检查单阈值 | 采用为失败诊断 | 若区间重叠即可明确否定统一分数阈值；即使分离也不自动上线 |
| 为得到更好结果调模型、候选权重或真值 | 拒绝 | 冻结后只运行，避免在同一小账本上过拟合 |
| 把无答案题没有命中短语当作会拒答 | 拒绝 | 短语账本只定义正例证据，负例仍会返回高分候选 |
| 调用 DeepSeek 生成并评判答案 | 拒绝 | 本轮只隔离检索排序与分数门槛，不混入生成模型变量 |

## 数据、隐私与失败场景

新账本只组合既有三篇公开论文、12 条中英正例、6 条中英无答案题及已经人工核对的必要原文短语，并绑定 PDF SHA-256。只读取本机 PDF、E5 和两个固定重排模型缓存；不读取密钥，不修改论文、译文缓存、阅读记录或用户 Vault。

失败场景包括：候选前 30 本身缺少必要短语，任何重排器都无法补救；短语出现在无关语境造成字符串误报；不同页各含一半事实却被错误拼接；负例最高分与正例最低分重叠；某模型总体改善但在单篇论文或中文上回退；CPU 延迟不适合交互。报告必须把答案短语覆盖、页锚点和拒答分开陈述。

## 架构影响

复用 `reranker_evaluation.evaluate_case`、固定候选召回、两种本机 Cross Encoder 与已有 PDF 指纹检查。新增一个冻结 JSON，把每个必要短语表示为必须覆盖的独立 evidence group；`summarize` 只增加正负例最高分区间与是否可由单阈值分离的离线诊断字段。不会修改 `EvidenceSet`、HTTP API、前端、生产排序或持久化。

## 兼容性矩阵

| 组合 | 检查 |
| --- | --- |
| 当前论文／跨论文 | 每题只检索其绑定论文；汇总不把不同论文文本混合 |
| 英文／中文问题 | 6 组正例与 3 组负例均有中英问法，分别报告 |
| 原文／译文 | 只匹配英文 PDF 原文；不读取或自动生成译文 |
| 不同会话 | 离线评测不读取会话、历史或快照令牌 |
| 本地／云端 | 全部本地且强制离线；不调用 DeepSeek |
| macOS／Windows | JSON 与纯 Python 汇总逻辑跨平台；模型推理仅在当前 macOS 实测 |

## 实现顺序

1. 先冻结组合账本与 PDF 哈希，不运行重排模型。
2. 为汇总器增加分数区间和单阈值分离测试，旧账本无负例时保持 `null`。
3. 用同一候选分别运行 mMARCO 与 BGE，记录答案短语 Top-5、逐语言／逐论文回退和 CPU 时间。
4. 单独检查 6 条无答案题与正例分数区间，不把检索分数解释为概率。
5. 运行完整 pytest、前端生产构建和差异检查，更新验收、项目、蓝图与学习地图。

## 验收标准

- 12 条正例的所有必要短语均能在绑定 PDF 的同一页人工核对，6 条负例无 evidence requirements。
- 两个模型使用完全相同的前 30 候选与 Top-5 预算；报告候选池缺失、提升和回退。
- 自动测试覆盖正负分数可分、重叠、无负例兼容和非有限分数既有失败关闭。
- 若任一模型的负例最高分不低于正例最低分，明确判定统一拒答阈值不成立。
- 完整 Python 测试与前端生产构建通过；不调用 DeepSeek、不写用户数据。

## 暂不实现

- 不训练或校准新的拒答分类器。
- 不把任何重排器或窗口接入生产。
- 不生成答案，不用 LLM-as-a-judge。
- 不把三篇既有论文结果冒充新论文泛化能力。
