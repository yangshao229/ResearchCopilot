# 首次使用与本地服务恢复：开源产品拆解

检索日期：2026-10-05。范围是空论文库、旧后端和本地服务不可达时的页面引导；不改变 PDF、检索或模型能力。

## 用户问题

第一次打开 ResearchCopilot 时，用户需要马上知道“导入一篇 PDF → 阅读原文 → 核对证据 → 保存自己的理解”的最短路径。若浏览器标签连接到旧服务或本地服务暂不可用，页面不能把错误误显示成空资料库，更不能让用户以为论文消失；它应说明原因并提供安全重试。

## 流程、数据与失败处理

页面加载先并行读取健康信息、论文列表和集合。论文列表成功且为空时显示首次使用四步与中央导入按钮；论文列表失败时显示本地服务恢复卡和“重新检查”，不把空数组当成真实资料库。健康端点缺少或返回不同 schema 时显示版本不匹配提醒，同时让仍兼容的论文列表继续工作。

重试只重新读取状态，不停止、重启或替换进程；用户仍通过双击启动脚本管理服务。PDF 导入沿用现有接口和安全目录，不增加网络上传。空状态文案不要求配置 DeepSeek：导入和阅读原文应先可用，模型功能按需启用。

## 架构影响

- 后端 `/api/health` 增加 `api_schema` 与应用版本；不新建状态存储。
- 前端复用现有 `listPapers`、导入函数和错误处理，只增加健康请求、兼容警告与重试触发器。
- 不改变论文、阅读上下文、证据、记录或 Vault 领域对象。

## 兼容性矩阵

| 情况 | 行为 |
| --- | --- |
| 当前论文／跨论文 | 只影响启动与资料库外壳，不改变范围。 |
| 原文／译文 | 首次使用先导入并读原文；不自动翻译。 |
| 不同会话 | 重试不清除浏览器保存的论文、页码或会话选择。 |
| 本地／云端 | 仅检查同源本地 API，不访问外网或模型。 |
| macOS／Windows | 浏览器流程一致；启动方式继续由各平台说明承担。 |
| 新前端／旧后端 | 显示明确版本提醒；基础论文列表若能读取则继续可用。 |

## 实现顺序

1. 为健康端点增加稳定 schema 版本和测试。
2. 前端并行读取健康信息并区分服务失败、旧版本和真实空库。
3. 为错误状态加入重试，为空库加入中央导入入口与短流程。
4. 运行完整测试和生产构建；不触碰用户论文或本地记录。

## 验收标准

1. 健康端点返回明确 `api_schema`，自动测试固定契约。
2. 论文列表失败时中央区域不显示空库文案，而是说明本地服务不可用并可重试。
3. 旧健康端点或 schema 不匹配时显示版本提醒，不把论文误清空。
4. 真正空库时，中央区域可直接导入 PDF，并解释下一步阅读闭环。
5. 不新增模型调用，不修改现有论文、阅读记录、翻译缓存或 Vault。

## 暂不实现

自动停止旧进程、后台更新应用、端口扫描、遥测、登录、云端同步和自动导入示例论文。这些会扩大权限或改变用户文件，应另行设计。
