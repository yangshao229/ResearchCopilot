# M7.4e 行内数学保护真值与误报评测：开源产品拆解

检索日期：2026-10-03。此记录先于评测代码完成。只借鉴评测结构、坐标核验与失败关闭方法，不复制第三方代码、模型或测试数据。

## 用户问题

M7.4d 已能把 `sample.pdf` 第 7 页中唯一可定位的 `β₁`、`β₂` 和 `ϵ = 10⁻⁹` 保留为原 PDF 小裁片，但证据只有一篇论文的一页。直接扩大正则会把希腊语散文、重复参数、跨行碎片或普通变量赋值误当成已验证公式；继续停留在单一成功样本，又无法判断现有规则是否只是在过拟合。

本阶段先建立可重复的真值账本：分别记录“规则声称支持且应保护”“不应误报”和“有数学含义但必须安全回退”三类案例，自动计算受支持样本召回率、负样本误报率和安全回退率。评测只决定当前规则的可信边界，不把未覆盖表达式自动升级为支持范围。

## 参考项目与一手资料

| 项目 | 一手资料与成熟做法 | 许可证与本项目取舍 |
| --- | --- | --- |
| [Marker benchmark](https://github.com/datalab-to/marker/blob/master/benchmarks/README.md) | 用 1,403 个单页 PDF、约 8,400 条可判定测试按数学、表格、多栏、扫描件等类别分别评分；总分采用类别宏平均，而不是用几个展示案例代替评测。其无 OCR 文字层模式在数学类别明显失效，说明文字层路径不能被包装成通用公式恢复。 | Marker 代码 Apache-2.0，模型权重另有许可。只借鉴“固定数据、分类评分、可复跑”的评测思想；不下载 benchmark、模型或代码。 |
| [Nougat 官方仓库](https://github.com/facebookresearch/nougat) | 科学 PDF 到数学/表格标记依赖视觉模型；训练数据把 PDF 与 LaTeXML 处理后的 HTML 配对，评测按不同文本模态计算。仓库也明确提供失败检测与 `[MISSING_PAGE]`，而不是保证每页都可重建。 | 代码 MIT，模型权重 CC-BY-NC。完整视觉解析需要模型、数据和算力，本阶段拒绝引入；借鉴“PDF/结构真值配对”和显式失败状态。 |
| [pdfplumber 官方 README](https://github.com/jsvine/pdfplumber/blob/stable/README.md) | 每个字符暴露文字、字体、大小、变换矩阵和 `x0/x1/top/bottom`，并提供裁图与视觉调试；同时明确更适合机器生成 PDF，而不是扫描件。 | MIT。项目已经使用该依赖；本阶段只复用现有字符坐标，不增加依赖，也不把坐标等同于数学语义。 |
| [PDF.js 官方文本示例](https://github.com/mozilla/pdf.js/blob/master/examples/text-only/pdf2svg.mjs) 与 [文本切分问题](https://github.com/mozilla/pdf.js/issues/18201) | 官方示例通过 `getTextContent()` 的字符串、字体和变换矩阵重建可视位置；实际 issue 展示同类文字可能被切成整句、单词、空格或空项，文本项边界并不稳定。 | Apache-2.0。只把 PDF.js 用于现有原页显示；评测不依赖浏览器文本项恰好如何切分。 |

共同结论是：公式处理必须按类别和失败模式评测；字符坐标可证明“来自原页的哪个区域”，却不能证明已恢复数学语义；视觉模型能扩大覆盖，但带来模型、许可证、算力与跨平台成本，不能在本地轻量阶段偷偷引入。

## 各项目成熟做法与 ResearchCopilot 取舍

### 评测流程

1. 固定一份人可读、机器可读的真值账本，案例带稳定 ID、类别、源文字、可见字形、几何变体、期望决策和理由。
2. 将指标分开：受支持样本计算召回率，普通文本计算误报率，歧义/不支持数学计算安全回退率；不把回退当作识别成功。
3. 使用真实 `sample.pdf` 保留一个端到端锚点，再用多个合成排版轮廓覆盖不同间距、上下偏移、重复位置、旋转和跨行失败；合成样本不是“跨论文真实精度”的替代品。
4. 每次规则扩展必须先增加真值案例，再修改实现；若指标退步，停止扩展并保留原 PDF 对照。

### 数据、模型与交互

- 真值账本只保存短小的人工构造字符串和坐标轮廓，不复制外部论文内容，不写入用户资料库。
- 继续复用 `FormulaRegion`、页码和 `OriginalPdfClip`；评测不增加领域对象、不改变缓存格式，也不调用翻译模型。
- 受支持且唯一定位的片段继续显示原图；未支持、重复、旋转或跨行的案例原样留给现有流程，并由数学复核提示要求读者对照原 PDF。
- 本阶段不因为合成评测通过就扩大到 ASCII 变量、函数、分式或任意上下标；这些需要真实跨论文人工真值。

## 架构影响与兼容性矩阵

新增内容限于评测真值、测试和文档。生产路径仍为 `PageTranslationService → protect_inline_assignments → FormulaRegion → OriginalPdfClip`。若评测暴露实现缺陷，只允许修复唯一定位、边界检查或失败关闭；不得借机建立第二套公式解析链。

| 情况 | 预期 |
| --- | --- |
| 当前论文 / 其他论文 | 真实锚点仍来自仓库样本；合成轮廓覆盖多种排版，但结论明确不宣称真实跨论文精度。 |
| 原文 / 译文 | 原 PDF 永不修改；评测只检查是否应用原图占位符，不生成公式译文。 |
| 当前会话 / 其他会话 | 页级公式保护与会话无关，不读写问答记录。 |
| 本地 / 云端 | 全部在本地运行，假页面代替模型；DeepSeek 调用数为零。 |
| macOS / Windows | 只使用 Python、JSON、pdfplumber 既有接口和 pytest，不增加系统字体或原生工具依赖。`data/raw/sample.pdf` 是按约定不随 Git 同步的本机锚点；缺失时跳过该真实页核对，合成账本仍必须通过。 |
| 机器生成 / 扫描 PDF | 机器生成 PDF 可使用字符坐标；扫描页继续安全回退，不启用 OCR。 |
| 唯一 / 重复 / 跨行 / 旋转 | 只有唯一、同一视觉行、坐标有效的受支持表达式可保护；其他情况必须保持原文。 |

## 实现顺序

1. 新增真值账本，区分 `protect`、`leave` 和 `safe_fallback`，覆盖至少四个受支持变体、普通希腊语、ASCII 赋值、重复源文字、重复视觉位置、字形不匹配、跨行和旋转。
2. 用同一测试驱动器重放所有案例，输出受支持召回率、负样本误报率和安全回退率；指标计算必须防止空集合或分母漂移。
3. 对真实 `sample.pdf` 第 7 页固定三处行内裁片数量、顺序、页码、边界和原文其余内容不被吞掉。
4. 只有评测证明必要且有确定修复时才修改生产规则；否则记录“未扩展”结论。
5. 运行完整 pytest 和前端生产构建，更新验收、学习地图、项目进度与产品蓝图。

## 验收标准

1. 真值账本可由测试直接读取，至少包含 12 个案例和三种期望决策；每个案例有理由与合成来源轮廓。
2. 当前窄规则对账本中的受支持样本召回率为 `1.00`，对明确负样本误报率为 `0.00`，对歧义/不支持数学安全回退率为 `1.00`。
3. 重复视觉位置、重复源文字、字形不匹配、跨行、旋转和不存在的 PDF 不生成原图区域。
4. 在本机存在真实 `sample.pdf` 时，第 7 页仍得到三处行内区域，坐标有效且 PDF 原文不变；其他设备缺失该文件时只跳过此锚点，不调用真实模型。
5. 完整 Python 测试与前端生产构建通过，指标和局限写入验收文档。

失败场景：若某个 `leave` 或 `safe_fallback` 案例产生裁片，评测立即失败；若受支持案例找不到唯一同一行字形，也必须失败，而不是降低分母或把案例移出真值。

## 暂不实现

- 扫描页 OCR、VLM/LaTeX 重建、任意行内公式、表内公式或整篇批量翻译。
- 下载 Marker/Nougat 模型或外部 benchmark；引入新模型前需单独核对许可证、体积、离线能力和 Mac/Windows 成本。
- 把合成多轮廓结果表述为真实跨论文准确率；后续取得允许使用的多篇论文样本后，必须追加真实人工真值再扩大识别范围。
