# M8.4r：真实论文回答人工复核流程——开源产品拆解

检索日期：2026-10-09。设计状态：只准备离线复核协议，不接入新模型或自动评分。

## 用户问题

ResearchCopilot 已能把回答绑定当前论文的原文片段，并在模型自报证据不足或引用编号无效时拒答。然而“引用编号有效”并不意味着引用真的支持结论。用户读论文时需要知道：模型答得对不对、该页原文是否支持每个结论、该拒答时有没有猜、能回答时有没有误拒。这些问题不能继续用页码 Top-5 或相似度分数代替。

## 参考项目与一手资料

| 项目 | 一手资料 | 可借鉴的做法 |
| --- | --- | --- |
| Haystack | [官方评测器文档](https://docs.haystack.deepset.ai/docs/evaluators)、[官方模型评测说明](https://docs.haystack.deepset.ai/docs/model-based-evaluation) | 把检索文档质量、答案匹配和回答忠实度作为不同指标。 |
| LlamaIndex | [官方回答评测用法](https://docs.llamaindex.ai/en/v0.9.48/module_guides/evaluating/usage_pattern.html) | 同一条回答保留问题、上下文、响应，并分别检查 faithfulness 与 relevancy。 |
| Ragas | [官方指标迁移和定义](https://docs.ragas.io/en/stable/howtos/migrations/migrate_from_v03_to_v04/) | 把回答正确性与检索上下文忠实度分开，不把其中一个总分当作另一个。 |
| SQuAD 2.0 | [原始论文](https://aclanthology.org/P18-2124/) | 有答案与无答案都要测；无答案题可以与正文主题非常相近，不能靠粗糙相关性判断。 |

以上借鉴的是评测结构，不复制任何项目代码；当前不新增依赖，故没有新增许可证、下载体积或平台运行风险。未来若引入评判模型，需要另核对许可证、跨平台运行成本、中文能力、API 费用及偏差。

## 各项目流程与本项目边界

- **交互**：Haystack、LlamaIndex、Ragas 面向开发者的评测流水线通常接收已保存的问答样本。ResearchCopilot 本轮也先离线审阅，不在日常阅读界面塞一个“真实率”按钮。
- **数据结构**：每条样本必须固定论文 SHA-256、问题、可回答性、实际送入模型的证据、模型原始结构化结果、用户可见结果和人工裁决。原文页码来自现有 `SourceDocumentRef`／`EvidenceSet`，不得在新账本中形成第二个权威页码体系。
- **模型／检索**：继续使用现有检索和回答链，不为了评测改变候选或重排。评测时记录当时检索模式、证据快照和模型版本，以免后来索引变化使结果不可复现。
- **引用**：人工逐条判断答案中的事实能否由所引原文直接支持；“引用 ID 存在”和“引用忠实”分列。中英问法作为配对但独立记录，不自动把英文判定复制给中文。
- **隐私**：只对允许使用的测试论文做小规模本机评测；原始 PDF、回答和人工标签保持本地，不送给第三方评判服务或用户 Vault。若调用 DeepSeek，需要先明确题数与费用边界，不能由回归测试偷偷触发。
- **失败处理**：缺失 PDF、SHA 不匹配、证据快照缺失、输出截断或人工标签未完成时，该题状态为“不可评分”，不能算作通过或拒答成功。API 错误与模型拒答也必须分开记录。

## 对 ResearchCopilot 的取舍

| 方案 | 决定 | 原因 |
| --- | --- | --- |
| 独立统计“错误肯定／错误拒答／引用忠实／答案正确” | 采用 | 四项反映不同失败；直接对应读论文可信度。 |
| 复用已冻结的跨论文问题与 PDF 哈希 | 采用 | 减少事后挑题和真值漂移。 |
| 先由人核对原文页和模型回答 | 采用 | 当前样本少且有公式、双栏与中英问题，自动评判无法充当真值。 |
| 直接引入 Haystack、Ragas 或 LlamaIndex 整包 | 拒绝 | 仅为少量离线样本引入新框架会增加依赖和心智负担。 |
| 用模型自评或引用编号有效率宣称忠实度 | 拒绝 | 这些无法证明语义支持；还可能把同一模型偏差带进评测。 |
| 自动将评测结果写入 Obsidian | 拒绝 | 评测记录不是用户确认的知识笔记。 |

## 架构影响与兼容性矩阵

本轮只新增复核协议与待填账本，不改生产 API、网页、`PaperAnswerService` 或 Vault。将来执行时，输入来自既有 `EvidenceSet` 与 `PaperAnswer`，新账本只保存复核所需的快照和裁决，不成为 PDF 真值或阅读记录的替代品。

| 维度 | 处理方式 |
| --- | --- |
| 单论文／跨论文 | 先按论文独立评分；跨论文比较答案仍保持关闭，不把多论文候选混作单篇引用。 |
| 原文／译文 | 答案可中英，支持性一律回看原始 PDF；译文不充当唯一证据。 |
| 不同会话 | 固定 PDF 哈希、问题 ID、模型版本和证据快照，避免后来会话覆盖旧结果。 |
| 本地／云端 | 本地保存账本；云端仅在获得费用边界后作为被测回答模型，不作为默认裁判。 |
| macOS／Windows | 使用 JSON/Markdown 和现有 Python 3.12 环境，无平台专属路径或新增依赖。 |

## 实现顺序与验收标准

1. 从已冻结的 RAG、LoRA、Transformer、BERT 账本选少量有答案和无答案的中英题；先锁定 PDF 哈希、问题 ID 和人工判定细则。
2. 在用户确认付费调用上限后，保存**真实**模型输出及当次证据快照；不允许回归测试调用 API。
3. 人工逐题核对 PDF 原文，单独标注是否答对、是否误拒、每个引用是否支持相应论断；复核者看不清时标“待复核”而非猜测。
4. 仅在样本完整时汇总分母与失败类型；任何失败案例都附问题、PDF 页、模型输出和支持／反驳的原文位置。

完成条件：至少覆盖一个答案正确、一个错误肯定、一个正确拒答、一个错误拒答的人工校验样例；统计时四类分母分开；无效／未填人工标签不得被计入通过。失败场景：PDF 内容版本变化、模型输出截断、只给真实引用 ID 却无语义支持，均不能被误报为“通过”。

## 暂不实现

不做整篇论文自动答案裁判、模型驱动的自动修正、不使用单一“可信度”分数、不调整生产检索参数、不开放跨论文生成，也不在未约定 API 预算前执行真实模型批量测试。
