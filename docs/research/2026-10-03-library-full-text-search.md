# M8.2 本地资料库全文搜索：开源产品拆解

检索日期：2026-10-03。此记录先于功能代码完成。只借鉴交互、范围和失败处理，不复制第三方代码或索引实现。

## 用户问题

论文数量增加后，仅靠集合和标签无法回答“哪篇论文、哪一页提到这个术语或方法”。现有 ResearchCopilot 检索入口附属于当前论文，并会继续进入证据问答；若直接把它扩大到整个资料库，用户可能误以为系统已经进入经过评测的跨论文生成模式。M8.2 因此只提供本地资料库内容查找：返回论文、真实 PDF 页码和原文片段，点击后打开对应论文与页面，不调用模型、不生成跨论文结论。

| [Zotero Searching](https://www.zotero.org/support/searching)、[Full-text API](https://www.zotero.org/support/dev/web_api/v3/fulltext_content) | 快速搜索把元数据、标签、笔记和已索引 PDF 内容区分为不同模式；高级搜索可限定集合。全文索引显示覆盖状态，无法抽取文字的 PDF 不应伪装成已索引。 | Zotero 代码 AGPL-3.0。借鉴“资料库查找与内容生成分离”、可见范围和索引失败状态；不复制代码或数据库结构。 |
| [Paperless-ngx 使用文档](https://github.com/paperless-ngx/paperless-ngx/blob/dev/docs/usage.md)、[REST API](https://github.com/paperless-ngx/paperless-ngx/blob/dev/docs/api.md) | 文档列表可把全文查询与标签等过滤器组合；结果按相关度排序并提供命中高亮片段。全文查询接口和普通元数据过滤明确区分。 | GPL-3.0。借鉴“结果包含片段、分数和筛选范围”；不引入 Tantivy、OCR、自动标签或服务端 HTML 高亮。 |
| [JabRef 库内搜索](https://docs.jabref.org/finding-sorting-and-cleaning-entries/search) | 默认多词查询要求全部词出现；短语可用引号，高级字段语法另行提供；清空搜索恢复完整列表。 | MIT。第一版采用容易解释的全部词匹配和清空恢复，不开放正则或字段查询语法，避免难以验证和跨语言不一致。 |

共同结论：库内搜索首先是定位工具，范围和匹配位置必须可见；内容全文与元数据筛选应组合而不是互相覆盖；无可抽取文字、索引失败和零结果需要分别表达；生成或跨论文总结不应由搜索动作隐式触发。

## 各项目的成熟做法

### 交互流程

1. 用户在资料库输入一个或多个词并显式提交；不会边输入边对所有 PDF 重复解析。
2. 当前集合和标签筛选决定本次搜索包含哪些论文，页面显示实际搜索范围。
3. 结果按可解释的词频分数排序，展示论文名、真实 PDF 页码和纯文本片段。
4. 点击结果只切换到该论文和页面，并保持结果列表；不会发起 DeepSeek 请求或创建问答记录。
5. 清除查询恢复普通资料库列表。无结果与无可搜索论文使用不同说明。

### 数据、检索与引用方式

- 复用 `PaperLibrary` 的稳定论文 ID、`PaperSearchService` 的按论文本地分页缓存以及现有 `source_page`，不建立第二套页码或 PDF 文本副本。
- 查询去除多余空白、大小写不敏感；所有查询词必须在同一检索片段中出现。第一版不承诺词干化、模糊匹配、中文分词或短语语法。
- 每篇论文最多返回有限片段，再全局按词频、论文名、页码和片段序号稳定排序；限制总结果数，防止大资料库一次返回过多文本。
- API 返回纯文本片段，不接受服务端 HTML，避免高亮注入；前端第一版不拼接不可信标记。
- 结果页码引用原始 PDF 的一基页码，点击复用现有阅读器跳页逻辑。

### 隐私与失败处理

- PDF 文本抽取和关键词匹配全部在本机进行，不访问网络、不调用嵌入模型或生成模型。
- 只读取当前搜索范围内的论文；不写论文、阅读历史、术语表、译文缓存或集合元数据。
- 单篇 PDF 损坏或无法抽取文字时记录为不可搜索并继续其他论文；整个请求不能因一篇失败而丢失已有结果。
- 不存在的论文 ID 被忽略或拒绝会隐藏范围错误；因此 API 对未知范围 ID 返回明确错误，空范围则返回空结果。

## 对 ResearchCopilot 的取舍

| 决策 | 理由 |
| --- | --- |
| 新增独立 `/api/library/search`，不复用当前论文 `/answer` | 从接口层阻止搜索隐式进入跨论文生成。 |
| 复用现有分页 JSON 与关键词检索，不新增索引依赖 | 当前库规模小，先验证查找流程；避免数据库迁移、模型下载和跨平台安装成本。 |
| 前端把当前集合/标签筛选后的论文 ID 作为显式范围 | 搜索范围与用户眼前的资料库范围一致；空范围不会退化为全库。 |
| 多词使用全部词匹配 | 与 JabRef/Paperless 默认语义一致，降低短查询噪声；暂不声称支持自然语言语义搜索。 |
| 结果只显示原文片段和页码 | 保持证据可核对，不生成摘要或跨论文结论。 |
| 单篇抽取失败继续并返回失败计数 | 大资料库中一篇坏 PDF 不应阻断其余结果，同时不能把它误报为“没有命中”。 |

明确拒绝：OCR、语义/向量库级搜索、自动相似论文、服务端 HTML 高亮、正则/高级查询语法、保存搜索、跨论文回答和自动主题笔记。

## 数据与隐私边界

本阶段只可能通过现有 `data/processed/<paper_id>.json` 懒生成或刷新本地分页抽取缓存；它是现有单篇检索已经使用的可重建产物。不会写入 `data/raw`、`artifacts/reading_history`、`page_translations`、术语表、集合与标签或论文卡片。搜索请求和结果不发送给 DeepSeek。测试使用临时 PDF 与临时 processed 目录。

## 架构影响与兼容性矩阵

新增库级搜索请求/结果领域模型和只读路由；检索仍由 `PaperSearchService` 完成，`PaperLibrary` 负责把 ID 解析为安全路径。前端在现有资料库面板增加搜索表单和结果列表，点击结果调用已有 `choosePaper` 与 `changePage`。

| 情况 | 预期 |
| --- | --- |
| 当前论文 / 跨论文 | 搜索可定位多个显式范围内论文；点击后才切换当前论文，不生成跨论文回答。 |
| 原文 / 译文 | 只搜索 PDF 可抽取原文；不搜索、读取或修改译文缓存。 |
| 当前会话 / 其他会话 | 搜索与会话无关，不创建或混合问答记录。 |
| 全部论文 / 集合与标签筛选 | 未筛选时显式传全部论文 ID；筛选后只传可见论文；空列表保持空范围。 |
| 本地 / 云端 | 全程本地关键词匹配，不加载 embedding，不调用 DeepSeek。 |
| macOS / Windows | 复用 pathlib、pypdf 和现有 JSON 缓存；无新增系统服务或原生依赖。 |
| 可抽取 PDF / 扫描或损坏 PDF | 前者返回页码片段；后者计入跳过数量，不执行 OCR。 |
| 中文 / 英文界面 | 搜索控件、范围、结果、空状态和错误均进入两套消息表；原文片段不翻译。 |

## 实现顺序

1. 为 `PaperSearchService` 增加不加载 embedding 的确定性库级关键词入口，保留真实页码并限制片段长度。
2. 新增库级搜索 API，验证显式论文范围、逐篇失败隔离、全局稳定排序和结果上限。
3. 在资料库面板加入显式提交、清除、范围说明、结果列表和点击跳页；不改变助手问答范围。
4. 补中英文消息、回归测试，运行完整 pytest 与前端生产构建。
5. 用临时多论文样本验证隔离，并在可行时用真实本地 PDF 做只读查找；不调用 DeepSeek。

## 验收标准

1. 两篇临时 PDF 中的不同词与共同词能返回正确论文、真实页码、片段和稳定顺序；多词必须同时出现。
2. 显式范围只搜索给定论文；空范围返回空结果；未知论文 ID 返回明确错误。
3. 单篇不可解析不会阻断其余论文，响应显示被跳过数量；零命中不等同于解析失败。
4. 点击结果切换到目标论文和页码，不调用回答接口、不创建阅读记录。
5. 当前集合和标签筛选改变搜索范围；清空搜索不改变集合、标签或当前论文。
6. 完整 Python 测试与前端生产构建通过，不调用 DeepSeek，不修改用户论文、阅读记录或翻译缓存。

失败场景：请求包含不存在的论文 ID 时必须返回范围错误，不能静默扩大为全库；某篇扫描 PDF 没有文本时继续搜索其他论文并显示跳过计数。

## 暂不实现的内容

- OCR、扫描件识别、词干化、拼写纠错、中文分词、短语/正则/字段语法。
- 资料库级语义向量索引、相似论文、跨论文 RAG、答案生成和主题笔记。
- 搜索历史、保存搜索、后台索引队列、增量数据库或大规模性能优化。
