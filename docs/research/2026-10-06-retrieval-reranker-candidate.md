# 宽泛论文提问的证据排序：开源产品与模型候选拆解

日期与一手资料检索日期：2026-10-06。状态：**候选调研，不代表已下载、接入或验证有效**。用户目标是中文问题检索英文 AI 论文的正文证据，不把参考文献、附录表格或普通提及误当答案。

## 真实故障与不可取的捷径

LoRA v2 中，`Which matrices does LoRA train?` 的现有混合检索前五个片段来自 PDF 第 10、6、22、1、21 页，而解释低秩更新矩阵的第 4 页未进前五。把原始词频直接换成 BM25 的本机试验仍未修好这一题，因此已撤回试验代码；不能凭单篇题目调高某个权重后宣布解决。现有检索按片段返回，相关性和最终回答的证据充分性也是不同问题。

## 架构影响与失败处理

- 复用既有“论文 → 内容块 → 检索结果 → 原文页码证据”流水线，不增加新的核心领域对象，也不改变 PDF 页码、阅读记录或 Vault 格式。
- 若用户批准实验，重排序器只接收现有关键词＋E5＋RRF 召回的有限候选，并返回独立的影子分数；默认检索和问答仍以现有路径运行，模型缺失、加载失败、内存不足、推理超时或分数数量不匹配时直接回退现有排序。
- 模型与 tokenizer 必须固定修订且仅落入本机模型缓存，不进入 Git；运行时不得联网补文件。许可证记录保留在本报告和后续验收中，不复制第三方模型代码到项目。
- Cross Encoder 分数不是证据充分性概率。参考文献、附录或表面相似片段仍可能高分，因此必须保留来源类型降权、真实页码和无答案题关卡；任何一项退化都不得接入默认问答。

## 兼容性矩阵

| 组合 | 预期行为与验收边界 |
| --- | --- |
| 当前论文 / 跨论文 | 单篇问题按片段重排；显式多论文集合仍按论文分组，不让全局分数吞掉弱势论文。两条路径分别报告页锚点召回。 |
| 原文 / 译文 | 只对权威英文原文片段评分；中文问题可以输入多语模型，但不得用译文缓存替代原文证据或生成新的页码。 |
| 同一会话 / 不同会话 | 结果由固定模型修订、查询和原文片段决定；内存缓存可丢失但不能改变排序语义，不能把上一会话的候选泄漏到下一篇论文。 |
| 本地 / 云端 | 模型只在本地、离线加载；DeepSeek 不参与本轮评测。缺少本地文件时明确失败或回退，不能自动联网下载。 |
| macOS / Windows | 两个平台沿用同一模型 ID、修订和 safetensors 文件；分别记录首次加载、热问延迟、峰值内存和路径错误。未实机验证的平台保持“未验证”，不声称兼容。 |

明确失败场景：模型下载不完整、固定修订不可用、内存或延迟超标、LoRA 单题改善但 Transformer/BERT 退化、参考文献误命中增加、无答案题误报增加、跨论文来源覆盖下降，或重排异常阻断现有关键词/E5 路径。出现任一情况即停止在离线实验，不开放产品入口。

## 进入产品前的验收门槛

1. 固定模型 ID、修订、许可、实际下载文件与本机磁盘占用。仅在用户明确选择后下载；失败不破坏关键词／E5 工作路径。
2. 锁定至少 LoRA、Transformer、BERT 三篇的中英文自然问题及人工 PDF 页锚点，记录当前 Top-5 与候选重排 Top-5；另含无答案题。不能删除失败题或用本题答案页硬编码查询词。
3. 分别量化页锚点召回、错误参考文献／附录率、无答案误报和 Mac 上首问／热问延迟。若只改善 LoRA 一题或使既有负例更差，停留在实验，不接入默认问答。
4. 若上线，仍由现有检索召回有限候选，再做可选重排序；不把模型分数当真值，不自动写 Obsidian，不改 PDF 页码协议。

当前结论：本地 E5 已能用且已做内存复用；宽泛问句的证据质量仍需独立评测。新增模型不是“修复一行代码”，也不是 DeepSeek API 的替代品。

## 首轮本机离线试验（2026-10-06）

用户同意后，仅下载固定修订 `1427fd652930e4ba29e8149678df786c240d8825` 的 `model.safetensors`、配置、分词器和模型卡到被 Git 忽略的 `data/model_cache/`；缓存约 470 MiB，未下载仓库里的 pickle、ONNX 或 OpenVINO 权重，也未上传论文。以本地路径、`local_files_only=True` 和离线环境变量加载成功。最小句对试运行给明确相关句约 `10.92` 分、无关句约 `-5.28` 分；这些原始分数不是概率。

在 LoRA v2 的固定问题 `Which matrices does LoRA train?` 上，沿用现有混合检索取前 30 个候选，原排序中 PDF 第 4 页首次位于第 8 位；Cross Encoder 仅对这 30 个候选做影子重排后，第 4 页升至第 1 位。此次 Mac CPU 对 30 个片段的模型打分耗时约 `0.78s`，不含首次加载与 E5 召回；这是一次测量，不是性能承诺。**尚未跨 Transformer/BERT、中文问题与无答案题验收，不能接入默认检索或据此宣称问题已修复。**
