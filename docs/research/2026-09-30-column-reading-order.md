# M7.4c 双栏页阅读顺序关卡：开源论文阅读产品拆解

检索日期：2026-09-30。本记录先于功能编码完成。

## 用户问题

双栏论文常按“左栏从上到下，再右栏从上到下”阅读。PDF 文本层却可能按绘制顺序抽出，导致左右栏交错。若把交错文字直接发给翻译模型，中文译文表面通顺却不对应原文。需要在调用 DeepSeek **之前**发现明确的交错，且不能把任何几何猜测宣称为已验证的阅读顺序。

真实样本：[BERT 原论文 PDF](https://arxiv.org/pdf/1810.04805) 第 2 页确实是双栏；人工核对原图后，当前 `pypdf` 在该页先抽取左栏再抽取右栏，属于可继续翻译但仍需提示复核的正例。另需用可重复的合成错序页检验拒绝路径。

| --- | --- | --- |
| [Docling](https://github.com/docling-project/docling) | [文档模型](https://docling-project.github.io/docling/concepts/docling_document/)用正文树的子项顺序表达阅读顺序，坐标和内容类型另存；[官方 CLI 指南](https://github.com/docling-project/docling/blob/main/docling/.agents/skills/docling/references/cli.md)指出复杂多栏版面可考虑 VLM，普通流水线可能排错。 | [MIT](https://github.com/docling-project/docling/blob/main/LICENSE)；不安装或复制代码。 |

这些产品共同提示：**页面空间位置、PDF 抽取顺序和可信阅读顺序是三种不同信息**。本阶段只增加本地质量关卡，不模仿其重型模型推理，更不复制实现。

## 流程拆解

- **交互**：用户翻译当前页前先看到是否为双栏候选；若检测到明显交错，翻译按钮不可用，并告知可选取单栏/段落翻译。普通双栏候选仍允许按页翻译，但提示需对照原 PDF。
- **数据**：复用当前论文、PDF 页码、`PageQuality` 和现有翻译缓存。检测只返回质量问题，不另建“已验证正文块”或新索引。
- **模型与检索**：在本地从 PDF 文本绘制位置取得候选列与抽取顺序；明确交错时不请求 DeepSeek。已有检索/问答仍使用原文索引，本阶段不改变它们的文本次序，因此不能声称其双栏可靠性已解决。
- **引用**：所有判断绑定当前 PDF 原文页码；继续以中间原 PDF 为最终依据。
- **隐私与失败**：检测在本机完成；无法确定列、旋转页、非标准 PDF 或只有少量候选行时维持“顺序未验证”的提示，不静默重排。只对多次明显跨栏回跳作硬阻断，避免单个页脚或图注误判。

## 对 ResearchCopilot 的取舍

| 选择 | 决定 | 原因 |
| --- | --- | --- |
| 对明确双栏页显示复核提示，对多次左右交错的抽取序列阻断整页翻译 | 采用 | 避免明显错序的正文被模型包装成可信译文，且不改变正确页的文本。 |
| 直接按 x/y 坐标重新排序全部文字 | 拒绝 | 跨栏标题、图表、公式、脚注会使简单排序产生新的错误。 |
| 现在接入布局 VLM 或声称“检测到双栏即顺序正确” | 拒绝 | 模型、许可证、资源和跨平台成本应在样本评测后再决定；候选检测不是结构校验。 |
| 遇到任何双栏就禁用整页翻译 | 拒绝 | BERT 第 2 页展示当前文本顺序可能已符合阅读顺序，全部阻断会损害正常阅读。 |

## 架构影响与兼容性

新增一个只读的本地抽取顺序审计函数，并把结果作为 `PageQuality` 的一个复核或阻断问题；服务端和前端共用现有质量门槛。真实 BERT 第 2 页还暴露既有原文区域分组会跨窄栏间距合并的问题；在同一阶段修正原文区域的中缝分割，但不把分割后的几何框当成可信阅读顺序。既有译文缓存仍按论文和页码隔离，访问缓存前也必须检查新门槛；不新增数据库、模型调用或会话状态。

| 场景 | 验收要求 |
| --- | --- |
| 当前论文 / 换论文 | 只检查请求中的 PDF 和页码；绝不复用另一篇论文的坐标判断。 |
| 原文 / 译文 | 原 PDF 不变；只在明确错序时阻断新译文或旧缓存展示；一般候选不重排文本。 |
| 不同会话 | 页级译文仍与问答会话独立，错序风险不写进另一会话记录。 |
| 本地 / 云端 | 检查仅在本地；被阻断的页面不发给 DeepSeek。 |
| macOS / Windows | 复用已有 `pypdf`，不调用系统专有工具或下载新模型。 |

## 实现顺序与验收标准

1. 核对真实 BERT 第 2 页的视觉双栏与 `pypdf` 当前抽取顺序，建立“候选但未见交错”正例。
2. 用合成双栏页分别模拟先左后右和左右交错的 PDF 绘制顺序，明确至少两次跨栏回跳才硬阻断。
3. 本地质量报告向用户解释候选与阻断的区别；前端按钮和服务端 API 均执行同一门槛，避免绕过界面直接调用模型。窄栏间距的原文锚点仍保持左右分开。
4. 回归单栏/图表页、空页、旧缓存、跨论文隔离；完整测试与前端构建通过。
5. 真论文样本不调用真实 DeepSeek；若原 PDF 内容或文字层不支持确定判断，记录限制而非宣称顺序已修好。

## 暂不实现

不自动重排、逐块双语对齐、翻译表格单元或行内公式；也不把这项翻译前检查扩展到检索/问答索引。后者需独立评测检索命中质量和引用页码。
