# M6.5.3 选区翻译复用：开源论文阅读产品拆解

检索日期：2026-09-26。只借鉴产品设计，不复制以下项目代码。

## 用户问题

读英文论文时反复回看同一句/段很常见。每次重新等待和付费翻译会打断阅读；但错误地复用另一篇论文、另一页、另一目标语言或旧提示词的译文，也会误导理解。本步只处理已有选区上下文翻译结果的安全复用与显式重译。

## 对 ResearchCopilot 的取舍

| 决策 | 理由 |
| --- | --- |
| 采用精确且保守的缓存键 | 匹配论文、会话、页码、原选区、恢复上下文、语言策略、模型和翻译提示版本；不同任务不共用。宁可多一次调用，也不拿错误语境解释论文。 |
| 复用已有 `ReadingRecord` | 记录已保存原文锚点、上下文、译文、引用与模型；不建立第二套缓存文件、数据库或会话。命中时返回原记录 ID，不重复写历史。 |
| 命中标记与“重新翻译” | 侧栏应说明本次未调用 API；用户可显式跳过缓存以处理不满意或陈旧的译文。 |
| 不缓存失败或旧版本记录 | 证据不足、空译文、缺有效原文引用、M6.5.2 的无版本记录均不复用。 |
| 拒绝整篇预翻译与跨会话共享 | 当前逐页 PDF 文本不足以稳定产生结构块；跨会话共享会使不同研究主题历史交叉。后续 M7/M8 再评估。 |

## 数据、检索、引用与隐私边界

仍从当前 PDF 页本地重建选区上下文；选区是唯一待翻译原文证据，检索结果和译文不会混入 PDF 索引。命中时从当前锚点重建证据页码，并返回已有引用；不发送网络请求，不存 API 密钥。未命中或显式重译时，才按 M6.5.2 的明确按钮将有限选区与上下文发给 DeepSeek。历史 JSON 在本机，受当前项目 `.gitignore` 排除。提示版本是缓存失效标记，不是对用户确认译文质量的保证。

## 架构影响与兼容性矩阵

只在 `ReadingContext` 加单次 `refresh_translation`，`ReadingRecord` 加兼容默认值的 `prompt_version`，`PaperAnswer` 加非持久的 `cache_hit`。服务层先尝试历史匹配，再调用现有答案服务；UI 展示命中状态和重译入口。不新增核心实体。

| 组合 | 预期行为 |
| --- | --- |
| 同一论文、会话、选区、语言/模型/上下文 | 复用且无新历史/API 调用。 |
| 换论文、换页、换会话、换目标语言/术语策略/模型/上下文 | 不复用，独立翻译。 |
| 原文与译文 | 原文仍为引用唯一依据；缓存译文不是检索证据。 |
| 本地与云端 | 命中本地完成；未命中才由用户按钮发云端。 |
| macOS 与 Windows | 只用已有跨平台 Python、JSON、浏览器请求；模型/索引不跨设备同步。 |
| 旧记录、失败记录、重新翻译 | 旧版本与失败结果跳过；用户显式重译时跳过缓存并新增记录。 |

## 实现顺序与验收标准

1. 增加兼容字段、服务层精确匹配和失败排除；保证旧历史可读。
2. API 接受仅本次有效的重新翻译标志，返回缓存命中标识。
3. 阅读器明确显示缓存复用/模型请求，并提供重译动作。
4. 自动测试覆盖命中、不重复记录、语言/会话/页码/上下文/模型变化、失败、旧记录、显式重译；真实 PDF 在本地验证页码和上下文。完整测试和前端构建不得回归。

暂不做预翻译整篇论文、跨论文译文复用、在线同步、术语库（单独拆解）、英文整站 UI（单独拆解）。
