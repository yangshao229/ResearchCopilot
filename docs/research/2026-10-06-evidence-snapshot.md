# 已查看证据与回答的一致性

日期：2026-10-06。接续[统一证据包](2026-10-06-evidence-set-consolidation.md)，只解决两个 HTTP 请求之间的证据漂移；不调整排序、拒答阈值或新增模型。

## 用户问题

用户可以先在“证据”页检查候选原文，再点击生成回答；但这两个动作原本会分别检索。如果中间缓存、索引、PDF 或检索设置变化，回答可能使用一批用户没有看过的片段，界面却无法说明差异。本阶段要把“我刚看过的证据”变成下一次回答请求可验证、会过期且失败关闭的交接对象。

## 开源产品拆解与取舍

- [PaperQA2](https://github.com/future-house/paper-qa) 将检索、证据上下文和最终回答分阶段；其“懒收集证据”适合直接提问，却不足以保证用户先查看的一批片段在下一次请求中原样复用。
- [Open Notebook 来源、笔记与会话设计](https://github.com/lfnovo/open-notebook/blob/main/docs/2-CORE-CONCEPTS/notebooks-sources-notes.md) 将来源视作不可变证据、笔记视作可变理解，并让用户显式控制上下文。我们沿用“用户看到什么证据，就用什么证据回答”的边界，不复制其数据库结构。
- [Open Notebook 引用说明](https://github.com/lfnovo/open-notebook/blob/main/docs/3-USER-GUIDE/citations.md) 强调从回答回到原文核查；本项目继续保留 PDF 页码和版本锚点。
- [LlamaIndex CitationQueryEngine 官方 API](https://docs.llamaindex.ai/en/v0.10.17/api_reference/query/query_engines/citation_query_engine.html) 将检索节点交给回答合成和引用组件；可借鉴节点身份的传递，但本项目不需要其框架、重切分或第二套来源模型。

上述三项目只借鉴交互和数据边界；没有复制第三方代码、引入依赖或改变许可证义务。
- [Haystack `AnswerBuilder`](https://github.com/deepset-ai/haystack/blob/main/docs-website/reference_versioned_docs/version-2.27/haystack-api/builders_api.md) 把传给生成器的文档与回答中的编号引用重新关联。我们借鉴“编号必须从同一批输入文档解析”，但不引入其流水线或依赖，也不把引用存在误当作证据充分。

许可证核对：PaperQA2 与 Haystack 仓库为 Apache-2.0，Open Notebook 为 MIT。本阶段只借鉴公开架构思想，没有复制三者源代码、提示词或数据结构，也没有增加第三方依赖；新增实现只使用 Python 标准库与项目现有 Pydantic 模型，因此不会把外部许可证条款带入产品分发物。

检索日期：2026-10-06。上述核心证据均来自项目官方 GitHub 仓库或仓库内官方文档。

## 流程拆解与取舍

| 环节 | 成熟做法 | 本项目取舍 |
| --- | --- | --- |
| 检索 | PaperQA2 将收集证据与生成分开 | 借鉴分层，但搜索结果必须先成为显式 `EvidenceSet` |
| 上下文控制 | Open Notebook 让用户控制来源和会话 | 借鉴显式来源边界；拒绝复制数据库与持久化会话结构 |
| 引用 | Haystack 从同一批输入文档解析编号 | 直接借鉴编号绑定原则，并继续由服务端生成页码与原文摘录 |
| 请求间交接 | 三者都没有直接满足本项目“先看后答”的短期一致性 | 增加进程内短期令牌；拒绝把整批论文文字塞进客户端或令牌 |
| 隐私 | 本地来源应留在用户设备 | 快照仅驻留本机服务内存，不写云端、Vault 或日志 |
| 失败处理 | 来源不可用时应能回到原文核查 | 任一版本／参数不匹配就要求重查，不静默重新检索 |

## 架构影响与兼容矩阵

快照位于 HTTP 搜索与回答之间，复用上一阶段的 `EvidenceSet` 和 `SourceDocumentRef`，不改变检索器、模型、阅读历史或 Vault 的权威边界。内存存储按固定上限和 TTL 淘汰，服务重启即失效；令牌本身不包含论文文字。

| 场景 | 行为 |
| --- | --- |
| 当前论文关键词／语义／混合检索 | 搜索成功后可签发快照；回答必须使用同一模式、条数和范围 |
| 原文／译文界面 | 快照只保存原始 PDF 证据，不把译文冒充来源 |
| 旧前端或直接调用回答 API | 不传令牌时保持原有一次性检索路径 |
| 会话切换 | 会话不影响证据内容；回答仍按既有会话隔离保存 |
| macOS／Windows | 仅进程内内存与标准库锁，无平台路径依赖 |
| 服务重启、扩容到另一进程 | 快照明确失效并要求重新检索，不尝试跨进程猜测 |

## 失败场景

- 论文 ID、PDF UID／哈希、问题、模式、条数或范围任一变化：返回冲突并要求重新检索，不调用模型。
- 快照过期、被有界淘汰或服务重启：同样失败关闭，不静默回退到新检索。
- 搜索结果没有当前 PDF 的版本锚点：不签发快照。
- 客户端篡改或伪造令牌：只会得到无效快照错误，令牌不能反推出证据内容。
- 模型生成失败：沿用既有失败关闭规则，不保存不完整回答；快照本身也不写历史或 Vault。

## 最小方案

搜索返回原有片段列表，同时给一枚短期快照令牌。服务进程只在内存中保存对应 `EvidenceSet`，限制数量与存活时间。回答时若带令牌，必须核对论文 ID、PDF UID+哈希、问题、检索模式、条数和范围偏好，直接用原证据包生成回答；任何不符、超时或服务重启都返回“重新检索”，绝不静默重查或发送旧内容。直接提问仍走正常检索。选区翻译和本地结构问答不使用令牌。

快照不是持久化知识库、不是证据充分性结论。它不写 Vault、阅读记录或 PDF；只有成功生成回答才按既有流程记录。前端更改问题、模式或范围后，不再复用旧令牌；旧结果只作为旧问题的展示，提交新问题走直接提问。

兼容检查：当前论文使用单篇 PDF 版本键，跨论文聚合端点不发此令牌；译文、选区翻译与本地结构问答不把译文冒充原文候选；不同会话可分别保存回答，但令牌始终绑定论文、问题和检索设置；本机内存快照不上传云端，只有用户发起问答时原文候选才按原有规则发往 DeepSeek；macOS/Windows 使用同一 Python 进程内实现，重启均要求重新检索，不跨设备同步令牌。

## 数据与隐私边界

令牌是不可预测的随机字符串，仅映射到当前服务进程中的深拷贝证据包。服务不把证据正文编码进令牌，不输出令牌到日志，不把快照写入磁盘，也不向模型发送快照元数据；模型只接收与既有问答相同、已经由用户查看的有限原文片段。PDF、翻译缓存、用户笔记和 Vault 均不被修改。

## 实现顺序

1. 在领域层已有 `EvidenceSet` 与来源锚点之上定义严格快照键。
2. 实现有界、带 TTL、线程安全且深拷贝隔离的进程内存储。
3. 搜索签发令牌，回答验证令牌后绕过第二次检索。
4. 前端只在论文、问题、模式和范围仍匹配时提交令牌。
5. 补齐 API、过期、淘汰、跨版本和失败前零模型调用回归测试。

## 验收

- 搜索后即使检索器返回不同排序，持令牌回答仍使用刚看到的片段与编号。
- 换论文、换 PDF 字节、换问题／模式／条数／范围、过期或进程重启都明确失败，不调用模型、不写历史。
- 直接回答、选区翻译、旧搜索响应及现有前端交互兼容。

## 暂不实现

- 不跨进程、跨设备或重启持久化快照；需要水平扩展时再设计共享存储与加密边界。
- 不把快照令牌当作用户确认、置信度或证据充分性评分。
- 不改变现有检索排序、重排器、无答案阈值、比较答案或跨论文生成开放状态。
