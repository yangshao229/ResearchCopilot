# 统一证据包：架构收敛记录

日期：2026-10-06。性质：落实已有[整体阅读架构拆解](2026-09-23-coherent-reading-architecture-and-bilingual-workflow.md)与[产品蓝图](../PRODUCT_BLUEPRINT.md)的 `EvidenceSet`，不新增用户能力或检索策略。本轮不复制外部项目代码。

## 用户问题

“只查原文证据”、带引用回答和选区翻译不能各自分配片段编号、来源和引用；否则同一个 PDF 页面可能沿几条路径产生不同的证据含义。候选片段也不能仅因排名靠前就被当作“足以回答”。

## 已完成的开源拆解与取舍

既有拆解检查了 [Open Notebook](https://github.com/lfnovo/open-notebook) 的来源/会话/笔记分离、[PaperQA2](https://github.com/Future-House/paper-qa) 的检索/证据/回答阶段，以及 [Zotero PDF Reader](https://www.zotero.org/support/pdf_reader) 的原文回跳。此处只复用“单一证据包贯穿任务”的设计，不引入数据库、Agent 框架、额外模型或他人的实现代码。

## 最小契约

- `EvidenceSet` 保存问题、来源方式（检索或精确选区）、解析后的范围、按顺序编号的候选原文片段。它**不是**证据充分性判决。
- 检索和回答都调用同一个收集函数；模型只接收这个证据包里的原文，不得自己生成引用正文。引用编号经证据包校验后，由服务端从原文片段生成。
- 选区翻译可传入直接原文，不额外执行语义检索；回答历史继续记录同一份原文页锚点。
- 单篇搜索与跨论文取证在接口上仍分开：后者目前只返回各论文的候选片段，不在本轮开放跨论文答案。

## 验收与失败场景

- 同一查询和范围下，单篇“先看证据”和问答使用同一收集逻辑；直接选区不调用检索器。
- 重复或不存在的模型引用 ID 不得生成伪造引文；候选为空时不调用模型；证据包不能有重复/跳号 ID。
- 新证据保留此前的论文 UID、PDF 哈希与文件页码；没有通过原文版本检查的缓存不得取得新锚点。
- 运行全部 Python 测试、前端类型与构建；不调用 DeepSeek、下载模型或修改真实 Vault。

## 不在本轮解决

排序好坏、中文召回、自动判断“是否回答了问题”、两次 HTTP 请求之间的结果快照一致性，以及跨论文比较答案，都要用冻结的有答案/无答案真值另行评测，不能由这次模型重构假定已经解决。
