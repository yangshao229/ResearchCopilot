# 开源自测版：开源产品拆解

检索日期：2026-10-12。目标是让外部测试者在自己的电脑上复现论文阅读流程并反馈问题，不把当前单人本地应用误称为可公网部署的多用户服务。

## 用户问题

目前应用依赖开发者电脑上的环境和构建产物；他人拿到源码后，不一定知道如何安装、启动、保护 API Key、连接自己的 Obsidian Vault 或报告错误。需要一个从干净源码开始、无需 Codex 权限的自测流程。

| --- | --- | --- | --- | --- |
| Open Notebook | [README](https://github.com/lfnovo/open-notebook/blob/main/README.md)、[安全文档](https://github.com/lfnovo/open-notebook/blob/main/docs/5-CONFIGURATION/security.md)、[许可证](https://github.com/lfnovo/open-notebook/blob/main/LICENSE) | 给自托管用户明确的启动入口；配置模型提供商后导入资料并阅读 | 文档和模型配置留在自托管环境；公开服务需要额外认证；来源与回答在界面关联 | 明确默认部署的安全限制；MIT |
| Khoj | [自托管指南](https://docs.khoj.dev/get-started/setup/)、[仓库](https://github.com/khoj-ai/khoj)、[许可证](https://github.com/khoj-ai/khoj/blob/master/LICENSE) | 分开说明本机、Docker 等部署路径和平台要求 | 用户文档由所选部署控制；本地与云模型是不同配置；检索结果用于回答 | 本地匿名模式不能直接等同于公网服务；AGPL-3.0 |

这些项目的共通经验不是“加一个部署按钮”，而是让用户知道入口、数据存放、模型调用、安全限制和出错时如何定位。其模型流程不必照搬：ResearchCopilot 继续复用现有 PDF → 页码内容块 → 检索证据 → 带引用回答 → 人工确认 → Vault 的单一流水线。

## 对 ResearchCopilot 的取舍

| 借鉴 | 调整 | 暂拒绝 |
| --- | --- | --- |
| 一份从干净源码开始的安装和启动指南；锁文件；反馈模板；明确本地数据边界 | 当前只给“单人本机自测版”，继续默认监听 `127.0.0.1`；密钥仅由测试者本机配置；Obsidian 可选 | 无认证公网部署、共享账号、服务器端存储他人 PDF、默认自动下载模型、复制第三方项目代码、另建数据库 |

选择 Apache-2.0 作为本项目许可是用户明确决定；这里只借鉴流程设计，不引入三个参考项目的源码。已有 Python、npm 依赖各自按其许可证使用；发布前仍需单独核查依赖清单与前端静态资源归属。

## 数据与隐私边界

- Git 只发布源码、锁文件、文档和不含个人内容的测试；`.env`、PDF、模型、索引、阅读历史、Vault 均不应提交。
- DeepSeek Key 由测试者自己保管；默认不需要 Key 就能本地读 PDF，启用云端回答或翻译才发送所选问题/证据/页面文本。不要把实际 Key、私人论文、Vault 内容附在 Issue 中。
- 单人本地服务没有登录认证；`127.0.0.1` 以外的监听、公网端口转发、反向代理和服务器共享均不在本版安全承诺内。
- Git 历史也可能含敏感内容；正式公开前对历史和待提交文件都做保守扫描，再由仓库所有者最终确认。

## 架构影响与兼容性矩阵

无新核心对象、存储格式或模型调用链。新增的只是仓库层说明、许可和问题反馈入口；现有 `research-copilot serve`、`web/dist`、`.env`、本地资料目录与 Vault 协议保持不变。

| 组合 | 自测版要求 |
| --- | --- |
| 当前论文／跨论文 | 仍由现有资料库及原文页码机制处理，部署不改变隔离边界 |
| 原文／译文 | 无 Key 可读原文；需 Key 才能云端翻译，译文不得取代原文证据 |
| 不同会话 | 各测试者在自己的电脑上保留本地状态；不提供多用户隔离 |
| 本地／云端 | 本地阅读可用；DeepSeek 是可选的外部服务，API 失败应可继续阅读 |
| macOS／Windows | 文档分别给出命令；本轮自动检查主要在 macOS，Windows 需外部测试者回报结果，不能冒称已验证 |

## 实现顺序与验收标准

1. 先记录本拆解并更新蓝图；再添加许可、干净安装指南及反馈模板。
2. 现有测试与前端构建通过；检查 Git 忽略和仓库历史中的常见敏感文件／密钥模式。
3. 从干净目录按指南尝试安装和启动，至少验证无 Key 的本地入口；若网络/平台限制导致无法完成，应明确记录。
4. 失败场景：不设置 DeepSeek Key 时不能伪称云功能可用；端口已占用时以终端显示的实际 URL 为准；不支持把本地服务直接开放公网。
5. 不要求公开 GitHub 仓库、推送或分享用户资料才能通过自测版验收。

## 暂不实现的内容

Docker 镜像、云托管、账号系统、远程团队协作、自动上传日志，以及 Windows 上的论文复现实验。若未来需要这些能力，先另做开源拆解、安全设计和端到端验证。
