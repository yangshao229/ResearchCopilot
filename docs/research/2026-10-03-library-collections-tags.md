# M8.1 本地论文集合与标签：开源产品拆解

检索日期：2026-10-03。此记录先于功能代码完成。只借鉴产品模型与测试边界，不复制第三方代码或资源。

## 用户问题

ResearchCopilot 已能导入和阅读多篇本地 PDF，但资料库仍是一列按文件路径排序的论文。论文变多后，用户无法按研究项目、主题、方法或阅读状态整理，也无法快速只看某个范围。直接把 PDF 移入不同文件夹会改变论文 ID，进而割裂阅读记录、会话、译文缓存和术语表，因此组织能力必须作为独立元数据覆盖层，而不是改动原文件路径。

M8.1 提供最小本地组织能力：同一篇论文可加入多个扁平集合，并拥有多个人工标签；资料库可按一个集合和多个标签筛选。删除集合只移除归属，不删除论文、笔记或缓存。自动标签、层级集合、跨论文问答和同步留给后续阶段。

共同结论：集合是对条目的多对多引用，不是文件夹复制；标签是可组合的轻量描述；原文件、阅读产物与组织元数据应分离；自动分类必须可审查，不能混入第一版人工整理。

## 各项目的成熟做法

### 交互流程

1. 资料库根视图始终保留全部论文。
2. 用户可新建集合，把当前论文加入一个或多个集合；同一论文不被复制。
3. 用户可为当前论文输入多个人工标签；标签按规范化名称去重。
4. 选择一个集合并勾选零个或多个标签后，只过滤左侧论文列表，不改变当前 PDF、会话或问答范围。
5. 删除集合只删除集合及其归属；论文仍在“全部论文”中，标签和其他阅读数据不变。

### 数据结构与失败处理

- 集合有稳定随机 ID 和用户名称；名称去除多余空白并在大小写折叠后唯一。
- 论文组织记录只保存 `paper_id → collection_ids + tags`，不复制标题、路径或页数。
- 标签去除首尾/重复空白，大小写不敏感去重，保留第一次输入的显示形式；限制数量和长度。
- 保存论文组织信息时验证论文存在、集合 ID 存在；未知 ID、空名称、重复集合名或超限标签返回明确错误。
- JSON 缺失时视为空组织状态；损坏数据应失败关闭，不覆盖 PDF 或阅读记录。

## 对 ResearchCopilot 的取舍

| 决策 | 理由 |
| --- | --- |
| 新增独立 `LibraryOrganizationStore`，不修改 PDF 目录结构 | 保持现有基于相对路径的论文 ID 和所有阅读数据引用稳定。 |
| 集合和标签均为多对多元数据 | 同一论文可以同时属于“当前项目”“方法参考”和“待读”，不产生重复论文。 |
| 第一版只做扁平集合 | 层级集合会引入递归展示、移动、删除和父集合包含策略；尚无用户验证，不应一次扩大。 |
| 筛选只发生在前端列表 | 数据量尚小，后端保持完整论文清单；不引入数据库或第二套搜索索引。 |
| 标签完全人工输入 | Paperless 的自动匹配需要足够正负样本；当前资料量和人工确认流程不足。 |
| 删除集合不删除论文 | 与 Zotero 的安全语义一致，避免组织操作破坏原始研究资料。 |

## 数据与隐私边界

组织元数据保存在本机 `artifacts/library_organization/organization.json`，不进入 PDF、问答提示、DeepSeek 请求、阅读记录、翻译缓存或导出卡片。实现和测试不读取密钥、不调用模型、不修改现有 `data/raw` 或用户产物。API 只在本机服务中读写集合名、标签和论文 ID。

## 架构影响与兼容性矩阵

复用现有 `PaperSummary.id` 作为唯一引用；新增组织存储和少量 HTTP 端点，`GET /api/papers` 将组织信息合并进现有摘要。前端仍由 `App` 维护资料库状态，不创建第二个路由或工作台。

| 情况 | 预期 |
| --- | --- |
| 当前论文 / 其他论文 | 只更新目标论文的组织记录；筛选不会更改其他论文。 |
| 当前会话 / 其他会话 | 集合和标签独立于会话，切换筛选不混合问答历史。 |
| 原文 / 译文 | 不修改 PDF、页码或任何译文缓存键。 |
| 本地 / 云端 | 全部本地完成，不调用模型或外部服务。 |
| macOS / Windows | 使用现有 Python JSON 原子写入和浏览器控件，不依赖系统文件标签。 |
| 论文重命名 / 删除 | 当前阶段仍由现有文件扫描决定论文是否存在；孤立组织记录不显示，也不自动删除，避免误删。 |
| 中文 / 英文界面 | 所有新控件、空状态、错误和 ARIA 文案进入两套消息表。 |

## 实现顺序

1. 新增集合、论文组织模型和线程安全 JSON 存储，覆盖规范化、重复、未知集合、删除集合及并发安全边界。
2. 将存储注入 `create_app`，增加列表/新建/删除集合和读取/保存论文组织信息的 API；`GET /api/papers` 合并组织字段。
3. 在左侧资料库增加集合筛选、标签筛选和当前论文组织编辑器；筛选为空时给出明确状态，不能自动切换或清除当前阅读。
4. 补中英文消息、样式、后端 API 测试与前端消息覆盖测试。
5. 运行完整 pytest、TypeScript 与生产构建，并用临时数据验证不修改真实论文和阅读记录。

## 验收标准

1. 同一论文可属于多个集合并拥有多个去重标签；另一论文保持独立。
2. 重复集合名、空名称、未知集合 ID、过长或过多标签被拒绝，旧数据不被覆盖。
3. 删除集合只移除集合 ID 和所有论文的对应归属，不删除论文文件、标签或阅读数据。
4. 页面可按一个集合和多个标签过滤；清除筛选恢复全部论文；当前论文若被过滤掉，阅读区保持不变并明确显示筛选状态。
5. 中文和英文界面均无散落新文案，窄屏不产生新的横向溢出。
6. 完整 Python 测试和前端生产构建通过，不调用 DeepSeek，不修改现有论文、历史或缓存。

失败场景：保存包含不存在集合 ID 的论文组织信息时，API 返回冲突/校验错误，存储文件保持原值；删除集合后论文仍可从“全部论文”打开。

## 暂不实现的内容

- 层级集合、拖放排序、批量编辑、自动标签、智能集合、跨设备同步和多人权限。
- 跨论文问答、主题笔记、BibTeX 导入/导出或相关论文推荐；这些在 M8 后续阶段独立评测。
- 移动、重命名或删除 PDF；集合永远不是文件系统操作。
