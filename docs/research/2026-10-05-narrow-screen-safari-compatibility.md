# 窄屏与 Safari/WebKit 基础兼容：开源产品拆解

检索日期：2026-10-05。范围是阅读工作台的布局与浏览器能力降级，不改变 PDF 内容解析或翻译策略。

## 用户问题

三栏论文阅读器在桌面宽屏上工作良好，但 320–720 CSS 像素宽的窗口、浏览器高倍缩放或 Safari 动态工具栏可能造成顶部按钮溢出、可视高度计算错误，或因 `ResizeObserver` 不可用而无法得到适合宽度的 PDF。用户必须仍能打开资料库、阅读 PDF、打开助手和切换语言。

| 一手来源 | 成熟做法 | 本项目取舍 |
| --- | --- | --- |

| [WebKit：Safari 15.4 新视口单位](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/) | `dvh` 会随移动浏览器动态工具栏改变；传统 `vh` 仍需要作为旧版本回退。 | 保留 `vh`/`dvh` 双声明，同时把应用改成纵向 flex，让实际顶栏换行后剩余高度自动分配，不硬编码移动端顶栏高度。WebKit 为开源项目；不复制实现。 |

| [React-PDF 使用的 PDF.js 官方仓库](https://github.com/mozilla/pdf.js) | 浏览器内 PDF 渲染以容器尺寸驱动画布，阅读内容与周边 UI 分离。 | `ResizeObserver` 可用时继续精确测量；不可用时回退到窗口 resize 和元素 `clientWidth`，避免整页启动失败。Apache-2.0；只调整本项目胶水代码。 |

## 流程与失败处理

窄屏启动时顶栏分成标题行与操作行；资料库和助手仍以覆盖面板打开，中间 PDF 保持独立滚动。应用外壳以真实剩余高度分配工作区，避免 Safari 地址栏变化或顶栏换行后内容被截断。

PDF 容器先同步读取 `clientWidth`；若浏览器支持 `ResizeObserver` 则持续观察，否则监听窗口 resize。回退只影响适合宽度计算，不修改 PDF、页码、选区或引用。长路径、错误、Markdown 和按钮文字必须换行，页面根部不得出现因普通 UI 导致的横向滚动。

## 架构影响

- 仅修改现有 CSS 和 `PdfReader` 的尺寸监听；无新依赖、API、领域对象或存储。
- Safari 已有的 `ReadableStream` 异步迭代兼容层保留。
- PDF 仍由 PDF.js/React-PDF 渲染，不改文本层、坐标层或公式保护。

## 兼容性矩阵

| 情况 | 行为 |
| --- | --- |
| 当前论文／跨论文 | 布局变化不改变检索范围或研究集合。 |
| 原文／译文 | 原 PDF 与右侧译文面板都可独立滚动；不新增对齐。 |
| 不同会话 | 面板切换不清除会话或当前页。 |
| 本地／云端 | 纯前端布局，无网络或模型调用。 |
| macOS Safari／Chromium | `dvh` 支持时使用动态高度；否则回退 `vh`。 |
| ResizeObserver 可用／不可用 | 精确观察／窗口 resize 回退，两者都能计算页面宽度。 |

## 实现顺序

1. 将应用壳改为 flex 高度分配，移动顶栏允许换行。
2. 收紧 320px 下的按钮、语言选择、覆盖面板和长文本换行。
3. 为 PDF 宽度监听增加能力检测与安全回退。
4. 运行完整测试和生产构建；记录无法进行的浏览器限制。

## 验收标准

1. 320px 宽时顶部主要操作仍可见，普通文本不要求页面级横向滚动。
2. 顶栏换行或 Safari 动态视口变化时工作区继续占据剩余高度。
3. 缺少 `ResizeObserver` 时 PDF 阅读器不抛出启动错误，并能在窗口变化时重算宽度。
4. 完整后端测试与前端生产构建通过，不修改用户数据。

## 暂不实现

移动端手势重写、原生 iOS 应用、触屏批注、PDF 文本重排和 Safari 私有 API。真实 Safari 浏览器人工验收需要可监听的本地服务环境，无法由静态构建冒充。
