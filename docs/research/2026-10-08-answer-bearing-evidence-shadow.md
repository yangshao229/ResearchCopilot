# 答案承载证据覆盖：开源评测拆解

日期：2026-10-08

## 用户问题

当前离线评测只判断“人工标注的 PDF 页是否进入 Top-5”。同一页可能有多个片段，命中页码不代表送给回答模型的片段真的包含回答所需事实。用户需要的是能核对答案的原文证据，而不是一个看起来正确的页码。本轮先在已冻结的独立 RAG 论文账本上增加确定性的“答案承载短语组”检查，区分页命中与片段证据覆盖；不调用生成模型，也不把字符串匹配当作通用证据充分性。

## 参考项目与一手资料

1. [FEVER 原始论文](https://arxiv.org/abs/1803.05355)：可验证／反驳判断同时标注必要证据句，说明任务标签和证据集合应分开评估。
2. [HotpotQA 原始论文](https://aclanthology.org/D18-1259/)与[官方仓库](https://github.com/hotpotqa/hotpot)：除了答案，还提供推理所需的句级 supporting facts，说明“找到答案字符串”和“覆盖全部支持事实”不是同一指标。
3. [SQuAD 2.0 原始论文](https://aclanthology.org/P18-2124/)：把与上下文相关、带有貌似合理答案的不可回答问题纳入评测，说明负例不能靠关键词不匹配构造。
4. [KILT 原始论文](https://arxiv.org/abs/2009.02252)、[官方仓库](https://github.com/facebookresearch/KILT)与[官方检索评测源码](https://github.com/facebookresearch/KILT/blob/main/kilt/eval_retrieval.py)：将下游任务表现与 provenance 检索指标分开，支持本项目继续把页码来源、片段覆盖和最终回答拆成不同门槛。
5. [RAG 原始论文](https://arxiv.org/abs/2005.11401)：本轮四组答案承载事实和页锚点的唯一内容来源。

以上论文、仓库和数据只用于方法拆解；本轮不复制任何第三方代码或数据集，不增加依赖，因此不把其代码／数据许可证带入产品。RAG 公开 PDF 只保留为 Git 忽略的本机评测副本；已有 mMARCO 与 BGE 模型权重继续遵守其 Apache-2.0 模型卡，未新增模型。

## 各项目的成熟做法

| 来源 | 成熟做法 | 本项目采用方式 |
| --- | --- | --- |
| FEVER | 标签正确之外，证据集合也必须正确 | 页命中与答案承载事实覆盖分别计数 |
| HotpotQA | 标注完成推理所需的多条 supporting facts | 一个问题可有多个“必须覆盖”的概念组，每组允许若干原文变体 |
| SQuAD 2.0 | 使用与上下文主题相关的困难不可回答问题 | 保留现有自然负例，不把缺关键词当作拒答依据 |
| KILT | provenance 指标和任务输出指标分开 | 本轮只测检索片段覆盖，不宣称答案正确或可安全拒答 |
| RAG 原论文 | 事实由可核对原文定义 | 所有短语只来自固定 PDF 文本层，并绑定 PDF 哈希 |

## 对 ResearchCopilot 的取舍

| 决策 | 采用／调整／拒绝 | 理由 |
| --- | --- | --- |
| 在冻结真值中增加答案承载短语组 | 采用 | 可复现地检查 Top-k 片段是否包含人工确认事实 |
| 每组允许多个等价原文短语 | 调整 | 处理连字符、缩写与轻微抽取差异，但仍保持确定性 |
| 跨 Top-k 证据集合累计覆盖多个概念组 | 采用 | 多个片段共同构成证据时不强迫单片段完整 |
| 用短语覆盖分数自动上线重排器 | 拒绝 | 字符串出现不等于语义充分、关系正确或引用忠实 |
| 用短语缺失自动判定无答案 | 拒绝 | 同义改写可能没有固定短语；负例仍需要独立人工真值与拒答评测 |
| 调用 DeepSeek 判断充分性 | 拒绝 | 会混入生成模型偏差、费用和网络变量，也违反本轮离线边界 |

## 数据、隐私与失败处理

真值只增加来自公开 RAG 论文文本层的短语，不写用户论文、阅读记录、翻译缓存或 Vault。评测只读取本机 PDF、E5 和固定重排模型；PDF 哈希或模型快照不匹配时失败关闭。

已知失败场景：PDF 抽取把单词拆分导致短语漏检；一个短语出现在否定或无关上下文中造成误报；同义证据没有列入变体；多个概念分别出现却没有形成正确关系；Top-k 覆盖了事实但最终生成仍误答；负例始终会返回候选但没有可用的自动拒答规则。报告必须将此指标称为“答案承载短语覆盖”，不能称为通用证据充分性或回答准确率。

## 架构影响

复用现有评测真值、PDF 哈希、混合召回、重排和 `reranker_evaluation`。每个正例可选增加 `evidence_requirements`：外层列表表示必须全部覆盖的概念组，内层列表表示该组允许命中的任一原文变体。评测器只增加纯函数与离线输出字段；不修改八类核心领域对象、`EvidenceSet` 生产结构、HTTP API、前端或持久化。

## 兼容性矩阵

| 组合 | 检查 |
| --- | --- |
| 当前论文／跨论文 | 先在单篇独立 RAG 论文验证；不推断跨论文生成能力 |
| 英文／中文问题 | 同义问句共享同一组英文原文要求，分别统计覆盖 |
| 原文／译文 | 只匹配英文原文片段；译文不得替代来源证据 |
| 不同会话 | 离线真值不读取会话，结果与会话隔离 |
| 本地／云端 | 全部本地，不调用 DeepSeek 或外部服务 |
| macOS／Windows | 纯文本归一化跨平台；macOS 实测，Windows 尚未实机验证 |

## 实现顺序

1. 先把四组 RAG 正例所需事实写入冻结真值并人工复核原文。
2. 在评测模块增加 Unicode／空白归一化和概念组覆盖纯函数。
3. 同时报告候选池、Top-1、Top-5 和页级去重 Top-5 的覆盖，不改变排序。
4. 增加单元测试，覆盖多概念、多变体、跨片段累计、缺失组和旧账本兼容。
5. 离线复跑固定模型，运行完整 pytest 和前端生产构建，更新验收与路线文档。

## 验收标准

- 旧真值没有 `evidence_requirements` 时结果保持兼容。
- 四组中英文正例共享事实要求，候选池、Top-1、Top-5 覆盖可复现。
- 至少一个测试证明“页码命中但答案承载事实不完整”会被区分。
- 无答案题不被短语覆盖函数自动判定为可回答或可拒答。
- PDF 哈希、模型离线边界、完整 Python 测试和前端构建全部通过。

## 暂不实现的内容

- 不训练证据充分性分类器。
- 不调用 LLM-as-a-judge。
- 不改变生产检索、回答、比较或主题笔记。
- 不把短语覆盖推广为跨论文准确率。
- 不自动翻译问题或原文来提高指标。
